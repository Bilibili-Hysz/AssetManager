## 一、性能链路全景（核实后的准确描述）

```
目录扫描(_ScanTask, QThreadPool 全局池) → 模型填充(beginResetModel/endResetModel)
  → 可见行+prefetch(_load_visible) → ThumbnailLoader.request(row, path, priority)
      → QImageReader 增量解码(_LoadTask/_BakeTask, 3 线程池, 容量96, deferred 队列)
      → 磁盘 webp 缓存 + 内存 LRU 64MB → thumbnail_ready 信号 → 批量投递(_flush_thumb_batch)
  → 网格 paintEvent(可见行裁剪 + 按行显示缓存 + 按源路径复用纹理 + 全量重建预算 + 帧合并)
  → 遥测(grid.frame/texture、model.reset、thumbnail.*、grid.frame_request——按需启用)
并行: 每个子目录 _SizeTask(2 线程池) → MetadataService 缓存 or os.walk 全量递归
```

## 三、掉帧根因排序（修正后）

1. **[高] 全量 reset 链**：任何触发（进入目录/排序/过滤/外部文件变动/操作后刷新）→ 模型清缓存 + 全量 reset → 网格全部行 dirty → 多帧纹理重建。大目录下这是每次可见卡顿的来源
2. **[高] 目录大小扫描风暴**：未预热目录的首次浏览，N 个 os.walk 任务与缩略图解码抢 IO
3. **[中] FS watcher 无防抖**：下载器/同步工具写文件时持续触发第 1 项（最易被用户感知的"无故卡顿"）
4. **[低] paintEvent 逐行 Python 编排**：已有可见行裁剪/局部更新/帧合并，剩余开销可控
5. **[方法论] 遥测默认关闭**：`performance_telemetry_enabled=False`（app.py:36-38）——所有埋点存在但从未用于定位

## 四、优化计划（按 ROI 排序）

### 第 0 步：建立测量基线（0.5 天）
- 开启遥测：设置 `performance_telemetry_enabled=true`
- 补 1 个埋点：`model.reset`（触发源 + 行数 + 耗时）；`grid.frame` 已有 texture_build_count/deferred_count 字段（_grid_widget.py:533-535）——记录滚动 5 万文件目录的 frame 分布
- 复现脚本：合成 5 万文件目录（含图片），进入 → 滚动 → 外部 touch 一个文件 → 观察

### 第 1 步：FS watcher 防抖 + 增量刷新（1-2 天，收益最快）
- `_on_fs_changed`（_navigation.py:59-66）加 500ms 单次防抖（QTimer）
- **不再 clear_cache**：`_loader.clear_cache()` 改为仅清队列（`clear_queue`），保留 64MB 内存缓存——同一路径缩略图直接命中
- `_post_refresh()` 前先判断：变化的目录 = 当前目录才全量刷新；其余仅使受影响目录的目录摘要失效
- 验收：外部写文件时界面无感；内存缓存命中率提升（遥测 thumbnail.cache tier=memory hit）

### 第 2 步：纹理按"源路径"键复用（1 周，核心修复）
- `_grid_widget._textures` 从行号键改为路径键：`{row: (path, tex)}` 或 `{path: tex}` + 行号映射
- `update_layout` 时：仅 `item_count` 变化与 dirty 行重建；**reset 后按路径命中复用纹理**（模型缓存 path 键已具备条件，_model.py:205 注释"survive sort changes"正是此意——网格层没做到）
- 排序/过滤变化（_model.py:202-221）场景收益最大：纹理零重建
- 验收：排序切换/过滤时 frame 的 texture_build_count 趋近 0

### 第 3 步：目录大小扫描治理（3-5 天）
- 进入目录时**批量预取** file_meta 缓存（batch_get_cached_file_counts 已有，MetadataService:182）——命中即显示，不排队任务
- 未命中的 _SizeTask 限并发 1（当前 2）且**仅当目录可见行内**才排队（当前对 prefetch 区也排队）
- 大目录首次浏览降级：子目录显示 "…" 直到缓存命中（现状即如此，但要避免风暴）
- 验收：首屏进入时间缩短；_SizeTask 峰值并发可控

### 第 4 步：模型 reset 最小化（3-5 天，最后做）
- 保持全量 reset 语义（排序正确性依赖它），但：`set_directory` 的立即清空 reset 可省略（扫描完成一次 reset 即可，loading 状态由 scan_started 信号表达——需要验证空态渲染）
- 外部刷新（refresh()）时若目录内容未变（stat 对比或直接信任 watcher 已防抖）跳过 reset
- 验收：进入/刷新时 reset 次数减半；测试回归（state_changed 语义不变）

### 第 5 步：绘制微优化（3 天，可选）
- hover 动画期间仅 update(hover 行 rect)（_grid_widget.py:478-490 已有局部绘制，确认 update 范围）
- 滚动中暂停非可见 prefetch 加载（_load_visible 已有 extra 窗口，滚动时收缩 extra）
- `_reduce_motion` 时跳过 hover lift 绘制

## 五、为什么不需要 C++ 重写（核实后论证）

1. **热路径已 C++ 化**：缩略图 QImageReader 增量解码（_loader.py:125-129）、网格 QPainter 绘制（_grid_widget.py:396）、模型 Qt 原生——Python 仅做编排。**重写后沿用相同策略（全量 reset、watcher 全量刷新、行号纹理）照样卡**
2. **根因全部在"策略层"**：reset 范围、缓存保留策略、防抖、扫描风暴——语言无关，且第 1-3 步即可消除大部分掉帧
3. **重写成本 = 全部资产作废**：1590 项 Python 回归、双端共享应用层、插件 v2、事件投影体系
4. **遥测已埋好**：`grid.frame`（含 texture_build_count/deferred_count）、`thumbnail.*`、`grid.frame_request`——这是"先测量后优化"的现成地基，C++ 重写反而要重建
