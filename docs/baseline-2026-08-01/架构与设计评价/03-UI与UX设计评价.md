# 03 · UI 与 UX 设计评价

## 总评

**视觉与交互工程的完成度远超同类个人工具**：22 套主题、自绘网格动画、背景效果、启动动画、托盘体系——这是一个"把 UI 当产品做"的项目。但**信息架构与反馈机制**是短板：软件假设用户已经理解"库/标签/项目"模型，新用户会迷路。视觉 8.5/10，交互 7/10，信息架构 6/10，无障碍 6/10。

## 一、视觉设计

### 亮点

1. **主题系统是产品级设计**：
   - 两层 token（必选 13 色 + 扩展 13 色兜底，themes.py:52-95）——比"只有 accent 色"的工具高一个代际
   - QSS 全组件覆盖 + `scaled_px/scaled_pt` 全量缩放 + 高 DPI PassThrough 策略（app.py:34-38）
   - 热重载（theme_loader QFileSystemWatcher）——改 JSON 即时生效，配合 ThemePreviewWidget 是"开发者友好"的打磨
   - 背景图（模糊/马赛克）+ 面板透明度（`bg_panel_opacity` × `bg_header_opacity` 复合透明度，themes.py:283-299）——桌面美化能力超过大多数商业软件
2. **自绘网格的细节密度**：悬停淡入淡出、选中遮罩渐变、入场错峰、`_reduce_motion` 降级（_grid_widget.py:685-714）——**知道动画什么时候不做**（reduced motion）是专业信号
3. **统一视觉语言**：圆角（7px dock / 4px 控件）、间距、边框全部走 theme property 与 scaled_px——没有魔法像素
4. **启动体验**：启动窗口库卡片 + 主窗口 300ms 淡入（window.py:94-106）+ OpenGL 预热防首图闪烁（app.py:44-54）——"细节工程"的典型

### 问题

1. **两套视觉系统无共享源**：桌面 QSS 主题 JSON vs WebUI CSS 变量（#020617 slate 系）——品牌色、间距、圆角完全靠手工对齐；未来统一应让**主题 JSON 生成两端 token**
2. **WebUI 与桌面视觉差异明显**：桌面是多彩主题定制，Web 是固定暗色 + 单 accent（`lan_theme_color`）——用户体验断裂（浏览器里不是"我的库"的感觉）
3. **图标风格混用**：桌面 emoji 图标（🌐🔧🧩，window.py:222-246）与 WebUI lucide-react 图标并存——emoji 在不同平台渲染差异大，是"看起来像个人项目"的最大来源
4. **状态栏/托盘信息密度低**：分享状态只有文字标签 + emoji 按钮，无连接数/流量/隧道状态的实时聚合显示（数据全有：`status()` server.py:497-512，只是没展示）

## 二、交互设计

### 亮点

1. **高频路径打磨到位**：
   - 目录级视图记忆（`_view_memory`）+ 自然排序（file2 < file10）+ 隐藏文件开关——都是"真用过才知道要"的细节
   - 面包屑超过 5 层自动折叠 + "…" 弹出菜单（_navigation.py:207-232）
   - 拖放三态（网格→侧边栏收藏、网格→网格移动、外部→导入）语义清晰
   - Ctrl+滚轮缩放 + 动画插值（`_zoom_frame`）——素材浏览的手感核心
2. **异步纪律转换成体验**：缩略图分批投递防闪烁、信息面板后台加载 + 代际防过期、操作完成后选中新文件（_base.py:993）——每个异步都考虑到了"用户看到了什么"
3. **撤销/重做 + 回收站 + 系统托盘**：误操作安全的完整链条（虽然回收站视图缺失，见 G1-5）

### 问题

1. **右键菜单过载**：`_build_context_menu`（__init__.py:287）+ 插件贡献 + 命令分发——功能越多菜单越长；无菜单搜索、无图标分组
2. **反馈机制薄弱**：
   - Toast 只在文件列表（_toast.py），对话框内错误多为 QMessageBox 打断式
   - 后台任务（复制/删除/索引）无持续进度指示（G3-4）
   - 大量操作"静默成功"（成功无反馈），而"静默失败"也有（后端降级，见 02 文档 ⚠️7）
3. **确认对话框不一致**：删除走确认、清空缓存走确认、标签删除在 TagEditorDialog 内——没有一个统一的确认模式（危险度分级：破坏性/可撤销/幂等）
4. **快捷键无可视化入口**：只有一个静态 QMessageBox 列表（window.py:574-596），无法在界面上"按出"快捷键提示

## 三、信息架构（最大短板）

### 核心问题：**概念模型过载**

软件同时引入了 4 个抽象：**库**（library）、**项目**（project，深度阈值目录）、**标签**（tag，带规范名）、**元数据**（备注/URL）。真实用户（3D 素材收集者）的心智模型是："文件夹 + 文件名 + 我收藏的东西"。

- 启动窗口让用户"选择一个目录作为库"——但对用户这不是"建库"，是"打开我的素材文件夹"
- "项目"概念（ProjectService 的深度判定）从未在桌面 UI 明确解释——用户不知道为什么某些目录有"项目"标记
- 标签规范名（"贴图"→"Texture"，tag_library.py）是自动的，但用户不知道自己在被规范化

### 我的建议（信息架构修复）

1. **启动窗口改为"打开文件夹"语义**：去掉"库"术语，用"我的素材"；建库向导解释"数据保存在哪"
2. **桌面引入"最近浏览"作为默认落地页**（而不是空网格），减少概念门槛
3. **把"项目"改名为"分组/合集"或干脆在 UI 隐藏深度机制**，只显示效果（文件夹有封面）
4. **标签规范化做成可选**：默认显示用户输入原文，规范化作为"合并别名"的高级功能

## 四、无障碍与国际化

### 现状
- ✅ i18n 三语完整（桌面 + Web），语言热切换
- ✅ reduced-motion、焦点态（部分组件）、WebUI 的 `.light` 模式预留
- ❌ 无键盘导航测试、无对比度校验工具（`contrast_ratio` 工具存在但无 UI 检查）、Web 主页面无 aria 测试、桌面无高对比度模式映射

### 建议
- 用现有 `contrast_ratio`（color_utils.py:84）给主题编辑器加"对比度警告"——**低成本高专业度**的改动
- WebUI 补 `prefers-reduced-motion` 媒体查询（Gate 页已有，主页面无动画问题不大）

## 五、UI/UX 优先级建议（结合功能缺口文档）

| 优先级 | 改动 | 理由 |
|---|---|---|
| P0 | 首次分享/隧道安全确认弹窗（G6-6） | 信任安全 |
| P1 | 反馈体系：进度条 + 成功/失败 Toast 统一（G3-4） | 用户永远知道"发生了什么" |
| P1 | 标签颜色可视化（G2-1） | 信息密度提升 |
| P1 | 启动窗口"打开文件夹"语义 + 最近浏览落地（IA 修复） | 新手可用性 |
| P2 | 图标系统统一（emoji → 主题图标集） | 专业观感 |
| P2 | 主题 JSON → 双端 token 生成 | 品牌统一 |
