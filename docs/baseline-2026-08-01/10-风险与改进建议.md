## B. 数据安全与持久性

### B1. [高] 元数据绑定库目录，无完整备份/恢复机制
- 事实：标签/备注/URL 全部存在 `RuntimeData/{库名}_{hash}/assetmanager.db`；2026-08-04 已提供 Runtime scoped 的 tags/notes/URLs JSON 导出、WAL 一致性 RuntimeData 归档、只读恢复前校验和关闭 session 后的受控恢复 API，但尚无 Desktop/CLI/LAN 产品入口
- 风险：库目录被移动/删除/重装系统 → 数年整理成果丢失；用户难以迁移到其他工具
- 建议：① 提供一键导出（JSON/CSV：标签+备注+URL）② 设置页增加库数据目录"打开/备份提示" ③ 文档明确备份范围（库根 + RuntimeData 对应目录 + 缩略图）

### B2. [中] 撤销备份目录残留风险（已部分缓解）
- 事实：`UndoService._undo_dir` 用 `tempfile.mkdtemp`（系统临时目录），删除备份可还原（`_make_backup` 全量复制目录）
- 已实现：启动时仅扫描直接子目录，精确匹配 `AssetsManager_undo_*`；默认年龄阈值为 7 天，活跃进程/当前进程目录保留，单次最多清理 256 项；正常退出仍执行 `cleanup()`。
- 剩余风险：20 层深度的删除备份可能占大量磁盘；历史系统 Temp 仍可能有大量旧目录，不能在没有进一步审计的情况下批量删除。备份策略改为移动+硬链接或对超大目录跳过仍是后续任务。

### B3. [低] 文件系统监控仅覆盖当前目录
- 事实：`_navigation.py:48-66` 已有 QFileSystemWatcher，但只监视**当前正在浏览的单个目录**（`_watch_current_dir`），切换目录即重新 watch；非浏览中的目录变更仍无感知
- 风险：用户切到别的目录/在资源管理器改动其他位置后，该处目录摘要缓存/文件数缓存保持过期（需重新进入触发扫描）
- 建议：① 对库根挂常驻 watcher（防抖刷新受影响目录缓存）② 或提供定时自动刷新开关

### B4. [低] 库统计（library_stats）无更新入口
- 事实：`get_library_total_size` 依赖 `library_stats`，但 `set_library_total_size`（metadata_repository.py:225）**无任何生产调用者**；`_schedule_library_stats_update` 钩子（_base.py:1151）为基类空实现、子类未覆盖
- 风险：首页/信息面板的 `total_size` 长期为 0
- 建议：在 `refresh_all` 或后台任务中重新计算

### B5. [已解决（本阶段）] 同库多进程缺少单实例锁
- 事实：`AssetsManager/core/library_lock.py` 使用 Qt `QLockFile`，锁路径由规范化库根生成，落在 `RuntimeData/Shared/library-<hash>.lock`；锁由 canonical `LibrarySession` 的生命周期持有。
- 已实现：同一进程内多个服务对象共享底层锁，不破坏既有 foreign/stale session 兼容测试；不同进程打开同一库会被拒绝，不同库可以并行；初始化失败释放锁；session/runtime/数据库关闭成功后释放锁；关闭监听器或数据库关闭失败时保留锁，等待重试。
- 边界：这只解决同库跨进程并发打开，不等于数据库完整性自检、导出/恢复或防误删闭环；QLockFile 的锁文件不替代端口占用/分享安全提示。

## C. 功能缺口（个人用户视角）

### C1. [低] 外部导入已有基础，但缺批量/入口引导
- 事实：外部文件**可直接拖入文件列表面板**导入（`_base.py:958-994 _on_drop`：库内→移动、库外→复制，且记录撤销），能力已具备
- 剩余缺口：① 无菜单/工具栏的显式"导入文件/文件夹"入口 ② 导入目标固定为当前目录，无法选择子目录 ③ 拖入文件夹时无进度反馈（大目录 copytree 阻塞后台线程）
- 建议：补充显式导入对话框（选目标目录）+ 拖入大目录时显示进度

### C2. [中] Web 端与桌面端功能不对称
- Web 端仅浏览/下载/分享管理/标签（写标签仅 admin 通过 API）；桌面端可完整编辑
- 影响：移动端无法给文件加备注/标签（个人场景常用）
- 建议：为注册用户开放 `PUT /api/meta` 与 `POST /api/tags`（当前 tags 写接口 admin-only，tags.py:41-70）

### C3. [低] 分享下载的限次竞态
- 事实：`handle_share_download`（shares.py:215-238）：检查 `is_download_limit_reached` 与 `increment_download` 之间有窗口，极端并发可超限 1 次
- 建议：直接依赖原子 UPDATE 的返回行数判断（`UPDATE ... SET download_count=download_count+1 WHERE download_count < max`）

## D. 并发与生命周期

### D1. [中] 关闭协调复杂度高，回归风险大
- 事实：`LibraryRuntime` 状态机（open/closing/closed）+ `RuntimeEventRouter`（accepting/closing/drained）+ `WebSocketManager`（authority lease/transition）+ `LibraryService`（closing_roots）四套并发协议交织；对应测试 529 行
- 风险：此类并发代码的边界条件极难穷举；历史基线快照的 1590 passed、1 skipped 与 2026-08-05 非 E2E 的 2034 passed、2 skipped、1 warning 都是有用证据，但任何后续改动都容易破坏
- 建议：冻结该区域改动窗口；补压力测试（并发开关库 + LAN 请求 + WebSocket 连接同时进行）

### D2. [中] 单连接跨线程使用 + 三层锁的可维护性
- 事实：`check_same_thread=False` + 全局 `_WriteGate` + 每连接写锁 + owner 记录（database.py:39-78, 318-357）
- 风险：锁语义文档化不足，新维护者容易误用（如无参 `db_write_lock` 与有参版本语义不同）
- 建议：`db_write_lock()` 无参形式直接移除（`rg` 确认调用点后）

### D3. [低] WebSocket 50 连接上限与单进程吞吐
- `MAX_WS_CONNECTIONS=50`（ws.py:14）：个人/小团队场景足够；大团队需文档说明

## E. 安全观察

### E1. [中] 默认访客可浏览
- 事实：未配置任何认证时中间件直接放行 guest（server.py:980-982）；guest 默认 `lan_guest_list=True`、`lan_guest_preview=True`
- 风险：用户误开分享即对局域网全开放（设计使然，但需 UI 强调）；Cloudflare 隧道开启时等于对公网开放
- 建议：首次开启分享时弹"安全提示"确认；隧道启动前强制要求配置密码/密钥

### E2. [低] 插件权限是建议性
- 事实：README 明示插件拥有完整 Python 权限；`plugin.json` 的 `permissions` 不强制执行
- 影响：只装可信插件即可接受；可在插件管理器 UI 标注"未沙箱"

### E3. [低] 查询参数鉴权已废弃但未移除
- `get_auth_token` 仍接受 `?token=`/`?key=`（打警告）；移除后需确保 WebUI 与桌面端 `_share_api.py` 全部走 Bearer/Cookie

### E4. [中] Runtime secret 与本地 UI token 的语义容易混淆（B1 已收口）
- 事实：`AuthService`/`ShareService` 共用 Runtime-owned、每 Runtime/session 一次生成且不持久化的 `token_secret`；LAN UI token 使用由该 secret 与 `access_key/password/auth_mode` 派生的 `local_ui_auth_secret`。
- 约束：认证配置变化必须使旧 local UI token 失效；stop/start 在配置不变时保持稳定；session close 后整体失效。`LanServer.token_secret` 仅保留兼容别名，文档与新代码使用 `runtime_token_secret`。
- 协议：WebSocket revalidation、share routes、Desktop running/offline URL 必须使用实际 endpoint protocol/TLS active 状态，不能只看配置是否填写。
