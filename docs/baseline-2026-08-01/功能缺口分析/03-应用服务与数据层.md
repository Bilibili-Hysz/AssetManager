# 03 · 应用服务与数据层缺口

覆盖：`application/*`、`core/*`、`repositories/*`、`domain/*`

## G3-1 索引无全库初始化/重建入口 [P1][M]

- **现状**：`AssetIndexService.index_directory_tree`（asset_index_service.py:58）存在但**无调用者**（除文件操作后的局部刷新）；assets 表对既有库几乎为空，`search_by_name_indexed` 兜底基本失效；无"重建索引"UI
- **用户影响**：Web 端搜索降级走内存索引（内存占用大）；索引类功能（项目 file_count 预筛）不可用
- **实现路径**：① 设置/工具菜单加"重建索引"（后台线程 os.walk + 分目录提交，进度显示，M）② 首次打开大库时后台自动初始化

## G3-2 全文检索缺失 [P1][L]

- **现状**：搜索仅文件名（G1-6）；`assets` 表无内容列
- **实现路径**：SQLite FTS5 虚拟表（`assets_fts`）增量同步：文件写入时插入文本提取（txt/md/json 直接读，PDF 需 pdftotext 可选依赖）；`SearchService` 加 `search_by_content` 分支（L）

## G3-3 媒体元数据提取缺失 [P2][M]

- **现状**：无 EXIF/媒体信息读取：图片拍摄时间/相机/GPS、音视频时长/编码、模型文件统计（顶点数）均无；`file_meta` 表无字段
- **用户影响**：照片资产按拍摄日期整理、按时长筛视频等场景不可用
- **实现路径**：`MetadataService` 加 `media_info(path)`（Pillow EXIF + mutagen 可选依赖）；详情视图新增"媒体信息"区块（M）

## G3-4 文件操作无取消/进度/校验 [P1][M]

- **现状**：`FileOperationService` 全部同步执行（在 QThreadPool 线程中跑但无进度回调）；大目录复制/删除无进度、无取消、复制后不校验（不比对大小/哈希）
- **用户影响**：误操作大目录只能等；复制失败（磁盘满）只有最终错误列表
- **实现路径**：`FileOperationResult` 扩展 `progress` 回调（每项完成）；操作对话框（进度条 + 取消按钮 → 取消后回滚已完成项）；copy 后比对 `shutil.copystat` 大小（M）

## G3-5 无目录监控/自动导入 [P1][M]

- **现状**：仅当前浏览目录有 QFileSystemWatcher（_navigation.py:48-66）；无"监视文件夹 → 新文件自动入库"（个人素材常见：下载目录自动收纳）
- **实现路径**：新 `WatchService`：配置目录列表 → QFileSystemWatcher 或 watchdog → 新文件 → `copy_to_directory` + 可选自动打标签；设置页加"自动导入"区（M）

## G3-6 撤销/重做边界不足 [P2][M]

- **现状**：`UndoService` ① 删除备份全量复制（大目录复制 20 层占盘）② 无跨会话持久化（关库即清）③ 无"重做列表"UI（只有快捷键）
- **实现路径**：① 备份策略：>512MB 的目录跳过备份（提示不可撤销）或改移动（M）② 菜单"编辑"增加撤销/重做项（S）

## G3-7 项目（Project）管理能力弱 [P2][L]

- **现状**：`ProjectService` 的"项目"= 目录树中达深度的目录（project_service.py:20-26），无项目实体概念：① 无法手动指定项目封面（`find_first_image` 自动取字典序首图）② 无法固定/置顶项目（首页 recent 按 mtime）③ 无项目级笔记入口在 Web 端（`/api/meta` 有但 UI 无编辑）④ 项目统计（图片数/模型数分类）无
- **实现路径**：`project_meta` 表（封面路径覆盖 + pinned 标志 + 排序权重），ProjectService 读取覆盖（L）

## G3-8 无批量元数据 API [P2][M]

- **现状**：`MetadataService` 批量读有（get_cached_stats/batch counts）但批量写无：`set_notes_batch` / `add_url_batch` 不存在（对应 G1-1 的 UI 缺口）
- **实现路径**：批量写方法 + 单次事件发布（M，与 G1-1 一起做）

## G3-9 数据库维护工具部分交付 [P1][S]

- **现状**：`DatabaseMaintenanceService` 已提供数据库体积读取、WAL checkpoint、后台单飞和 retryable stop；`DatabaseIntegrityService` 已提供 `PRAGMA quick_check` 与保守孤儿维护。VACUUM 维护窗口、产品设置入口和统一维护协调器仍未完成。
- **实现路径**：保留当前 Qt-free service/adapter 边界，后续补齐显式 VACUUM 窗口、用户反馈和维护协调器（S-M）

## G3-10 数据完整性无自检/修复 [P1][M]

- **现状**：`DatabaseIntegrityService` 已在 Runtime 生命周期中执行 quick_check、缺失 metadata 清理和 thumbnail_cache 孤儿维护；半完成文件操作恢复、设置页“上次检查”展示和真实崩溃演练仍未完成。
- **实现路径**：继续沿用 session-bound integrity service，补齐操作日志/恢复 journal、产品反馈和崩溃演练（M，见 06-安全与可靠性.md G6-5）

## G3-11 领域层重复设计 [P2][S]

- **现状**：`domain/errors.py` 的 `PathEscapeError` 与 `lan/path_guard.py` 的 `PathEscapeError`（同名不同类）；`domain/library.py` 的 `LibraryPath` 与 `core/path_resolver.py` 功能重复
- **实现路径**：统一到 domain 层（path_guard 引用 domain 错误），`LibraryPath` 委托 path_resolver（S，纯重构，收益是降低维护成本）
