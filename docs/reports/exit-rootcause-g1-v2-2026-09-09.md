## 1. v2 实验设计（接口 × 扫描码，真拆分）

1. **拆分变量**（R1）：2×2 = 接口（keybd_event / SendInput）× 扫描码（0 / 布局查询真值）。**每格都在发送前查询键盘布局扫描码**（查询成本恒定，只差"是否使用"）：

| E | keybd_event | **0** | 归档失败驱动的输入属性（f989e27 + observed-08 时间戳锚定；负载已缩减，见 §1b） |

## 2. QQ.exe 身份补录：存在性与行为归因分开判断

round-1 §3 称"干扰源当时活跃、现不活跃"。本轮核实（2026-09-09 01:40）：

- 两个历史失败样本（observed-08，09-08 22:20；native-focus-3，09-08 22:35）超时现场的前台 PID 均为 **4212**；
- 补录查询时 PID 4212 = **QQ.exe**（`D:\_Social Media Software\Tencent QQ\QQ.exe`），原始 CreationDate 换算为 2026-09-07 12:59:13（+0800）；
- round-1 矩阵通过时段（09-08 23:35–23:51）QQ.exe 同样在前台候选列表中运行。

可锚定的结论（措辞按 V2 收窄）：QQ 在场与失败时刻**同时出现**，也在通过时刻在场——QQ 的**存在**不保证失败（非充分）。**QQ 是否必要无法判断**：没有 QQ 缺席时的失败样本，"既非充分也非必要"的"非必要"半句撤回。进程持续存活不等于其弹窗、输入钩子或焦点行为恒定，"外因随时间变化"的假设不能被此事实否定，也不能被支持。QQ.exe 保持**前台占据者相关性线索**身份：行为状态与责任均未知（前台占据≠发起者），不再作为主要定位路线的依据（V2 处置）。

环境事实来源（V2 要求补存）：[probe_pid4212_identity.py](exit-rootcause-g1-2026-09-08-evidence-v2/probe_pid4212_identity.py)（查询脚本）与 [pid4212-identity.json](exit-rootcause-g1-2026-09-08-evidence-v2/pid4212-identity.json)（09-09 补录，未嵌入精确执行时间）。记录支持该 PID 的进程身份和创建时间；原 01:40 查询未归档，不宣称完成了两份原始查询的一致性比对。进程持续存活不证明其弹窗、输入或前台行为恒定。原始记录保持不变。

## 5. 诚实边界（更新）

1. **未复现 ≠ 不存在**（保留）：两份历史失败样本的证据不被任何通过样本覆盖。
2. 接口×扫描码拆分（R1 修正后的新设计）能回答的问题是："**这两种输入属性在当前机器状态下是否单独致败**"。5/5 通过仍只支持"本轮未复现"，不支持"排除间歇性缺陷或与其他状态（如 QQ 弹窗、焦点抢占时序）的交互"。
3. 采样边界（R2 修正后的措辞）：200ms 轮询 + 每轮约 8–16 个采样点，不能排除采样间隙内的短于 200ms 状态变化；**"已采样点未见异常"不等于"异常不存在"**。首退与重启退的分相覆盖数见 §3 表。
4. IsWindowVisible=false 仍不能独立证明 HWND 已销毁。
5. G3 范畴（Qt 侧记录）本轮仍未观测——observed-08 的观察器不只是 sys.monitoring，还含应用级 Qt eventFilter 与退出信号记录（V4 更正）；G3 对照必须以完整归档文件及哈希为条件，不得按"仅 sys.monitoring"的文字重新实现。
6. 本轮 20 周期为缩减负载对照（§1b），与历史负载的可比性受限；"四组连续运行的时间差"不构成受控环境差异的证据。

## 6. 下一项区分实验（修正后）

1. **事件链对齐优先**：由 G3/G2 冻结负载和观察条件，记录测试窗口输入、Qt 调用及状态事件；前台 PID/进程名仅作关联辅助，不等于键盘焦点或最小化发起者。出现失败时，从最早缺失的链路证据继续定位。暂不安排缺少区分假设的固定 30 轮长跑。
2. **G3 观察器对照**（R4 修正版）：按完整归档文件及哈希区分条件——①无插件、②observed-08 原样条件（sys.monitoring、应用级 Qt eventFilter、退出信号记录，无原生过滤器）、③增加原生消息记录条件（observed-09 型）。三组分别命名、分别统计结果，不合并。
3. **失败边界重放的前提**：QQ 活跃时段长跑**降级为次要路线**（V2 处置）——QQ 行为状态未观测、责任未知，不宜作为主要定位依据。若 G3 对照或 G2 事件链对齐产生"时机放大"假设，再按该假设设计定向重放。
4. 结案标准维持工作包第 5 条：允许"未定位"交付，不制造生产补丁。

## 7. 结案状态

round-1 的"输入形式排除为充分原因"结论**统一改为**："四组（round-1 A–D 与 v2 E–H）本轮均未复现，未观察到输入属性与结果差异的关联"。在（a）接口与扫描码共变的拆分缺陷被修正、（b）历史形态锚定收窄到"可证实的输入属性"（负载不可比）、（c）重启相与首退分列计数之后，本篇以 v2 矩阵结果为准重新表述（见 §3/§4）。round-1 的 40 退出 code 0 记录仍然有效，但其矩阵定义、历史形态标注、外因时变推断、"40 次退出零最小化"概括均已被本篇取代。G1 线以"本轮对照未复现"阶段交付转交 G3/G2 联合事件链对齐，不再积累同条件的通过次数。
