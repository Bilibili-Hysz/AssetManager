复核未点名、但本轮核实中发现的**第五处事实错误**：

> **round-1 §1 的"A 形态 = 历史失败形态（30ms 间隙）"标注错误。** 三个证据：
> 1. 归档历史失败驱动（final-matrix-native-focus，`f989e271d1a6…`）的 `keybd_event` 调用之间**没有任何 sleep**；

## 1. v2 实验设计（接口 × 扫描码，真拆分）

从官方验收驱动 bd8142 重新派生 [w6_g1_input_v2.py](exit-rootcause-g1-2026-09-08-evidence-v2/g1v2-driver.py)（官方驱动未动），v2 对 round-1 的四项修正：

1. **拆分变量**（R1）：2×2 = 接口（keybd_event / SendInput）× 扫描码（0 / 布局查询真值）。**每格都在发送前查询键盘布局扫描码**（查询成本恒定，只差"是否使用"）：

| 形态 | 接口 | scan | 语义 |
|---|---|---|---|
| E | keybd_event | **0** | **历史失败精确形态**（f989e27 + observed-08 时间戳双重证实） |
| F | keybd_event | 布局真值 | 仅扫描码变量 |
| G | SendInput | **0** | 仅接口变量 |
| H | SendInput | 布局真值 | 当前官方形态（= bd8142 = round-1 D） |

2. **去掉全部事件间 sleep**：历史失败形态本就背靠背（§0），round-1 的间隙因子撤出设计——A/C 形态间隙采样随之移除，前台观测改由退出期 200ms 采样流承担。
3. **重启相采样接线**（R2）：`_wait_for_exit` 现在首退、重启退都传 HWND + samples。
4. **前台归因**（R3）：每 200ms 采样记录全系统前台窗口 PID + **进程名**（快照解析）；逐轮 JSON 嵌入驱动 SHA-256、argv、形态定义、墙钟起点。

每格 5 轮 ×（启动 → 自动开库 → 功能链 → Ctrl+Q 退出 → 重启 → 功能链 → 二次 Ctrl+Q 退出）= 20 周期 **40 次退出**，全部 onefile maximized（历史失败配置）。候选包哈希逐轮绑定 `1d568fb8…`（与工作包登记一致）。

环境条件（如实登记）：矩阵运行期间桌面上**存活两个用户应用实例**（run.py，09-08 16:18/16:20 启动）与 QQ.exe（PID 4212）——与两个历史失败样本发生时的环境构成一致（见 §2），AM_RUNTIME_ROOT + 独立端口保证单实例管道不冲突。

## 2. QQ.exe 事实：round-1"外因归因"被环境证据否定

round-1 §3 称"干扰源当时活跃、现不活跃"。本轮核实（2026-09-09 01:40）：

- 两个历史失败样本（observed-08，09-08 22:20；native-focus-3，09-08 22:35）超时现场的前台 PID 均为 **4212**；
- PID 4212 = **QQ.exe**（`D:\_Social Media Software\Tencent QQ\QQ.exe`），2026-09-07 12:58 启动，**至今存活**；
- round-1 矩阵通过时段（09-08 23:35–23:51）QQ.exe 同样在前台候选列表中运行。

即：**"QQ 在场"既出现在失败时刻、也出现在通过时刻**——它的存在本身既不是失败的充分条件也不是必要条件，round-1 的"干扰源现已不活跃"说法被直接否定。QQ.exe 作为失败现场前台占据者仍是**待验证的相关性线索**（谁发起最小化仍未知——前台占据只能建立相关性，不能归责），但不能再作为"外因时变"的依据。

## 5. 诚实边界（更新）

1. **未复现 ≠ 不存在**（保留）：两份历史失败样本的证据不被任何通过样本覆盖。
2. 接口×扫描码拆分（R1 修正后的新设计）能回答的问题是："**这两种输入属性在当前机器状态下是否单独致败**"。5/5 通过仍只支持"本轮未复现"，不支持"排除间歇性缺陷或与其他状态（如 QQ 弹窗、焦点抢占时序）的交互"。
3. 采样边界（R2 修正后的措辞）：200ms 轮询 + 每轮约 8–16 个采样点，不能排除采样间隙内的短于 200ms 状态变化；**"已采样点未见异常"不等于"异常不存在"**。首退与重启退的分相覆盖数见 §3 表。
4. IsWindowVisible=false 仍不能独立证明 HWND 已销毁。
5. G3 范畴（Qt 侧记录）本轮仍未观测——observed-08 的"Qt 零键记录"仍只在观察器视角成立。

## 6. 下一项区分实验（修正后）

1. **全系统前台变化记录**（保留，R3 修正版）：不预设 QQ 有责。退出等待期记录全系统 GetForegroundWindow 变化流 + 焦点进程名，在用户活跃时段长跑（≥30 轮）；**若长跑中出现一次失败，第一时间用当日归档的状态序列 + 前台流定位前台/最小化时刻的进程名，再判层级**。v2 驱动已具备该归因能力（fg_pid + fg_name 已在采样流中）。
2. **G3 观察器对照**（R4 修正版）：按哈希区分条件——①无插件、②observed-08 原样条件（仅 sys.monitoring，无原生过滤器）、③增加原生消息记录条件（observed-09 型）。三组分别命名、分别成功率，不合并。
3. **失败边界的定向重放**：若需要更快逼近复现，下一轮优先在 **QQ 活跃交互时段**（弹窗/消息到达时段）运行 E 形态长跑——这是目前唯一同时出现在两个失败现场的第三方进程，作为"时机放大器"假设而非定责。
4. 结案标准维持工作包第 5 条：允许"未定位"交付，不制造生产补丁。
