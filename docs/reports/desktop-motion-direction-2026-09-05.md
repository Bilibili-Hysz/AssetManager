# 桌面动画系统：未来方向与交互构思

> 状态：**DESIGN PROPOSAL（未来设计补充，未实施）**  
> 日期：2026-09-05。作为[桌面视觉一致性方案](desktop-visual-consistency-2026-09-05.md)的动画专项补充。  
> 依据：当前动画、自绘网格、缩放、分段切换和通知代码；源码基线沿用主报告的工作区摘要。以下参数均为首轮原型建议，不是已验证的最佳值或现有效果声明。

## 1. 想获得的界面感受

让界面表现出**及时回应、连续跟随、轻微弹性和清晰层次**：鼠标指向时控件有所回应，点击后状态立即建立，切换时知道内容去了哪里，结果到达时能自然注意到变化。

建议将“灵动”落实为四种体验：

- **跟手**：快速切换标签、调整缩略图尺寸时，动画从当前状态转向新的目标。
- **有触感**：按钮、标签和导航指示器有短促而轻微的按下/释放反馈。
- **有连续性**：资产卡与预览、展开与收起、列表更新之间保留位置和对象关系。
- **有节奏**：用户操作、内容载入和结果反馈各有节奏，同一时刻的主动作明确。

默认动态强度建议为“自然”。让操作区富有反馈，素材本身稳定可看；较明显的弹性用于导航指示器和小控件，大图、文字输入区保持稳定。

**本次新确认的时间模型问题**：网格定时器间隔为16ms，缩略图每次回调增加0.12，hover/选择每次按0.30比例接近目标；入场队列每次释放 `max(1, len(queue)//12)` 项。因进度按回调次数推进，界面忙碌时完成时间会伸长，入场节奏也受队列长度影响。

这不等于已实测动画卡顿。Qt说明定时器可能晚于预定时间触发，超时合并时不会补发每一次回调，因此后续应按实际经过时间计算进度。[Qt QTimer 文档](https://doc.qt.io/qt-6/qtimer.html)

## 3. 动画语法：让不同组件像同一套系统

### 3.1 建议动作角色

| 角色 | 用户感受 | 首轮时长/幅度建议 | 适用位置 |
|---|---|---|---|
| `feedback` 即时反馈 | 按下就有回应 | 立即建立pressed状态；释放过渡80–120ms | 按钮、图标、评分、标签操作 |
| `follow` 追随 | 指示器跟着选择走 | 140–220ms，必要时轻微弹性 | 工作区/分段指示器、控件滑块 |
| `reveal` 显露 | 新区域自然出现 | 160–220ms；局部位移4–8逻辑px | 浮层、详情内容、筛选面板 |
| `dismiss` 退出 | 完成后轻快离场 | 100–160ms，通常比进入短 | 快捷浮层、临时提示 |
| `reflow` 重排 | 位置变化能被追踪 | 180–240ms；按对象身份衔接 | 集合项增删、少量可见卡片重排 |
| `resolve` 结果到达 | 从等待变成可用 | 120–180ms局部交叉淡化 | 缩略图、预览、状态图标 |
| `attention` 轻提示 | 知道哪里变了 | 一次150–240ms颜色/轮廓强调 | 标签新增、保存成功、连接建立 |

这些是具名动作配方，不能再演变成每个组件自行选择一组数字。现有 micro/fast/normal/slow 可继续作为底层时长档位；动作角色在其上定义曲线、幅度、退出策略和降级方式。

80–120ms等数值与现有档位之间的映射在样板阶段确定，不应先全面替换生产值。入场延迟、接口超时、搜索防抖和Toast阅读停留时间属于不同语义，分别管理。

### 3.2 弹性应体现在哪里

建议先给**小型导航指示器和控件装饰层**增加接近临界阻尼的轻弹性，幅度小、快速稳定。默认不对长文本、大图、整个主窗口做反复回弹。

首轮可对比两种原型：

- 自然模式：不越过目标，以连续减速体现柔和感。
- 灵动模式：允许一次轻微越界，位移不超过目标行程的约3%，且有1–2逻辑px的绝对上限；不允许连续振荡。

数值仅用于视觉试验。若实际平台像素取整导致抖动，优先使用平滑无越界曲线；自绘阶段可采用浮点状态，在绘制时再处理像素对齐。

## 4. 具体交互构思

| 场景 | 建议动画 | 触发与收尾规则 | 级别 |
|---|---|---|---|
| 图标按钮 | hover底色柔和显现；按下装饰层轻缩，释放归位 | 热区固定；支持键盘；不缩放文字、不触发父布局重排 | 第一批 |
| 标签/工作区切换 | 选中背景与指示器连续追随，宽度跟随目标标题 | 内容状态立即切换；连续点击时直接转向最新目标 | 第一批 |
| 网格悬停 | 当前卡片轮廓增强，卡片底板轻抬1–2px，图片主体尽量稳定 | 鼠标快速划过不积累动画；只更新新旧hover项 | 第一批 |
| 网格选择 | 点击立即显示选择边框，底色短过渡；取消选择柔和淡出 | 多选结果立即准确；拖框选中时用直接反馈，结束后不逐项补播 | 第一批 |
| 标签新增/移除 | 新胶囊轻显露并获得一次轮廓强调；移除后附近项平滑补位 | 业务提交与成功反馈分离；失败保留原状态并就近说明 | 第一批 |
| 星级/收藏 | 点击时图标短促强调，成功后稳定为已选态 | 取消也有反馈；不反复跳动；后台失败明确恢复 | 第一批 |
| 信息面板换选 | 标题与元数据先更新；预览就绪后局部交叉淡化 | 只呈现最新资产；不能把旧图继续显示成新文件的预览 | 第一批 |
| 打开QuickLook/QuickTagger | 浮层从轻微偏移/轻缩到稳定，遮罩同步显现；退出更短 | 可立即Esc关闭，焦点与交互区域立即建立；大内容用缓存装饰层过渡 | 第一批 |
| 搜索与筛选 | 筛选激活标记立即变化；结果就绪后少量重排或淡化 | 不为每个按键播放整页入场；等待状态真实，旧查询结果不得覆盖新查询 | 第二批 |
| 进入目录 | 面包屑更新，网格上方轻微引导；新内容一次短过渡 | 明确前进/后退时可用方向提示；跳转或换库用中性过渡 | 第二批 |
| 网格尺寸调整 | 保持鼠标或当前资产锚点，卡片位置连续变换，末段文字清晰落定 | 沿用已有缩放路径；用户继续滚动时从当前可见状态接续 | 第一批调优 |
| 侧栏/信息栏显隐 | 边缘滑入与内容淡化组合，形成“从侧面展开”的关系 | 切换期间保留实际焦点规则；不在每帧强制重算整个网格 | 第二批 |
| 展开树节点 | 新分支短显露，当前节点和箭头同步反馈 | 大目录按需装载；不先等待动画完成才开始读目录 | 第二批 |
| 批量导入 | 已成功项小批出现，状态栏同步更新；最终只强调一次完成 | 大批量只对当前视口有限元素动画，其余直接显示；进度来自真实任务 | 第二批 |
| Toast/复制成功 | 状态图标短变换＋轻显露；相同重复提示合并 | 保证可读停留时间；不把退出动画时间当阅读时间；不抢焦点 | 第一批 |
| 主题切换 | 优先过渡界面承载面和控件颜色，保留资产图像 | 先完成V01/V02样式统一；不让大图随主窗口透明度变化而闪烁 | 第二批试验 |
| 缩略图→大预览 | 以源卡片的位置/比例为起点，展开到预览画布；关闭时返回来源 | 同一资产仍可定位才做关联；源卡离屏或切库后改用普通淡出 | 探索批 |
| 集合拖放 | 可接收区域提前显露，释放时落点有轻反馈 | 基于真实拖放结果；无效目标使用明确提示，不依赖弹跳表达失败 | 探索批 |

## 5. 三段体验脚本

### 5.1 浏览一张图片：指向 → 选择 → 预览 → 返回

1. 指向卡片：底板轻抬、轮廓显现，名称位置和点击热区保持稳定。
2. 点击：选择边框立即确定；底色在约120ms内完成过渡，右侧标题与信息开始更新。
3. 预览解码完成：图片在约160ms内与占位衔接；若马上换选，直接取消上一张的未完成过渡。
4. 按空格：快捷预览在约200ms内进入；用户从开始就可以按Esc退出。
5. 关闭：约140ms退场，焦点返回原卡片；探索阶段再试验从大图回到卡片的空间关联。

步骤之间由用户动作和真实数据结果触发，不串成必须等待上一段结束的固定演出。

### 5.2 连续打标：输入 → 增加 → 继续输入

1. 输入框保持稳定，不随新标签重排而失去焦点。
2. 提交后立即进入明确的处理中状态；本地写入成功才出现确认反馈。
3. 新标签用约160ms的轻显露，周围可见标签在约180ms内调整位置。
4. 短时间连续新增多项时合并重排，最后一项轻强调，已存在标签不再次入场。
5. 写入失败时保留输入与错误说明，可直接重试；动态反馈不假装保存成功。

### 5.3 切换筛选：条件变化 → 结果落定

1. 筛选按钮/条件胶囊立即显示激活，先让用户确认操作已接收。
2. 数据未返回时保持容器稳定；只有超过建议约120ms的等待阈值才显示轻量忙碌提示，避免快请求闪烁。
3. 结果到达后先形成准确的可选择列表；少量仍存在的可见资产按稳定身份衔接位置。
4. 大幅结果变化、快速连续输入或低性能状态下，用约120ms的局部淡化代替大量位移动画。
5. 空结果显示现有空态组件；不把整页内容先收走再缓慢显示“没有结果”。

以上时间线均为原型参数。数据加载、可操作时间与动画时间应分别记录。

## 6. 建议的动画系统组织

### 6.1 统一策略与状态，不强行统一成一种渲染方式

建议演进为四层：

1. **MotionTokens**：时长、曲线、位移、缩放、分组错峰上限；与主题配置建立明确关系。
2. **MotionPolicy**：用户强度、reduce_motion、窗口可见性、负载预算和全局停止策略。
3. **MotionController**：跟踪拥有者、动画通道、当前值/目标值、取消、中断、合并和完成状态。
4. **执行适配**：普通Qt属性使用QPropertyAnimation/QVariantAnimation；网格继续用集中自绘状态与按行重绘。

以上名称是责任划分草案，不要求创建四个复杂框架。先用少量组件验证公共接口，再抽取实际重复部分。Qt已有属性动画和动画组，可继续用于合适的控件过渡。[Qt Animation Framework](https://doc.qt.io/qt-6/animation-overview.html)

每个动画实例至少需要标明：组件拥有者、目标属性/通道、动作角色、当前目标、业务/模型世代、中断方式、减弱动态效果替代方案。不要把业务写入放进动画完成回调。

### 6.2 使用实际时间推进

网格优先改为基于单调时钟的进度：

- 有限时长动画：`progress = clamp((now - started_at) / duration, 0, 1)`。
- 连续追随：按实际 `dt` 更新；现有每16ms乘0.30的追随，可先用 `factor = 1 - (1 - 0.30) ** (dt / 0.016)` 保留近似手感。
- 定时器只负责请求下一次更新；不能把“16ms定时器”视作稳定60fps承诺。
- 长时间挂起/窗口隐藏后直接恢复到最终状态，不补播错过的历史帧；实际弹簧数值积分须控制大步长或使用稳定解析方式。

固定时长动画和弹簧各有用途。选中显现、错误反馈需要明确完成时间；持续拖动和指示器追随更适合追随模型。真实物理弹簧还需要保留速度；反复重启一个带弹性曲线的动画不等同于连续物理弹簧。

### 6.3 中断、优先级与完成语义

| 情况 | 应有行为 |
|---|---|
| 同一属性收到新目标 | 取消旧目标，从当前显示值接续；弹簧场景保留合理速度 |
| hover刚进入又离开 | 平滑反向，不先跳回起点，也不继续完成旧入场 |
| 正在展开时按Esc | 立即转为关闭过程；减弱动态效果时直接关闭 |
| 点击A后很快点击B/C | 逻辑状态跟随最新选择；动画不排队依次补播A/B |
| 重复相同目标 | 合并请求，不重新启动计时 |
| 排序/过滤/异步结果改变行号 | 按稳定资产身份与世代检查映射；不能把旧行号动画套到新文件 |
| 切库/关闭/控件销毁 | 停止相关动画、释放缓存/订阅，旧回调不能更新新界面 |
| 拖动和自动过渡冲突 | 用户直接操作优先；交互→导航→数据显露→装饰依次降级 |
| 快速连续通知/入场 | 合并与限量；不堆积一个长队列 |

同一组件可以同时有选择和hover，但应写入不同状态通道，再由绘制层合成。几何位置只能有一个明确拥有者，避免Qt布局、缩放动画和弹簧控制器同时争抢。

## 7. 在 QWidget/QPainter 中落地的细节

### 7.1 小控件

按钮的点击区域和布局尺寸保持固定，可改变图标/底板的绘制偏移与缩放。普通QWidget没有Web式通用transform，不应假定给所有控件设置一个scale属性就能工作。轻量自绘装饰或自定义属性适合小组件；优先保持文本清晰。

### 7.2 大面板与停靠区域

面板宽度动画可能反复触发布局和网格重排。先试验两种实现：

- 简单场景：限制宽度过渡的范围和时长，复用布局预算。
- 复杂场景：在绘制覆盖层上过渡内容快照，真实布局只在必要节点更新；遮罩、焦点和命中区域必须与实际可用控件一致。

快照不能包含过期资产信息并被误认为新内容，也不能无限缓存大图。若当前版本无法可靠协调QDockWidget布局，就先采用直接布局变化＋局部内容淡化，随后单独研究停靠动画。

### 7.3 网格与重排

继续复用当前纹理缓存，动画优先绘制选择/hover层；状态变化不重新解码图片。重排只为可见且身份稳定的少量资产保存起止矩形，绘制矩形、命中测试和键盘焦点需要共享过渡坐标。

首屏可以尝试“成组轻显露”，例如每组间隔20–30ms、最多3–4组，整个错峰窗口不超过约120ms。缩略图有数据即可显示，入场装饰不应把已可用资产藏起来等待排队。持续滚动不重复播放每一屏的完整入场。

### 7.4 阴影、透明度与像素清晰度

优先动态调整已有阴影/底板强度或使用缓存绘制，不在每个卡片每一帧创建模糊效果。QGraphicsEffect的组合与成本要单独核查，避免阴影被新透明度效果替换。文字与细线最终落位到适合当前DPR的像素边界；不要每帧重新生成整套QSS来模拟颜色动画。

## 8. 用户强度、性能预算与自然降级

### 8.1 强度模式构思

| 模式 | 行为 |
|---|---|
| 减少动态效果 | 立即呈现最终状态，关闭位移、缩放、错峰和弹性；用静态轮廓/文案维持反馈，状态信息完整 |
| 自然（建议默认） | 短过渡、连续追随、轻幅度；大内容稳定，无循环装饰 |
| 灵动（可选） | 小指示器轻弹性、少量成组显露、验证通过的关联预览过渡 |

第一轮可以只实现“自然＋现有reduce_motion”，无需立即增加复杂设置。旧布尔设置开启时优先映射到减少动态效果。未来若接入系统动画偏好，需要明确系统与应用覆盖关系；当前不能声称已遵循系统设置。

配色主题与动态强度尽量独立，切换颜色主题不应意外把界面变成更强烈的动画模式。

### 8.2 预算与降级次序

建议在固定测试机器上记录输入到首次可见反馈、动画步进时间、绘制时间、布局次数、活动动画数和临时纹理内存。60Hz的整帧时间约16.7ms，120Hz约8.3ms；这是屏幕刷新周期，不是动画代码可独占的预算。

首轮工程目标可设为普通场景中动画状态计算的p95≤1ms；绘制、解码和布局另计，并按实际设备校准。当前没有实测证明项目已达到该目标。

负载升高时依次：取消装饰错峰→关闭弹性/位移→减少关联预览特效→直接呈现最终状态。保留点击反馈、选择边框、错误和进度信息。降级条件应依据连续多个采样窗口，恢复也应有稳定窗口，避免同一动作中频繁切换质量。

窗口隐藏、最小化和无活动动画时停止装饰更新。自绘网格可集中调度；普通Qt属性动画沿用Qt调度能力，不再额外启动一个持续运行的全局16ms计时器。

## 9. 分批实施建议

| 批次 | 内容 | 用户可感知的收益 | 验证门槛 |
|---|---|---|---|
| M0 时间与策略 | 时间驱动、公共reduce_motion、中断/清理、测量点 | 在忙碌时节奏更稳定，快速操作不拖尾 | 伪时钟测试、切库/关闭与重复中断测试 |
| M1 高频微交互 | 指示器追随、按钮、网格hover/选择、标签、Toast、浮层进出 | 日常点击与切换更跟手、更有反馈 | 同一场景自然/减少动态效果录屏与响应对照 |
| M2 内容连续性 | 信息面板预览、筛选结果、有限重排、侧栏显隐、主题过渡 | 页面变化更容易理解，突兀跳变减少 | 长列表、异步乱序、大图、不同DPI与负载测试 |
| M3 探索效果 | 卡片到大图的关联过渡、轻弹簧、集合拖放 | 有辨识度的空间感与轻弹性 | 单项原型评审、性能与焦点命中验证后才推广 |

与主报告阶段的衔接：A阶段固定动作样板；B/C阶段开展M0/M1；D阶段接入浮层；样式与布局稳定后进行M2/M3。完整关联预览或复杂弹簧不应成为基础视觉统一的前置条件。

## 10. 动画验收与原型交付

每个动作原型交付一张规格卡：触发动作、起止状态、角色、时长/曲线/幅度、可中断方式、业务失败处理、减少动态效果版本、性能采样和短录屏。原型阶段用真实界面和固定素材；后续可在现有主题样板中增加可重复播放的“动态样板”页。

至少验证：

1. 以16ms、33ms和不规则间隔推进伪时钟，同一绝对时间的过渡状态近似一致；长停顿后能够正确落定。
2. 连续切换十次标签、快速进出hover、滚轮缩放反向，位置不跳回旧起点，不排队播放过期目标。
3. 打开浮层后立即Esc、动画中换库/关闭窗口，不留透明窗口、旧纹理、幽灵焦点或持续计时器。
4. 单击、多选、拖框、重排期间命中与可见位置一致；逻辑结果不依赖动画是否完成。
5. 预览A慢、预览B快时最终只显示B；空结果、加载失败和成功状态不会因过渡被掩盖。
6. reduce_motion切换时立即停止不必要的运动并正确落定；功能、内容和状态不减少。
7. 深浅主题、不同UI缩放和系统DPI下，最终文字清晰、布局稳定、动态幅度一致。
8. 大目录加载与动画并行时，对比功能可用时间、卡顿分布和空闲CPU；画面更柔和不能以操作被延后为代价。

建议先制作四个代表样板：**标签指示器追随、网格hover/选择、信息预览切换、快捷浮层打开/关闭**。这四处能同时检验跟手感、弹性尺度、异步衔接和层次感，是“界面更灵动”的首轮落点。
