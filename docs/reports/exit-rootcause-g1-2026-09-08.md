> 执行：主代理。候选与驱动哈希已核对（onefile `1d568fb8…` / onedir `6afcf663…` / 基准驱动 `bd8142…` 全匹配）。
> 结论级别：**输入形式排除为充分原因；历史失败本轮未复现**（未复现 ≠ 不存在）。

## 1. 实验设计

从基准驱动 `bd8142` 派生实验驱动（[g1-experiment-driver.py](exit-rootcause-g1-2026-09-08-evidence/g1-experiment-driver.py)，官方验收驱动未动），实现 2×2 判别矩阵——把历史上**同时改变**的两个因素拆开：

| 形态 | 注入接口 | 事件间 30ms 间隙 | 对应历史 |
|---|---|---|---|
| A | keybd_event（vk-only，flags=0） | **有**（ historical 失败形态） | 修复前驱动 |
| B | keybd_event（vk-only） | 无 | 仅接口变量 |
| C | SendInput（vk+scan） | **有** | 仅时序变量 |
| D | SendInput（vk+scan） | 无 | 当前通过形态（`bd8142`） |

遥测增强（基准驱动没有的观测点）：
- **空隙内采样**：A/C 形态在每次 30ms 间隙中点插入前台/修饰键观测——历史四相采样只覆盖事件边界，间隙内的抢占不可见；
- **退出期窗口状态采样器**：`_wait_for_exit` 改为 200ms 轮询，记录 IsIconic/IsZoomed/可见/前台的时间序列——捕捉"最小化发生在何时"；
- 每形态 5 轮 × 完整周期（启动 → 自检 → Ctrl+Q 退出 → **重启** → 自检 → 二次 Ctrl+Q 退出）= 每形态 10 次退出、共 **40 次退出事件**，全部在 onefile maximized（历史失败形态）。

**核心观察**：
1. 历史失败形态 A 在本轮 **5/5 全过**（含重启退出）——未复现。
2. A/C（有间隙）与 B/D（无间隙）无失败差异——**间隙本身在当前条件下不致败**。
3. 40 次退出中**零次**空隙内前台翻转、**零次**最小化转换；每次退出的状态序列均为
   `(非最小化, 最大化, 前台) → 窗口消失`——退出即销毁，无中间态。

## 3. 故障层级判定表

| 链路层级 | 本轮判定 | 依据与边界 |
|---|---|---|
| 输入生成（keybd_event vs SendInput） | **排除为充分原因** | A 形态 5/5 过；接口差异单独存在不致败 |
| 事件间隙（30ms 睡眠） | **排除为充分原因** | C 形态带间隙 5/5 过；20 周期空隙内零抢占 |
| 前台/焦点保持 | 当前桌面状态下**未见异常** | 四相 + 空隙采样全覆盖；历史 native-focus-3 的"四相完美仍超时"本轮无对应样本 |
| 退出期窗口状态 | 正常 | 零最小化/零前台丢失；历史超时现场的 IsIconic=true **本轮无对应** |
| Qt 键事件→Shortcut→request_exit | **本轮未观测**（无 Qt 侧记录器） | observed-08 的"Qt 零键记录"仍只在观察器视角成立；G3 范畴 |
| 外部干扰（最小化来源） | **头号剩余假设** | 历史超时现场 IsIconic=true 无代码路径可解释；本轮同时段无此现象——干扰源当时活跃、现不活跃 |

## 4. 诚实边界

- **未复现 ≠ 不存在**：历史两份失败样本（observed-08、native-focus-3）的证据不被本轮覆盖；本轮证明的是"输入形式与间隙时序在当前机器状态下不致败"。
- 历史失败的必要条件大概率包含**当时刻的桌面/机器状态**（外部最小化与前台抢占同源），该状态本轮未出现，无法回放。
- 重启相的第二次退出未接采样器（驱动只接首退）——重启相的中间态时序本轮仅有退出码证据。
- 样本量 5×4 不足以宣称"零故障率"，只支持"本轮未复现"。

## 5. 下一项区分实验（建议）

1. **全系统前台变化记录**：退出等待期不只看目标窗口，记录全系统 GetForegroundWindow 变化流 + 焦点进程名——在用户活跃时段长跑（≥30 轮），把"外部最小化/抢占"从假设变为可直接观测的事件。
2. **G3 观察器对照**：以 observed-08 归档观察器（sys.monitoring + 原生消息过滤器）复跑 A 形态 ×10，检验观察器是否改变失败概率（当时观察器在场且失败）。
3. **重启相采样补全**：把退出期采样器接到重启相第二次退出（一行改动），补齐重启中间态时序。
4. 若长跑复现一次失败：立即以当日归档的状态序列 + 全系统前台流定位最小化/抢占时刻的来源进程，再判层级。
