## 4. N3：资源基线与归还合同

当前继承基线：小图/批量/ZIP 响应已验证，192 MiB 同对象取消后流式重试已通过；服务器与客户端循环分开采样。当前 `bounded` 只对应重复批次 RSS 增长，不代表完整容量或资源回收达标。

实施入口与第一条测试见 [LAN 工作包](week-2026-09-14-lan-workpack.md)。ZIP 预算饱和按现有合同为 `503 + Retry-After`，与访客额度拒绝的 429 分开；取消后是否仍占名额须通过清理屏障确定，不能假设所有清理都慢。

1. 先列现有服务器下载任务、ZIP 名额/预留、临时文件与清理重试对象的内部所有者。优先在测试 harness 观察已有状态，不为验收新增公开管理接口。
2. 用服务端屏障确认请求进入传输；记录实际取消量，验证 30s 观察窗口内状态回到规定起点或进入明确 pending 重试状态。具体阈值须与现有合同核对，不能忽略 OS 故意清理失败。
3. 独占机器执行并发 1/2/4、一次 ZIP 第五请求拒绝、慢读/取消；采集服务端 loop p95/max、RSS 时序、临时盘、任务/名额与实际字节。
4. 先小样本后大图/目录 ZIP；明确冷暖缓存、数据集哈希、机器条件。测出预算问题再决定限流或输出预算实现，不预先重写传输管线。

**退出条件：** 成功/失败/取消都有明确资源归属证据；未测范围明确登记，JSON、文本摘要与源码匹配。ZIP 崩溃后持久回收先产设计和复现依据，未经归属方案审查不实现批量删除。
