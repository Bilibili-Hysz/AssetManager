## 1. 本周要交付的结果

发送者从选择内容进入统一分享中心，在同一流程完成必要配置、启动与链接/二维码交付。接收者在同网和另一网络两种条件下打开分享，进入同一套清晰的浏览、图片预览与单文件下载体验。

本周目标是首批可运行链路和明确的首次配置缺口；整个 WebUI 的完整迁移继续分批交付。服务认证、作用域、资源回收和数据正确性是改造门槛，不以自动化“全绿”代替真实设备上的可用性。

## 3. P：先统一产品流程

输入：用户已反馈两端难用、无法一键快速配置；已确认两种网络方式同等优先，首版无需访客编辑能力。

输出两端可交互原型及场景脚本：
- 桌面：选择内容 → 同网/互联网 → 开始分享 → 必要的首次配置 → 链接/二维码与状态 → 停止该分享。
- 接收端：打开分享 → 必要验证 → 文件夹/文件 → 预览 → 下载 → 返回原位置。
- 两端包含启动中、依赖缺失、网络失败、链接过期/撤销、错误访问码、取消与重试。

原型重点确认步骤、信息层级与恢复路径，使用既有视觉 tokens；不先花预算做复杂背景和动效。首次评审同时走两种分享方式，不先验收一种再设计另一种。

**出口**：同一份页面/状态地图、DTO 草案和 U1–U9 使用脚本；用户审阅原型可继续修正方向，其他线同时推进不依赖视觉细节的合同工作。

## 4. S：桌面分享中心

主页面包括快速分享、正在分享和高级设置。菜单、顶栏、状态栏与所选文件入口统一进入中心，保留当前库与选中内容。

必须完成：
1. 同网与互联网两个同级流程，复用内容范围与权限摘要。
2. 自动处理已有条件下的配置与启动；首次缺项在流程内补齐，取消/失败保留选择。
3. 明确“服务启动”“链接生成”“设备已连接”的不同状态；未验证可达时不假报成功。
4. 链接、QR、新建和列表复制统一使用所选交付地址。
5. 停止单个分享与停止整个服务分开；重复点击/重试幂等，不误停其他分享。
6. 高级页保留现有配置能力，但不作为常规分享必经页。

复用 ShareService、LanControlPort/ShareSettingsPort、既有 LAN/远程通道。互联网流程保留服务级认证预检；单链接访问码不能替代它。运行中的其他分享需要保护，不能静默覆盖凭据或重启服务。

**文件边界**：dialogs/sharing_settings_dialog.py、share_link_dialog.py、widgets/lan_sharing.py、必要的 window.py 入口与新 UI/协调组件。协调层接口与 A 线先对齐；大型文件逐步拆分，不复制第二套服务生命周期。

## 5. A：双端共用的服务与地址合同

当前已确认的直接缺口：
- 链接表复制固定拼接本机 HTTP 地址，与其他入口的 status URL 不一致。
- 创建分享记录与服务就绪可达没有统一的任务结果。
- 分享接收端 API 缺少明确的目录 listing；既有 /browse 不能直接作为分享范围浏览后门。

本周最小增量：
- 定义交付地址解析：LAN、公网、本机入口；来源/状态/访问条件一致，供复制和 QR 共用。
- 定义分享范围目录条目：相对路径、类型、名称、大小、预览能力、分页及错误码；按 share scope 验证每一请求。
- 明确准备状态、取消和资源归属，失败只回滚本次资源。
- 核对服务级认证、单分享授权及受限 cookie 的衔接，保留撤销、有效期与下载额度合同。

**出口**：真实接口及客户端适配器可驱动 W 的最小目录浏览；越界路径、撤销后继续访问、失效链接和无授权访问均有回归。若接口范围超过 6h，先缩小额外字段与媒体能力，保留目录浏览和安全边界。

**文件边界**：application 的必要 ports/协调器、lan/routes/shares.py、DTO/API 注册与定向测试；与 S 共同拥有的接口由 A 定义、主代理统一整合。

## 6. W：接收端 WebUI 重写

首版访客打开链接直达分享内容，不必先选择“画廊”或“工作台”。文件/文件夹区分，主要操作有文字，手机上能够准确点击。

必须完成：
- 分享首页、目录与预览的统一导航；返回恢复目录/滚动，支持浏览器后退与深链接。
- 图片预览与单文件下载；其他格式明确可下载/暂不支持预览，按后端能力呈现。
- 加载中、空目录、网络异常、错误访问码、过期/撤销与下载失败各自有恢复操作。
- 分享范围适配器接入既有服务；缓存/身份/路径不跨分享污染，不导入管理权限。
- 375px 手机、平板与桌面布局；浅/深色、键盘、文字放大与减少动态效果。
- 当前 Runtime 字段、连接状态组件与 URL 改动作为该主线的一部分审查，避免重复实现。

**文件边界**：ShareReceivePage、必要入口/布局、分享浏览与预览组件、api/shares、类型与定向测试。BrowsePage 的全功能工作台和管理页本周保留可访问，不在首批同步重写全部功能；后续逐步统一 WebUI 信息架构。

## 7. Q：通过使用任务验收

验收场景和判据见[产品方案 U1–U9](sharing-experience-rewrite-2026-09-09.md)。至少分别记录：
- 同网手机扫码，浏览目录、图片预览、下载并核对文件。
- 独立网络打开互联网链接，完成同样操作。
- 首次配置缺项、错误口令、撤销/失效、网络断开后的明确行为。
- 复制地址与二维码一致；服务端就绪不冒充跨设备可达。
- 分享期间桌面隐藏/恢复、下载取消/正常退出的资源归属与数据状态。

真实设备/网络证据不可用时写 NOT_RUN 或具体阻断；浏览器移动视口只验证布局，不替代扫码/跨网络实测。下载交给浏览器后无法观测保存完成，不伪造完成百分比。

技术门槛：
- Python 只在独立完整快照、RuntimeData 和端口中测试；每线独立，禁止主工作区 pytest。
- 权限/路径/分享 cookie、下载取消/ZIP 预算和相关生命周期合同按实际改动回归。
- 数据恢复若未被影响，保留历史验收与影响审查；涉及 session/DB/锁则补相应恢复组合。
- 前端类型、公共契约、组件、构建 dist 与候选源码一致；必要的浏览器真实路由检查不能全被 mock 替代。
- 新候选绑定当前未提交源码清单；旧包的 G3/W6 通过不覆盖新 UI。
