## 1. 当前事实与本轮问题

G1 v2 的四组输入对照完成：20 周期、40 次退出通过，首退/重启有 314/322 个状态采样点。它采用缩减负载，不能视为历史失败条件回放。QQ 的存在性不区分成败，行为及责任未知。

正式 W6 驱动的六项受控验收已通过，生产退出代码未因本轮探针修复而改变。历史 observed-08 中，重启退出超时但未记录 Qt Ctrl/Q、Shortcut 或 request_exit，Qt 后续仍处理窗口事件。另一次失败的原生前台与线程焦点都曾指向目标，超时现场窗口已最小化。这些记录尚不能解释输入在何处丢失，或谁触发了最小化。

本轮只回答三个问题：

1. 应用内观察器的存在、记录方式，是否改变故障表现或关键事件时序？
2. 失败时，输入到进程退出的链路最早在哪一层缺少可验证事件？
3. 最小化发生在输入、失焦和退出调用的哪个位置；是否有证据将它与故障联系起来？

## 4. 最小事件链与证据合同

G2 定义事件表，G3 实现采集。每条记录至少含 run_id、首退/重启相位、PID/TID、窗口标识、事件类型、序号、单调时间。跨进程时钟须先验证可比较性并记录误差范围；无法对齐时只能给出部分顺序，不能将两个独立时间戳硬拼成因果链。

| 层级 | 必须记录 | 判读边界 |
|---|---|---|
| 输入生成 | Ctrl/Q down/up 调用顺序、实际扫描码、发送前后状态、接口结果 | keybd_event 没有插入数量；不得伪造成功回执。SendInput 数量也不是 Qt 回执 |
| 原生窗口消息 | 目标进程 Ctrl/Q 的 WM_KEYDOWN/UP 等消息、目标 HWND；必要的激活/最小化/销毁相关消息 | 应用内过滤器看不到消息，不自动证明 OS 未生成；可能在更早层被处理 |
| Qt 输入 | Ctrl/Q KeyPress/Release、ShortcutOverride、Shortcut 序列及歧义标志 | 记录 Qt 实际 focusWindow/activeWindow；与原生焦点区别描述 |
| 退出调用 | request_exit、closeEvent、shutdown_resources 的进入/返回，force_quit 和 close 接受状态 | 方法未返回不自动等于死锁；需要后续进度或线程栈 |
| 应用终止 | lastWindowClosed、aboutToQuit、GUI 子进程和 onefile 父进程退出码/时间 | 分辨 GUI 已结束但 onefile 父进程仍未结束的情况 |
| 窗口状态 | 原生 IsWindow/IsIconic/IsZoomed/可见性，Qt 状态及状态事件 | 不可见不等于销毁；独立的前台 PID 不是最小化发起者 |

采集范围限测试窗口和相关事件。前台进程身份只作辅助关联，不采集其他应用内容或用户键入内容。首退与重启必须采用同等采集路径，并分别保存结果。

### 记录可靠性先验收

在合成测试中验证正常退出、主动超时、缓冲溢出、记录器异常、目标提前结束时都有明确结果。每个事件流写入启动/安装状态、序号、丢失数和结束状态；没有日志与零个事件不能混为一谈。

缓冲模式必须有容量上限和失败保全方案。控制器在判定 30 秒超时后，先请求导出已存事件，再清理本次 PID 树；导出机制不能只依赖可能卡住的 Qt 主线程。若仍无法导出，记为日志不完整，不据此认定事件没有发生。失败后的导出宽限不改变 30 秒退出验收结果。

## 5. 第一阶段：观察干扰对照

固定候选、完整负载、输入方式、外部采样和桌面运行规则，只改变下表条件：

| 组别 | 应用内观察条件 | 用途 |
|---|---|---|
| O0 | 无诊断插件 | 保留无应用内观察的行为参照；没有 Qt 记录是设计限制 |
| O1 | 相同的原生/Qt/方法观察点，事件先写入有界内存缓冲 | 获取事件链并减少同步磁盘写入 |
| O2 | 与 O1 相同的观察点、字段、过滤和导入时机，同步写盘 | 隔离记录出口方式带来的影响 |

O1/O2 从同一实现派生，模式选择只能改变记录出口。不得提前导入 MainWindow、替换原生产方法对象或改变信号连接。sys.monitoring 仅启用目标 code 的本地事件，不启用全局追踪。复用旧观察器时以完整归档与哈希为准，并保存新增 diff。

历史 observed-08 原样条件如需单独验证，另命名 H08；它缺少原生过滤器，不能与 O1/O2 当作“只有写盘方式不同”的对照。第一阶段不默认增加 H08 组。

**预登记矩阵：** 四个区组，每组各运行一次 O0/O1/O2：

| 区组 | 顺序 |
|---|---|
| 1 | O0 → O1 → O2 |
| 2 | O1 → O2 → O0 |
| 3 | O2 → O0 → O1 |
| 4 | O0 → O2 → O1 |

上限 12 周期、每周期含首退和重启退出，最多 24 次退出。顺序在执行前冻结；这是减轻顺序偏差的交错设计，不代表时间或环境已被完全控制。独占 GUI 窗口最多 90 分钟，任一轮出现目标失败即停止批次并转入失败分析；未运行格明确标记 NOT_RUN。

结果分组报告周期数、首退/重启失败数、输入无效数、日志完整性和耗时分布。小样本全部通过只可写“本批次未复现”；不能宣称观察器无影响、输入原因排除或故障率为零。

## 6. 第二阶段：失败现场如何转成区分实验

保全失败后由 G2/G3 共同填写下表，主代理选择一个能区分假设的后续实验，而不是同时增加多个补丁。

| 现场 | 优先检查 | 不可直接推导 |
|---|---|---|
| 只有外部发送记录，无原生/Qt 输入 | 观察器健康、目标线程/焦点、消息覆盖；有必要才增加定向 OS 跟踪 | 不能直接认定 Qt 或关闭逻辑有错 |
| 原生 Ctrl/Q 消息存在，Qt 输入缺失 | 输入转换、事件过滤、焦点映射与记录器遗漏 | 不能直接认定外部应用吞键 |
| Qt Key/ShortcutOverride 存在，Shortcut 缺失 | 修饰键状态、shortcut context、事件接受与歧义 | 不直接增加全局快捷键绕过 |
| Shortcut 存在，request_exit 缺失 | 对应 QAction、信号绑定与方法监测可靠性 | 不先加无条件 app.quit |
| 退出调用进入但未完成 | 最后完成的清理步骤、进度和仅目标进程的线程栈 | 不把窗口不可见当成进程已经结束 |
| GUI 子进程结束，onefile 父进程仍在 | 父进程退出/解包清理相关证据 | 不把父进程等待归责于 QAction |
| 最小化/失焦与输入相邻 | 对齐事件顺序；有证据才追踪触发来源 | 前台占据者不等于事件发起者 |

若只在 O0 失败而 O1/O2 未失败，先承认观察可能干扰，不要求日志证明 O0 中不存在的观察点。由 G3 减少观察点/改记录方式，派生一个更小的对照。

第二阶段最多追加 4 个完整周期；运行前写出待区分的两个假设、唯一改变量、预期结果和停止条件。若没有可区分的实验，不启动额外长跑。

若本轮没有修复、只有诊断结果，不为重申已有通过而机械重跑六项正式验收。
