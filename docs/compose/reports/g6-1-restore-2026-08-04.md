# G6-1 受控恢复 API 首切片 — 2026-08-04

## 结论

G6-1 已完成受控恢复 API 首切片。`LibraryExportService.restore_backup()` 只允许在目标 `LibrarySession` 已关闭后执行，获取按库 `QLockFile`，再次校验备份，解压到 RuntimeData 同级 staging 目录，执行数据库 `quick_check`，再原子替换目标数据目录。

被替换的旧 RuntimeData 不直接删除，而是移动到 `RuntimeData/_orphaned/restore-backups/`；恢复失败时会将新 staging/安装目录隔离，并尝试把旧目录恢复到原位置。

本切片不提供 Desktop 设置页、CLI 或 LAN 入口，也不自动清理旧数据。产品层仍需负责用户确认、进度、错误提示和隔离区管理。

## 安全边界

- 在线 session 直接拒绝恢复，避免活动连接、Runtime 适配器或窗口仍持有旧数据库。
- `overwrite_existing=False` 默认拒绝覆盖已有 RuntimeData；覆盖必须显式传入 `True`。
- 目标库根目录必须存在，备份 manifest 的库名必须匹配目标库名。
- 通过按库锁阻止其他进程同时打开目标库。
- 只从已验证 manifest 的 `data/` 成员提取，使用新建 staging 目录，不使用 `extractall()`。
- 安装前后都执行数据库 `quick_check`；失败时保留失败目录并回滚旧数据。
- 旧数据作为 `_orphaned/restore-backups` 保留，不做不可逆删除。
