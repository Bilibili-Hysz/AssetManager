# Batch C LAN WebUI Reliability - Final Report

## Scope

Task 5 is a legacy fallback stopgap, not a feature-parity effort. The approved WebUI design and plan define the primary WebUI direction; this delivery keeps the legacy pages safe and minimally usable while that boundary remains in place.

No Batch C-specific design or plan file was present in this worktree. The linked approved WebUI design and plan are the available source materials for the fallback boundary.

## Delivered Behavior

- Standardized the legacy image-viewer visibility contract as the shared `visible` class across `app.js`, `detail.js`, `share.js`, and `style.css` regression coverage.
- Fixed the legacy user-dropdown outside-click selector to match the markup's `.app-header__user` class. The previous `.header__user` selector never matched.
- Preserved and strengthened legacy static-root rejection of `.bak` and `.bak2` artifacts, including case-insensitive nested paths.
- Preserved local icon fallback and the no-mandatory-external-font/CDN policy.
- Added focused fallback tests before the production change; the focused suite was RED on the stale selector and GREEN after the fix.

## Architecture And Behavior

Legacy assets continue to be served through the existing `/static/{filename:.*}` handler. The handler resolves the requested target beneath the configured static root, rejects path escapes, rejects filenames ending in `.bak` or `.bak2` case-insensitively, and serves only regular files. The legacy viewer uses `image-viewer.visible` for open state and removes `visible` on close. No legacy fallback feature parity with the primary WebUI was added.

## Residual Risks

- The legacy fallback remains intentionally behind the primary WebUI in feature parity and receives only stopgap reliability fixes.
- Static backup filtering is suffix-based by design; other stale-but-non-backup files remain ordinary static assets if they are inside the root.
- Browser-specific interaction regressions still require a manual browser pass in an environment that can execute the LAN pages.

## Lessons

- Selector drift is easy to miss when markup and script changes are reviewed separately; a source-level assertion should bind the selector to the current component class.
- Fallback tests should cover every legacy page that shares a behavioral contract, not only the main app page.
- Delivery evidence must distinguish automated checks from manual browser and package-audit work that was not performed.
