## 2. 三端形态与入口链

```
桌面端 PySide6    LAN 端 aiohttp    Web 端 React SPA(webui/dist,由 LAN 托管)
     │                  │                    │
     └────── 同进程(单进程模型)──────┘        │
         SQLite 单连接 + 连接级写锁;跨进程靠文件锁 + CAS
```

- **桌面入口**:`main.py` / `run.py` → `AssetsManager.app.main()` → crash_handler → QApplication(HighDPI/主题/缩放)→ ApplicationBootstrap → 插件发现 → StartupWindow → `library_opened` → `MainWindow(bootstrap)` → `workspace.add_library(path)` → `library_service.open_session`(锁→身份→迁移 v1-v34→LibrarySession)→ `bootstrap.runtime_for(session)`(LibraryScopedServices + RuntimeEventRouter + reconciliation worker)→ 可选 LAN 自启。
- `run.py --package-smoke`:冻结态 QtSvg + icon 冒烟。
- **LAN 入口**:ShareManager 状态机 → LanServer(runtime= 强制)→ _LanServerImpl 后台 asyncio 线程 → 140 条路由。
- **Web 入口**:`/` LandingPage → GET /api/info 引导 → AuthContext。

**桌面外壳实测(域报告 1)**:
- app.py 210 行(window 域唯一构造点是 app.py:99);window.py **1246 行**(文档称 717,1.74 倍);window_lifecycle_coordinator.py 328 行(文档称 134,2.45 倍)。

## 4. LAN 核心层(域报告 3,16 文件约 6,180 行全读)

**文件清单**:__init__.py(329,LanServer 外观门面)、server.py(**1678**,_LanServerImpl)、manager.py(557,ShareManager 状态机)、api.py(463,唯一路由注册口)、auth.py(31)、principal.py(137,6 身份→8 能力)、dto.py(306)、utils.py(168)、path_guard.py(129)、security.py(332)、scanner.py(146)、tunnel.py(346)、ws.py(794)、safe_open.py(98)、token_revocations.py(169)、tunnel_identity.py(106)。

**请求全链**(声明式策略 + 三层中间件):
`security_mw`(安全:IP 黑白名单→限流;security.py:176)→ `_metrics_middleware`(server.py:337)→ `_auth_middleware`(principal 解析+token 撤销检查+能力门;server.py:1543)→ `enforce_capabilities`(authorization.py:57)→ handler。**未知路由/未匹配策略 → required+general = fail-closed**(route_policy.py:99-109)。

- **限流=滑窗**(security.py:62-117,每 IP 时间戳列表截头,非桶计数;`pop(0)` 热路径 O(n²));三档:auth_strict 10/300s、browse 600/60s、general 100~1000(视入口);显式无锁,契约=仅事件循环线程访问。
- **令牌**:password/user/share/local_ui 均为 `ts.nonce.sig` HMAC-SHA256[:32];user token 验证回查 DB;share token 1h;接受无 nonce 旧格式(兼容面)。撤销:TokenRevocationRegistry(24h TTL、10k 上限、内存正缓存+DB 权威、**DB 异常即拒 token** fail-closed)。
- **路径防护四层**:reject_path_text(C0/ADS)→ PathGuard.resolve(is_relative_to)→ assert_under_root(TOCTOU 复查)→ 句柄级 open_under_root(file_snapshot.py:128-176:逐目录拒 symlink/junction/mount、POSIX dir_fd+O_NOFOLLOW、fstat 复验、读后 identity 复验)。
- **WS**(ws.py:794):50 连接上限/30s 心跳(ping+pong 10s 驱逐)/1MB 广播帧二分裁剪到 95% 预算/authority lock 发送(head-of-line 取舍)/revoke_authority 驱逐。
- **隧道**(tunnel.py:346):Popen `cloudflared tunnel --url …` + stderr 正则提取 URL + 意外退出回调;访客 cookie(tunnel_identity.py):`am_quota_id` v1.<32hex>.<HMAC> 30 天,httponly+Lax+Secure=request.secure;隧道下按 cookie 隔离限流桶,拒绝响应不发 cookie(防身份农场)。

**路由实测**:api.py `_add(` 140 条 = GET 85 / POST 38 / PUT 6 / PATCH 2 / DELETE 9(123 个唯一 pattern);分类:**页面(SPA)30、Commerce 54、认证 14、核心库 42**。另 `/assets` 静态 public+skip;on_startup 注册事件→WS 广播桥。

**脆弱点(代理亲眼验证,按严重度)**:
1. **🔴 08-P0 实锤未修**:tunnel.py:25 下载用 `releases/latest/download/...` **无版本 pin**;`_validate_cloudflared_binary`(:58-70)仅"非空+--version 退出码 0"**无 SHA-256**;PATH/打包内置 binary 完全跳过校验;`ensure_available` 自动下载→:201 直接 Popen。即"下载即执行链无强校验"仍然成立(此前 dated evidence 系列没有任何一份覆盖此点)。

3. 撤销 miss 每请求 DB 往返,DB 抖动→全量误拒(fail-closed 可用性代价,注释已承认)。
4. WS 无 token 的 local_ui 上下文 `lambda: capabilities.realtime` 常真(websocket.py:112)+中间件 revocation_supported 兼容分支(server.py:1561-1565)。
5. 隧道匿名共享 loopback 桶:无 cookie 访客共享 1000/60s,NAT/隧道混用预算互扰。

**并发语义(设计严谨,值得学习)**:
- 双时钟策略:内存一律 monotonic,持久化一律 wallclock,落盘用 `now_wall + max(0, deadline_mono−now_mono)` 换算剩余时长——**墙钟回拨时安全方向截断**(任务立即 due);前跳则提前到期。
- CAS 层叠:领取(state/attempts/next_due)→ 续租/完成/重试(state+attempts+token+lease 未过期)→ 整快照 replace 用 generation CAS;恢复不占 attempts;索引侧根 revision CAS(整树只 CAS 一次)。
- 跨进程:无 OS 文件锁,靠每连接进程内 db_write_lock + SQLite `BEGIN IMMEDIATE` + generation + 0.5s poll;拒绝世代回退。
- 崩溃恢复:任务保持 RUNNING+墙钟租约;开库时 load→恢复→replace(expected_generation);旧 worker 的心跳/完成 CAS 必败→`_stale_completion_noop`。

**与 G17 边界的关系**:README 的"单库单 owner stop-the-world,cross-process marker locking 属 later phase"(migration:99-100)与代码一致;**但 SQLite 队列层实际已支持同版本多进程共享单 library**,真正受限的是 JSON 路径与新旧版本并存。

**脆弱点(代理证据)**:
1. 迁移读失败静默降级(migration:116-134 把不可读 marker 当空集)→ 未处理任务被改名归档,从队列消失且无告警。
2. recovery 先无条件把 task_id 加入 recovered 再 UPDATE 且不查 rowcount(store:1002-1027)→ 双进程竞态下 generation 空增。
3. committed 语义依赖 `conn.in_transaction`:外层事务下结果被标 staged → mark_retryable 重扫,长期持有事务的调用方会重复消费 attempts 直至 TERMINAL。
4. SKIPPED 快路径依赖目录 mtime 浮点相等(方向安全:只会退化为重扫)。
5. 心跳线程与扫描共用同一连接/写锁:长提交期间续租阻塞,可能自毁租约(操作龄 300s+租约窗缓解)。
6. sweeper 吞掉全部异常(294-297,无日志);`stop()` 超时抛错但 daemon 线程仍跑,继续关会话有 use-after-close 风险。
7. 仓库 `_advance_revision` 无 expected 的"无条件递增"(275-292)与 CAS 递增并存,存在绕过 CAS 的可能(仅调用方约定)。
8. 服务层 busy 重试包住 store 自身重试,延迟乘叠;`wait_for_ready` 用 time.monotonic 而 due 判定用注入时钟,假时钟测试下语义分裂。
