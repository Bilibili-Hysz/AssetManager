# Filelist 产品与交互建议

> **范围**：`AssetsManager/panels/file_list/` 及其关联的 controller、模型、文件操作和测试
> **重点**：类文件管理器交互、右键菜单、快捷键、批量操作与资产浏览体验
> **状态**：产品与交互建议，不代表已经确定的产品路线

## 1. 当前判断

Filelist 已经具备比较完整的文件管理器基础：

- Grid 和 Details 双视图
- 异步目录扫描与缩略图加载
- 后退、前进、上级目录和面包屑
- 名称、日期、大小、类型排序
- 当前目录搜索与类型筛选
- 多选、框选、Shift 连选、Ctrl 多选
- 重命名、批量重命名、复制、剪切、粘贴、复制副本
- 回收站删除、永久删除、撤销和重做
- 外部拖入、内部移动、外部拖出
- 标签操作、属性查看、外部工具和插件菜单

因此，当前的主要问题不是功能数量不足，而是功能需要进一步形成统一、可预测、可学习的操作体验。

核心目标应当是：

> 让用户可以快速浏览、判断、筛选、批量处理和安全整理大量资产。

## 2. 主要体验问题

### 2.1 异步操作反馈不统一

复制、移动、删除、拖放、批量重命名等操作的执行方式和反馈方式不完全一致。用户可能无法立即判断：

- 操作是否已经开始
- 当前是否仍在执行
- 已完成多少
- 是否出现部分失败
- 是否可以取消
- 是否可以撤销

建议建立统一的文件操作反馈区域，而不是只依赖 Toast 或最终刷新。

推荐的反馈形式：

```text
正在复制 126 个项目
已完成 48 / 126
[查看详情] [取消]
```

完成后：

```text
已复制 126 个项目
[撤销]
```

失败时：

```text
操作完成，但有 3 个项目失败
[查看失败项]
```

### 2.2 Grid 与 Details 的命令语义需要统一

目前 Grid 和 Details 有各自的菜单及选择处理路径。建议让两个视图共享同一套命令定义：

- 视图只负责提供选择和上下文
- 命令层负责判断可用性
- 菜单、快捷键、工具栏和拖放都调用同一个命令

这样可以避免切换视图后出现功能不一致。

### 2.3 打开、系统打开和显示位置需要区分

建议明确区分以下命令：

- **打开**：在 AssetManager 内部打开目录或预览文件
- **打开方式**：选择默认程序或外部工具
- **在资源管理器中显示**：打开系统文件管理器并定位文件

不要让“打开”在不同入口下产生不同结果。

### 2.4 拖放行为需要更明确

建议让拖放规则显式化：

- 外部拖入默认复制
- 库内拖动默认移动
- 按住 `Ctrl` 拖动切换为复制
- 拖动时显示当前目标目录
- 拖动到文件上时明确是否进入该文件夹
- 松开前显示复制或移动提示
- 大批量拖放进入统一后台任务

当前库内移动、外部复制的规则可以保留，但应通过拖放提示告诉用户，而不是让用户事后猜测。

### 2.5 批量重命名需要预览

当前批量重命名规则已经存在，但建议增加预览和冲突检查：

| 原名称 | 新名称 | 状态 |
|---|---|---|
| hero.png | hero_001.png | 正常 |
| idle.png | idle_002.png | 正常 |
| run.png | run_003.png | 正常 |

建议支持：

- 起始编号
- 编号位数
- 保留扩展名
- 按当前排序编号
- 冲突检测
- 非法字符检测
- 对冲突项跳过或自动改名

## 3. 右键菜单重设计建议

你的想法是可行的，而且很适合这个项目：

> 右键菜单不只是功能入口，也可以是快捷键的渐进式学习入口。

但需要避免菜单变成“快捷键说明书”或信息过载。建议采用 **命令统一 + 分组显示 + 低干扰快捷键提示 + 逐步引导** 的方式。

### 3.1 右键菜单中的快捷键显示原则

建议只有真正稳定、常用、值得记忆的命令显示快捷键：

| 菜单命令 | 快捷键 | 建议显示 |
|---|---|---|
| 打开 | `Enter` | 显示 |
| 返回上级 | `Backspace` | 显示 |
| 复制 | `Ctrl+C` | 显示 |
| 剪切 | `Ctrl+X` | 显示 |
| 粘贴 | `Ctrl+V` | 显示 |
| 重命名 | `F2` | 显示 |
| 删除 | `Delete` | 显示 |
| 永久删除 | `Shift+Delete` | 显示 |
| 复制副本 | `Ctrl+D` | 显示 |
| 撤销 | `Ctrl+Z` | 显示 |
| 重做 | `Ctrl+Y` | 显示 |
| 全选 | `Ctrl+A` | 空白区域显示 |
| 新建文件夹 | `Ctrl+Shift+N` | 空白区域显示 |
| 刷新 | `F5` | 可显示 |
| 搜索 | `Ctrl+F` | 搜索框或菜单显示 |
| 显示隐藏文件 | `Ctrl+H` | 可显示 |
| 属性 | `Alt+Enter` | 显示 |

不建议给以下功能强行分配快捷键：

- 添加标签
- 移除标签
- 管理标签
- 快速分享
- 打开方式
- 插件命令
- 设置文件夹封面

这些功能可以通过菜单发现，但不一定值得占用用户的记忆空间。

### 3.2 选中项目时的菜单结构

建议单选和多选尽量使用同一结构，仅根据选择数量启用或禁用命令。

```text
打开                                      Enter
打开方式                                  >

------------------------------
复制                                      Ctrl+C
剪切                                      Ctrl+X
复制路径

------------------------------
重命名                                    F2
复制副本                                  Ctrl+D
删除                                      Delete
永久删除                                  Shift+Delete

------------------------------
撤销                                      Ctrl+Z
重做                                      Ctrl+Y

------------------------------
标签                                      >
  添加标签
  移除标签
  管理标签

快速分享
属性                                      Alt+Enter
在资源管理器中显示
插件                                      >
```

### 3.3 空白区域的菜单结构

空白区域右键不应只有“粘贴”和“新建文件夹”，还应该成为用户学习全选、刷新、撤销等操作的入口。

```text
粘贴                                      Ctrl+V
新建文件夹                                Ctrl+Shift+N

------------------------------
全选                                      Ctrl+A
刷新                                      F5
显示隐藏文件                              Ctrl+H

------------------------------
撤销                                      Ctrl+Z
重做                                      Ctrl+Y

排序                                      >
视图                                      >
```

### 3.4 菜单中的命令状态

不能只通过隐藏菜单项表达不可用状态。建议尽可能保留命令并置灰：

- 没有剪贴板内容时，`粘贴`置灰
- 没有选中项目时，复制、剪切、重命名、删除置灰
- 没有可撤销操作时，撤销置灰
- 没有可重做操作时，重做置灰
- 多选时，单项目属性可以改为“属性（多个）”
- 当前目录为库根目录时，“返回上级”置灰

这样用户可以通过菜单理解系统能力，而不是因为项目消失而不知道功能存在。

### 3.5 快捷键学习应该渐进，而不是强迫

推荐分三步：

1. 第一次使用某个菜单命令时，在菜单右侧显示快捷键
2. 用户重复使用后仍然保留快捷键，但不弹出打扰性提示
3. 在帮助菜单或快捷键面板中提供完整清单

不建议每次用户点击“复制”都弹出：

```text
提示：你也可以使用 Ctrl+C
```

这会打断操作流。

可以在命令首次成功执行后，在 Toast 中提供低干扰提示：

```text
已复制 3 个项目
快捷键：Ctrl+C
```

也可以只对高价值操作提示一次，例如：

- 重命名：`F2`
- 搜索：`Ctrl+F`
- 撤销：`Ctrl+Z`
- 批量选择：`Ctrl+A`

### 3.6 右键菜单应该成为命令系统的一个视图

建议未来不要在 `_show_context_menu()` 和 `_ctx_menu()` 中分别手写行为，而是建立统一命令描述：

```python
Command(
    id="rename",
    label_key="filelist.menu.rename",
    shortcut="F2",
    group="file_operations",
    enabled_when=has_single_selection,
    execute=rename_selected,
)
```

菜单、快捷键、工具栏和帮助面板都由同一批命令生成。

产品收益是：

- 右键菜单和快捷键不会逐渐漂移
- Grid 和 Details 自动保持一致
- 快捷键帮助可以自动生成
- 命令是否可用有统一规则
- 后续支持自定义快捷键更容易

这属于交互一致性建设，不是为了增加架构层次。

## 4. 标签交互建议

当前通过文本输入框添加和移除标签，对于资产管理场景还不够高效。

建议右键进入轻量标签面板：

```text
当前标签
[character] [hero] [blue]

添加标签
[搜索或输入标签...]

最近使用
[environment] [texture] [model]
```

多选时可以显示：

- 所有选中项目共有的标签
- 只有部分项目拥有的标签
- 添加标签和移除标签的批量结果

这是 Filelist 从普通文件管理器向资产管理器转变的关键体验。

## 5. 状态与空状态建议

建议区分以下状态，不要全部显示为“文件夹为空”：

### 真正空目录

```text
此文件夹为空
[新建文件夹] [从外部导入]
```

### 搜索无结果

```text
没有匹配“hero”的项目
[清除搜索] [清除类型筛选]
```

### 正在扫描

```text
正在读取文件夹...
已发现 128 项
```

### 权限失败

```text
无法读取此文件夹
[重试] [在资源管理器中打开]
```

异步扫描和文件系统监听基础已经存在，建议把这些状态显式呈现给用户。

## 6. 推荐执行顺序

### 第一阶段：命令和反馈收口

1. 统一 Grid 与 Details 的右键菜单
2. 为常用菜单项显示快捷键
3. 统一打开、外部打开和显示位置的语义
4. 空白区域增加全选、刷新、撤销、重做
5. 不可用命令保留并置灰
6. 统一复制、移动、删除、拖放的进度和结果反馈
7. 删除、永久删除和撤销文案统一
8. 操作完成后自动恢复合理的选择和焦点

### 第二阶段：增强资产整理效率

1. 批量重命名预览
2. 标签搜索、多选和自动完成
3. 文件夹封面
4. 属性面板增加缩略图和资产元数据
5. 空目录、搜索无结果、扫描中、权限失败分别展示
6. 详情视图支持可选列

### 第三阶段：形成可学习的专业工作流

1. 从统一命令自动生成快捷键帮助
2. 支持快捷键自定义
3. 当前目录过滤与全库搜索明确区分
4. 支持组合筛选和保存筛选条件
5. 增加批量任务中心和失败任务详情

## 7. 结论

重新设计右键菜单是值得做的，而且不应只把它当作视觉调整。

最合适的方向是：

> **右键菜单负责发现能力，快捷键负责加速能力；两者共享同一套命令定义。**

用户第一次通过右键菜单完成操作，之后逐渐看到并记住右侧快捷键。熟练用户使用快捷键，不熟练用户继续使用菜单，两者不互相冲突。

当前最优先的不是继续增加更多菜单项，而是：

- 减少重复菜单实现
- 统一 Grid 和 Details 行为
- 统一命令名称和状态
- 让快捷键显示稳定且可信
- 为长时间操作提供过程反馈

如果只选择一个 Filelist 交互改造主题，建议选择：

> **统一命令系统驱动的右键菜单 + 快捷键提示 + 操作反馈。**
