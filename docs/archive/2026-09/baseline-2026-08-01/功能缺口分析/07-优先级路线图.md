## 实施顺序建议（三个迭代）

### 迭代 1（数据安全基线，1-2 周）
G6-1（导出、备份校验、受控恢复首切片已交付，继续产品入口与 quarantine 生命周期）→ G6-3 → G6-4（启动清理与 Windows 安全补强已完成，继续阶段验收）→ G6-5 → G2-11 → G3-9；A1 URL 剥离已另行完成，B2 ThumbnailLoader 服务化需先完成服务设计

**验收**：任意库可通过 service 导出 JSON、验证备份并在关闭 session 后受控恢复；双开被拒绝；产品入口、quarantine 生命周期和崩溃演练另有独立发布门禁。

### 迭代 2（价值兑现，2-4 周）
G4-1 上传（或下线能力）→ G4-2 rename/delete → G2-1 标签颜色 → G1-1 批量标签 → G1-3 查看器增强 → G1-4 文件收藏 → G5-7 错误处理

**验收**：Web 端可上传/改文件/打标签；桌面端可批量整理与收藏；标签树可视化。

### 迭代 3（体验完善，持续）
G1-2 视频缩略图 → G3-1 索引重建 → G4-3 审计持久化 → G4-5 认证 → G3-2 全文检索 → P2 其余按 ROI

**验收**：大库（≥5 万文件）全功能可用且搜索秒回；团队协作（上传/审计/密码重置）闭环。

## 关键原则

1. **先安全后功能**：所有 P0 不依赖新功能审批，直接做
2. **能力声明闭环**：任何出现在权限模型/README 的能力（如 upload）要么实现要么移除，不允许死代码
3. **复用既有层**：新功能一律走 Application Service + Repository + 领域事件，禁止在 UI 层直接写 SQL
4. **每个缺口自带测试**：参照现有 1590 项测试的组织方式（unit/integration/lan/desktop）
