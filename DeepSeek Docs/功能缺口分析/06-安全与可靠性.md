# 06 · 安全与可靠性缺口

覆盖：跨层（数据持久化、进程模型、安全基线）

## G6-1 库数据无备份/导出机制（最重要缺口）[P0][L]

- **现状**：全部用户数据（标签/备注/URL/分享/用户/索引/缩略图）存在于 `RuntimeData/{库名}_{hash}/`（path_resolver.py）；**无任何备份/导出功能**；`clean_orphan_dirs`（database.py:300-311）还会在 7 天后自动删除"不认识的"数据目录——库目录被移动/盘符变更后，原数据目录若不再被识别即有被删风险
- **用户影响**：数年整理的标签/备注随一次误删或迁移全部丢失；无迁移到其他机器/工具的能力
- **实现路径**（按价值排序）：
  1. **导出**：`Tags/Notes/URLs` → JSON（+可选 CSV），按文件路径组织，全部从 file_tags/file_meta 读（S-M，无新表）
  2. **备份**：库数据目录 zip（排除 .thumbnails 可选）+ 时间戳命名 + 设置页"备份/恢复"区（M）
  3. **防误删**：`clean_orphan_dirs` 改为移动到 `RuntimeData/_orphaned/` 而非直接删除（S，低成本高价值）

## G6-2 本地数据库无加密 [P1][L]

- **现状**：`assetmanager.db` 明文存储（标签/备注/URL 可能含敏感信息）；分享密码是 PBKDF2 哈希（domain/auth.py:44-50）但库本体无加密；RuntimeData 目录也无权限保护
- **影响**：笔记本失窃/共享磁盘场景数据裸奔
- **实现路径**：SQLite `PRAGMA key`（sqlcipher 换驱动，重）或文件级加密（库数据目录用 CryptProtectData/DPAPI 密钥派生 XOR 加密 db——侵入大）；务实方案：设置页提示 + 支持"导出加密备份"（AES-GCM + 用户口令，M）

## G6-3 无单实例锁 [P0][S]（已完成本阶段）

- **当前实现**：`AssetsManager/core/library_lock.py` 使用 Qt `QLockFile`，按规范化库根路径生成稳定散列锁名，锁文件位于 `RuntimeData/Shared/library-<hash>.lock`；不使用全局 `instance.lock`，因此不同库仍可并行打开。
- **生命周期**：锁属于 canonical library session；初始化任一步失败时回滚并释放；session/runtime/数据库全部成功关闭后释放；关闭监听器或数据库关闭失败时保留锁，等待重试。多个同进程服务对象共享底层 QLockFile，避免破坏现有服务隔离测试；跨进程同库打开被拒绝。
- **验收**：覆盖同进程锁共享、跨进程拒绝、不同库并行、初始化失败释放、关闭失败保锁、stale session 不误释放 replacement 锁；路径解析、LibraryService、Bootstrap、Runtime 和窗口生命周期回归通过。
- **剩余边界**：锁只约束同库跨进程打开，不替代数据库 `quick_check`、导出/恢复、防误删和 LAN 端口/分享安全提示。

## G6-4 撤销备份残留不清理（已部分缓解）[P0][S]

- **现状**：`UndoService._undo_dir = tempfile.mkdtemp(prefix="AssetsManager_undo_")`（undo_service.py）；正常退出由 `cleanup()` 删除，异常退出仍可能残留。
- **已实现子项**：首次创建 `UndoService` 时，仅扫描系统临时目录的直接子目录，精确匹配 `AssetsManager_undo_*`；默认只处理超过 7 天的目录，识别当前进程登记目录和带 PID 的活跃进程目录，并且单次最多处理 256 项。PID 标记使用 Undo 目录旁的 sidecar，另兼容早期放在目录内的标记。
- **剩余风险**：这是受限的残留缓解，不等于数据安全阶段闭环；数据库自检、导出/恢复和防误删策略仍未完成。历史验证曾在本机系统 Temp 观察到约 50,000 个旧目录，本轮未扩大清理范围。

## G6-5 崩溃后数据自检缺失 [P0][M]

- **现状**：`crash_handler`（crash_handler.py:59）只记日志；无启动自检：① `PRAGMA quick_check` ② `prune_missing`（project_data.py:172-184 存在但无调用者）清孤儿元数据 ③ thumbnail_cache 孤儿对照 ④ 半完成操作（移动中断）无恢复
- **实现路径**：启动后台维护任务（快速检查 + 孤儿清理 + undo 残留清理），结果写入日志 + 设置页"上次检查"显示（M，与 G3-10 合并）

## G6-6 默认开放风险（访客可浏览）[P0][S]

- **现状**：无认证配置时中间件直接放行 guest（server.py:980-982）；guest 默认可浏览+预览（principal.py:53-57）；隧道开启即公网可达；`/api/info` 公开暴露库名/统计
- **实现路径**：① 首次开启分享/隧道弹安全确认（要求设置密码或确认"局域网可信"）② 隧道启动强制要求认证已配置（S-M）

## G6-7 无更新机制 [P2][L]

- **现状**：桌面端无"检查更新"（GitHub Releases 可作源）；无自动更新；PyInstaller 打包升级需手动替换
- **实现路径**：检查更新（读 GitHub API 最新版本号 + 下载 zip 解压替换，需签名校验）（L）

## G6-8 遥测数据无查看/导出 [P2][S]

- **现状**：`PerformanceRecorder` 默认关闭（app.py:36-38，设置 `performance_telemetry_enabled` 但设置 UI 无此项）；即使开启也无查看入口
- **实现路径**：设置页"性能遥测"开关 + 事件表查看/导出（S）

## G6-9 插件沙箱缺失 [P2][XL]

- **现状**：README 明示插件有完整 Python 权限、`permissions` 不强制
- **实现路径**：真沙箱成本极高（子进程+IPC）；务实方案：① 插件列表显示权限声明 ② 安装来源警告（G2-10 zip 安装时提示）③ 可选"隔离模式"：插件在子进程运行（HostContext 走 IPC，XL）——建议文档化风险即可

## G6-10 无审计/合规痕迹 [P2][M]

- **现状**：LAN 活动日志内存化（G4-3）；桌面端无任何操作日志（谁在何时改了什么标签无记录）
- **实现路径**：与 G4-3 合并：统一 `audit_log` 表（桌面写 + LAN 写），设置页查看（M）
