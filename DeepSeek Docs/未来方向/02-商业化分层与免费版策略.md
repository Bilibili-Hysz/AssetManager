# 02 · 商业化分层与免费版策略

> **状态：🔵 已确认思路，暂不开发（与 01-个人数字资产店铺 同批确认）**
> 本文记录产品商业化分层模型（免费版/店铺版），是 01 文档的**产品层补充**（01 讲"店铺功能怎么做"，本文讲"产品怎么分版、怎么卖"）。

## 一、三个核心结论（2026-07 决策记录）

1. **"可信第三方支付"模式可行，但个人主体无法直连支付宝/微信 API**（需营业执照/商户号）——软件设计为"支付提供者抽象，运营者自配支付方式"即可绕过此限制
2. **freemium 分层思路正确**（免费版本地管理 + 付费店铺版），但**不是"砍 WebUI"，而是"功能分层"**——WebUI 是免费版核心资产，店铺版在 WebUI 上做加法
3. **WebUI 必须保留在免费发行版中**：技术（双端共享层是架构核心）、产品（LAN 分享是免费版差异化）、商业（店铺版长在 WebUI 上）

## 二、商业化分层模型

```
同一代码库，Edition 开关控制（feature flag，非代码分叉）
免费版 Edition=personal       店铺版 Edition=shop
├── 桌面资产管理（全部现有）     ├── + 上架（商品化数据模型 shop_items）
├── LAN 分享（全部现有能力）     ├── + 店面/商品页（WebUI 增量扩展）
├── WebUI 浏览/下载/分享链接    ├── + PaymentProvider（见下）
└──                            └── + 订单/发货/统计/审计
```

**原则**：
- 免费版保留现有全部能力（浏览/下载/限次限时分享），不做任何功能阉割——免费版就是今天的完整产品
- 店铺版 = 免费版 + 商业化服务层；激活通过许可证/激活码启用，不维护两个代码库
- 架构可行性：LanScopedServices 已按端装配，edition 只是服务暴露面的配置

## 三、支付方案（PaymentProvider 抽象）

**关键认知：支付账号属于运营者自己，不属于软件开发者**——软件只需让运营者配置自己的收款方式。

| 模式 | 门槛 | 自动发货 | 适用 |
|---|---|---|---|
| `QrCodeMode` 收款码 + 订单号备注 | 零（个人码即可） | ❌ 手动/半自动 | 起步期、无执照个人 |
| `MerchantApi` 支付宝/微信商户 API | 需营业执照（个体户即可注册） | ✅ | 有执照运营者 |
| `ExternalLink` 跳转 Gumroad/爱发电 | 零 | 平台负责 | 海外买家/最省事 |

**政策风险提醒**（写入文档的警告）：个人收款码用于经营性收入违反支付机构规则，有冻结风险——`QrCodeMode` 应标注"建议用于小额低频，长期经营请办个体工商户开通商户 API"。

## 四、变现方式（按推荐排序）

| 方式 | 定价参考 | 利弊 |
|---|---|---|
| 一次性买断 | ¥199-299 | 最简单，个人软件惯例，推荐起步 |
| 订阅 | ¥29/月 | 持续收入但个人软件续费率差 |
| 收入分成（成交抽成） | 2-5% | 最性感但运营者反感 + 需交易追踪，不推荐起步 |

## 五、产品风险记录

1. **版权牵连**：运营者售卖侵权素材——软件分发者责任小于平台，许可协议中声明免责即可
2. **盗版**：店铺版全本地运行易被破解 → 订单确认走"可选联网校验"，或接受盗版作为推广代价
3. **个人码风控**：见支付方案警告
4. **免费版与店铺版的边界**：必须清晰且对用户诚实——免费版不能是"残废版"，店铺版价值必须是"卖货"，否则用户反感
