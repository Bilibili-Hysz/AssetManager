# 03 · 应用服务层

应用层按职责分四组。每个库仍只有一个 `LibraryRuntime` 与一个 frozen `LibraryScopedServices` snapshot：Metadata/Tag/Thumbnail/FileOperation/Undo/Plugin/AssetIndex/DatabaseIntegrity/LibraryExport 为 Desktop/shared eager 字段；`AuthService` / `ShareService` 与 `token_secret` 组成 Runtime-owned `RuntimeSharingServices` eager 字段；Asset/Project/Search 位于 snapshot 内的 `LanRuntimeServices`，只在 LAN 组合时 single-flight materialize。LAN 与 Desktop 复用同一认证/分享服务实例。

## A. 库与文件操作组

### 1. `LibraryService`（library_service.py）
见 [02-入口与启动链路.md §5](02-入口与启动链路.md)。开库/关库/会话生命周期唯一入口。

### 2. `FileOperationService`（file_operation_service.py）—— 文件操作总闸

**数据流特征**：所有操作 = 文件系统变更 + 索引刷新 + 元数据迁移 + 领域事件发布。

| 方法 | 功能 | 事件 |
|---|---|---|
| `create_folder` (:82) | 新建目录（自动去重 "New Folder_1"…） | FileCreated, FileSystemChanged |
| `rename` (:102) | 目录内改名（委托 move） | — |
| `move` (:112) | 移动/改名；`_migrate_metadata` 迁移标签/元数据/缩略图；刷新索引 | FileRenamed, FileSystemChanged |
| `copy_to_directory` (:139) | 批量复制（文件/目录树） | FileCopied, FileSystemChanged |
| `move_to_directory` (:176) | 批量移动 | FileRenamed, FileSystemChanged |
| `duplicate` (:208) | 复制重命名 `name_copy.ext` | FileCreated, FileSystemChanged |
| `delete_permanent` (:228) | 永久删除；`_clear_deleted_projection` 清理标签/元数据/缩略图文件/索引 | FileDeleted, FileSystemChanged |
| `delete_to_trash` (:280) | send2trash 回收站 | 同上 |
| `restore_backup` (:255) | 撤销恢复备份 | FileCreated, FileSystemChanged |

安全机制：
- `_assert_under_root`（:22-24）：所有路径必须 resolve 后位于库根内
- `unique_destination`（:360-386）：`os.open(O_CREAT|O_EXCL)` 原子保留名字，防 TOCTOU 竞态
- `session_operation` 保证操作期间 session 存活

索引一致性：移动/删除后调用 `_refresh_parents` / `_refresh_after_move` / `_refresh_directory_tree` 同步 `assets` 索引表；删除时 `_clear_deleted_projection`（:299-323）在 `db_write_lock` 内级联删除 tag/meta，并物理删除对应 `.webp` 缩略图。

遥测：`_measure_command` 装饰器（:26-59）记录 `file.command` 性能事件；`suppress_command_telemetry` 用于撤销/重做场景防止重复计数。

### 3. `UndoService`（undo_service.py）—— 按库隔离的撤销/重做

- 栈按 `library_root` 隔离（:37-45）；深度默认 20
- **删除可撤销靠备份**：`prepare_delete` 把文件/目录复制到临时目录（`AssetsManager_undo_*`）→ 删除成功后 `commit_delete` 入栈；失败则 `discard_delete` 清理备份
- `perform_undo`（:208-235）：先在栈顶执行反向操作（rename→move 回来；delete→`restore_backup`），**成功后才出栈**（乐观锁校验栈顶未变）
- `cleanup()`（:323）：关库时删除整个备份目录

## B. 浏览/检索组

### 4. `AssetService`（asset_service.py）—— 纯文件系统浏览

- `list_directory(root, target, options)`（:85-134）：
  `os.scandir` → 过滤（隐藏文件/排除模式/分类/搜索/深度）→ 目录摘要（`_scan_dir_summary` 一次扫描同时取首图+文件数，走 DirectoryCache）→ 排序（`sort_key_for_entry`：目录永远在前）→ 汇总（总数/总大小/格式化）
- `validate_directory_summary_paths` / `validate_directory_summary_parent`（:138-162）：在缓存读取或扫描前校验 1–48 条、路径类型/唯一性和父目录存在性；失败抛出 `ValidationError`
- `summarize_directories(directories, parent=None)`（:164-195）：再次执行服务层校验，并要求目标均为 `parent` 的现有直子目录；保留旧的位置参数和 `directories=` 关键字调用，从首个目录推断缺省 `parent`，避免破坏插件/外部调用
- `_entry_to_item`（:197-261）：目录带 `is_project` 标记（按 project_depth 判定）
- 目录摘要缓存语义（`_scan_dir_summary` :308-367）：mtime 不一致即失效重扫；批量写入缓存

### 5. `SearchService`（search_service.py）—— 三种检索路径

| 方法 | 数据源 | 用途 |
|---|---|---|
| `search_by_tags` (:40) | `file_tags` 表（LOWER 大小写不敏感） | 标签检索 |
| `search_by_name` (:74) | 内存索引 `DirectoryScanner`（LAN 服务器后台全库扫描） | 快速文件名搜索 |
| `search_by_name_indexed` (:118) | `assets` 索引表（SQL LIKE/子串） | 索引兜底 |

LAN 搜索策略（metadata.py handle_search）：标签优先 → 内存索引 → 索引表兜底。所有路径带性能遥测与失败降级（返回空列表而非 500）。

### 6. `ProjectService`（project_service.py）—— 项目视图

"项目"= 目录树中达到深度阈值的目录（默认 `ProjectDepthConfig.global_depth=2`，可按一级分支覆盖，来自设置 `sidebar_depth_cfg`）。

- `list_projects` (:84)：候选目录 → 批量预热 file_count 缓存（`_batch_warm_file_counts` 避免 N+1）→ 组装条目（首图缩略图 URL / 标签 / 目录大小 / 文件数 / 备注）→ 排序（项目排前）→ 分页
- `get_home` (:223)：递归收集项目 → 附加缓存缩略图（DirectoryCache 命中 → `_attach_baked_thumbnails` 用 thumbnail_cache 表做二级匹配）→ 最近 20 个 / 预览墙 / 热门标签(前20) / 统计
- `build_tree` (:356)：目录树（按深度配置裁剪为叶子）
- `get_project_detail` (:301)：文件清单+图片清单+标签+备注+URL+下载 URL
- 所有 DB 查询带 try/except 降级（日志 debug），**不因缓存失败而中断浏览**——健壮性设计

### 7. `AssetIndexService`（asset_index_service.py）—— assets 表维护

- `index_directory` (:15)：单目录扫描 upsert；非 force 且有存量则跳过
- `index_directory_tree` (:58)：`os.walk` 强制全树索引
- 查询：`query_by_parent` / `query_by_extension` / `search_by_name`
- 删除：`remove_entry` / `remove_directory`（文件操作后一致性维护）
- 注意：索引是**懒填充**的——只有经过 FileOperationService 的目录或显式调用才会写入

## C. 元数据/标签组

### 8. `TagService`（tag_service.py）

- 全部经 `TagRepository` 访问 `file_tags`/`tag_metadata`
- **规范名解析**：`get_library().canonical(tag)`（tag_library.py 多语言同义词表）→ 用户输入"贴图"自动落库为 "Texture"（:99）
- **业务校验（A2）**：`add_tag` 与 `rename_tag` 在服务层统一去除首尾空白，拒绝空值、非字符串和超过 200 字符的名称，并抛出 `ValidationError`；LAN 路由只负责翻译为既有 400 响应
- 变更事件（:54-71）：`TagsChanged`（无会话）+ `AssetTagsChanged`（带 session_token，供 Runtime 投影）+ `TagCatalogChanged`（标签目录变化）
- 批量：`get_tags_for_files` 分块 IN 查询（900/块）
- `TagServiceAdapter`（:231-257）：把 TagService 包装成 TagStore 协议，供 TagEditorDialog 使用——**兼容层**的典型例子

### 9. `MetadataService`（metadata_service.py）

- `get_metadata`（:75）：一次性取 tags+notes+urls（两个 Repository）
- 备注/URL CRUD，变更发布 `AssetNotesChanged` / `AssetUrlsChanged`
- **目录大小缓存**（`get_dir_size` :129）：三层策略：库根总大小（library_stats）→ 缓存（cached_mtime ≥ 目录 mtime 即命中）→ `ProjectData.compute_dir_size` 全量递归扫描后写缓存
- 文件数缓存：`batch_get_cached_file_counts` / `batch_set_cached_file_counts`（批量预热用）

### 10. `DatabaseIntegrityService`（database_integrity_service.py）

- 每个 Runtime 绑定一个 canonical `LibrarySession`，在切库后后台单飞执行 SQLite `quick_check` 和保守孤儿维护。
- 慢速文件系统扫描不持有 session lease；数据库读写使用短 lease，破坏性删除在写锁内重新验证。
- `stop()` 支持关闭取消、活动连接中断和 worker 状态回滚；结果保留为 `IntegrityCheckReport` 并写入日志。
- 当前仍未覆盖半完成文件操作恢复和设置页“上次检查”展示，完整性服务不等于数据安全阶段闭环。

### 11. `LibraryExportService`（library_export_service.py）

- 只读读取 `file_tags` 与 `file_meta`，输出 schema-versioned `assetsmanager.metadata` JSON，首切片覆盖 tags/notes/URLs。
- 库内路径以相对库根路径输出；库外记录显式标记为 `absolute`，避免默认泄露本机根路径。
- 条目和标签稳定排序、重复标签去重；不导出缩略图缓存、凭据或分享密码哈希。
- `export_metadata_json` 使用同目录临时文件后原子替换目标，并拒绝把库内 `assetmanager.db` 作为导出目标。
- 当前服务已装配到 Runtime snapshot；`create_backup` 默认排除 `.thumbnails`，使用 SQLite WAL 一致性快照和 manifest 哈希；`validate_backup` 只读检查路径、哈希、库名和数据库 quick_check；`restore_backup` 要求 target session 已关闭，使用按库锁、staging、quick_check 和 `_orphaned/restore-backups` 回滚副本后再替换。Desktop 设置入口、CLI/LAN 路由仍待后续切片。

### 12. `DatabaseMaintenanceService`（database_maintenance_service.py）

- 读取 session 捕获的 SQLite 路径，提供数据库大小和有界 WAL checkpoint；checkpoint 临时使用 500ms `busy_timeout`，完成或失败后恢复共享连接原值，并在 service 已关闭时保持一致的 closed-service 语义。
- 后台任务是单飞的；关闭会中断活动连接，未完成时保持 cleanup pending，必须通过后续 close retry 完成 teardown；调度拒绝和 worker 启动失败保留可查询的状态原因。
- VACUUM 仍保持显式 unsupported 边界，不能把当前服务描述成完整维护协调器。

### 13. `LibrarySettingsAdapter`（library_settings_adapter.py）

- Qt-free 的设置层边界，统一暴露 integrity、maintenance、metadata export、backup validation 和 closed-session restore 状态。
- `integrity_error`、`integrity_schedule_error`、`maintenance_error` 和 `maintenance_schedule_error` 区分执行结果与调度阶段失败；不直接持有 Runtime 内部细节。
- 这些字段不代表 Desktop 设置页控件、异步 worker、用户指导和真实窗口验收已经完成。

### 14. `ThumbnailService`（thumbnail_service.py）

- `thumbnail_cache_key`（:28-50）：`sha256(解析路径|mtime)[:16]`，内存缓存 8192 条避免重复 syscall
- `resolve`（:84-105）：磁盘缓存命中（`.webp`）→ 原图（仅图片扩展名）；`max_size>=1024` 视为原图请求跳过缓存
- `process_image`（:107-132）：Pillow 打开 → 高斯模糊（敏感标签，radius=15）→ 等比缩放（LANCZOS）→ WEBP 质量 80
- `_check_blur`（:143-163）：blur_tags 与文件标签交集判定（敏感内容打码）
- 缓存元数据 API：`get_cached_source_mtime`、`touch_cache_metadata`、`upsert_cache_metadata`、`list_cache_metadata`、`delete_cache_metadata`、`clear_cache_metadata`；API 只返回业务所需值，不暴露 SQLite 连接
- 生命周期：Bootstrap 将 canonical `LibrarySession` 注入 ThumbnailService；缓存数据库操作与 `resolve` 均由 `session_operation` 租约保护，session 关闭后拒绝新操作
- B2 已纳入本地 `master` 基线（`f7dbca6`、`d8cb97c`，文档收口 `6266659`）：ThumbnailLoader 只持有 ThumbnailService 与 immutable Runtime 快照，不再持有 SQLite/ThumbnailRepository；保持 generation、取消、优先级、磁盘 fallback、orphan cleanup 和关闭 drain 语义。提交后聚焦测试已复核，真实图片 IO、性能基准与更大范围回归仍待闭合
- B3 TagTree Runtime 投影已纳入本地 `master` 基线（`c38a3a0`，文档收口 `2ef907e`）；后续切片补齐了 WebUI 活动标签筛选在显式 `TAGS` 失效和 cursor recovery 时的 authoritative refetch。真实浏览器跨端最终状态与发布环境证据仍待补齐

## D. 分享/认证组（Runtime-owned，LAN 与 Desktop 共用）

### 15. `ShareService`（share_service.py)

- `validate_password`（:36-46）：`None` / 空字符串统一表示无密码；其他值必须是 4–128 字符的字符串
- `validate_expires_hours`（:49-57）与 `validate_max_downloads`（:60-68）：服务直接调用只接受非布尔整数，范围分别为 1–8760 小时和 1–10000 次
- `create_share`（:86-125）：入口内再次执行三项校验 → 随机 10 位 id（碰撞重试 5 次）→ 密码 PBKDF2 哈希 → 到期时间戳 → 落库 → 返回 `ShareLink`；空密码的持久化与 DTO 均规范化为“无密码”
- LAN `/api/shares` 仅在 transport 边界兼容整数字符串，布尔值、浮点数和溢出数返回既有格式错误 400；`ValidationError` 由路由翻译，普通异常仍保持 500
- `validate_access`（:181-204）：分享存在性 → 密码 token 校验 → 到期/限次 → 路径范围校验（`is_path_allowed`）
- token：`generate_share_token`（1 小时有效，HMAC 签名）
- 生命周期：由 `ApplicationBootstrap._build_services(session)` 为每个 Runtime 生成一次随机 32 字节 `token_secret`，注入 `AuthService` 与 `ShareService` 并幂等初始化表；服务不再由 LAN 服务器临时创建。Runtime/session 关闭后该 secret 与服务实例随之失效，不跨 Runtime 持久化或复用。
- Desktop 入口：`ShareLinkDialog` 将 Runtime 的 `share_service` 交给 `ShareCreationTask`，在线程池中直接调用 `create_share`，不经过 HTTP。
- LAN 入口：HTTP `/api/shares` 管理链路仍保留；路由继续负责权限、PathGuard/transport 参数翻译，业务校验与落库仍由同一 `ShareService` 完成。
- 离线创建 URL：Desktop 即使 LAN 未启动也可落库创建分享，并依据设置中的协议、端口和访问密钥要求合成 `/s/{id}` URL；该 URL 在服务器实际启动前不可访问，启动后可复用相同配置访问。

### 16. `AuthService`（auth_service.py)

- 用户认证：`authenticate_user` → `generate_user_token`（24h）
- 注册：用户名规则（2+ 字符、字母数字_−）、密码强度校验（8+/大小写/数字/特殊字符/弱密码黑名单）、邀请码逻辑（**存在活跃邀请码时强制要求**）
- 用户管理：activate/deactivate、邀请码生成/吊销
- 令牌校验走 `domain/auth.py` 纯函数 + `AuthRepository` 取用户
- 生命周期与 `ShareService` 相同，由 Runtime 的 `RuntimeSharingServices` 持有；LAN 请求处理和 Desktop/本地 UI 使用同一服务，不再各自构造。

### 17. `PluginService`（plugin_service.py)

薄门面：包装 `PluginManagerService`，提供 discover/list/enable/disable/load/unload/load_all_enabled/get_commands/get_menu_contributions。无状态，跨库共享。

## 数据流要点

1. **写路径统一**：任何标签/元数据/文件变更 → 领域事件（带 session_token）→ RuntimeEventRouter → 投影失效 → LAN WebSocket 广播。桌面端则由面板直连 service + Qt 信号刷新；ThumbnailLoader 通过 scoped ThumbnailService 访问缓存元数据，不直接访问 SQLite。
2. **读路径分层缓存**：目录摘要（SQLite directory_cache）→ 文件数/大小（file_meta 缓存列）→ 实时扫描；搜索走内存索引 → assets 表 → 实时。
3. **降级优先**：ProjectService/SearchService/ThumbnailService 的 DB 异常几乎都吞掉降级，保证浏览不中断（代价是错误静默，见风险文档）。
### B1：Runtime-owned Auth/Share 与 LAN 本地 UI token

`AuthService`、`ShareService` 和共享的随机 `token_secret` 由 `ApplicationBootstrap` 在每个 live Runtime/session 中一次性组装；两项服务复用同一 session DB connection，secret 不持久化，LAN stop/start 不重建，session close 后失效。Desktop 的 `ShareCreationTask` 直接调用该 `ShareService`，不依赖 LAN server 已启动；HTTP 管理与远端分享路由仍通过同一服务处理。

LAN UI 的 Bearer/Cookie token 使用 `local_ui_auth_secret`，它由 Runtime secret 与 `access_key/password/auth_mode` 派生。`LanServer.token_secret` 是兼容别名，不应被解释为 Runtime-owned secret；真实字段是 `runtime_token_secret`。WebSocket revalidation 与 share routes 使用当前 local UI secret/实际认证状态。
