# 02 · 入口与启动链路

## 1. 进程入口 `main.py`

`main.py` 只做三件事：配置日志级别（过滤 PIL/urllib3 噪音）、把项目根加入 `sys.path`、调用 `AssetsManager.app.main()`。

## 2. 应用启动 `AssetsManager/app.py:main()`（:25-141）

启动序列（顺序即依赖关系）：

```
install_crash_handler()                      # core/crash_handler.py:59 注册 excepthook + 日志轮转
HighDPI 设置                                  # AA_UseHighDpiPixmaps + PassThrough 舍入策略
QApplication 创建 + 全局 QSS + 字体缩放        # themes.stylesheet() + ui_scale.scaled_pt
i18n.init()                                  # 加载语言包
ApplicationBootstrap(performance_recorder)   # 性能遥测默认关闭（settings 开关）
install_dock_refresh_handlers()              # dock_factory.py:214 主题/语言变化刷新 dock
bootstrap.discover_plugins()                 # 发现+加载启用插件，构造 PluginHostContext
OpenGL 预热                                   # 隐藏 QOpenGLWidget 抓帧，避免首次 ImageViewer 闪烁
SystemTrayManager 创建                        # widgets/tray.py，app.setProperty("has_tray")
StartupWindow 显示                            # dialogs/startup.py 库选择窗口
app.exec()                                  # 事件循环
```

### 关键回调：`_on_open(path)`（:64-95）

启动窗口选中库后：
1. 若有旧窗口：`_force_quit=True` + `close()` + `deleteLater()`
2. 创建 `MainWindow(bootstrap)`，`_workspace.add_library(path)` 打开库
3. 注册托盘引用；若设置 `lan_auto_start` 且 aiohttp 可用，延迟 1 秒自动开启分享

托盘信号（:121-131）：`show_requested` → 显示窗口/启动窗；`open_browser` → 用默认浏览器打开 LAN URL；`toggle_sharing` → 切换分享；`exit_requested` → `request_exit()` + 退出。

## 3. 服务装配 `application/bootstrap.py`

### `ApplicationBootstrap.__init__`（:63-73）
- 创建 `ServiceContainer`（`di/__init__.py`，RLock 保护、按类注册、自动单例）
- 注册服务（`_register_services` :76-91）：
  - 直接实例：`DatabaseManager(performance_recorder)`
  - 类注册（容器自动单例）：LibraryService（依赖 DatabaseManager）、AssetService、MetadataService、TagService、FileOperationService、ThumbnailService、SearchService、AssetIndexService、UndoService、PluginService
  - **刻意不注册**：AuthService / ShareService（需要库打开后的 db_conn + 随机 token_secret，由 LAN 服务器创建，见 bootstrap.py 模块 docstring）
- 挂两个监听器：
  - `add_session_closing_listener(_close_runtime)`：会话进入 closing 时关闭 Runtime 事件路由 + 停止适配器
  - `add_session_close_listener(_cleanup_session)`：会话关闭后彻底清理 Runtime 缓存

### `runtime_for(session)`（:123-163）：Runtime 单例缓存
- 以 `id(session)` 为键缓存 `LibraryRuntime`；多线程竞争通过 per-key `threading.Event` 门闩串行化创建
- 创建完成后**二次校验**：session 仍被 LibraryService 拥有且未关闭，否则 reject 并关闭新建 runtime
- 幂等语义：同一 session 永远返回同一 runtime 实例

### `_build_services(session)`（:173-197）：每库服务绑定包
```python
LibraryScopedServices(
    session,
    asset_service=AssetService(directory_cache=DirectoryCache(conn), session_token=...),
    metadata_service=MetadataService(connection_provider=session.connection_for, session=session),
    tag_service=TagService(...), project_service=ProjectService(...),
    thumbnail_service=ThumbnailService(
        connection_provider=session.connection_for, session=session
    ),
    search_service=SearchService(performance_recorder, session_token, connection_provider),
    file_operation_service=FileOperationService(session, asset_index_service, ...),
    undo_service=UndoService(library_root, session, ...),
    plugin_service / asset_index_service（容器级单例，无库状态）,
)
```

注意：`FileOperationService` 和 `UndoService` 绑定 session（有状态）；`PluginService`/`AssetIndexService` 是跨库共享单例（无状态设计）。
`ThumbnailService` 也绑定 canonical session：`resolve` 与缓存元数据 API 在完整 session operation 租约内执行，服务不会把数据库连接返回给面板或 Loader。

## 4. 库会话 `application/context.py`

### `LibraryContext`（冻结 dataclass，:48-78）
纯资源捆扎：`root / data_dir / thumb_dir / db_conn / tag_store / project_data`。`connection_for(root)` 校验 root 匹配，否则抛 `ValueError`（:77）。

### `LibrarySession`（:88-224）—— 公共的"已打开库"边界
- 不可变字段：`context`, `event_token`（每次会话唯一 UUID，用于领域事件隔离）
- 生命周期状态机：
  - `operation()` 上下文管理器（:161-187）：线程局部深度计数 + 全局 `_active_operations` 计数；最外层进入时 `_closed` 检查
  - `close()` → `_begin_close()`（拒绝新租约）→ `_finish_close()`（**等待 in-flight 操作排空** + 清 TagStore 缓存）
- 已废弃属性 `db_conn` / `tag_store` / `project_data` 会发 `DeprecationWarning`，指引改用 scoped services
- `db_conn` **不属于** session 生命周期：真正关闭由 `DatabaseManager` 负责（避免 conn 被多个 session 共享时提前关闭）

### `session_operation` 装饰器（:24-38）
服务公开方法用 `with session.operation():` 包住整个方法体，保证"操作期间 session 不会被关闭"。这是并发关闭安全的关键机制。

## 5. 库生命周期服务 `application/library_service.py`

`LibraryService`（:28-）：
- `_open(root)`（:84-127）：线程安全开库
  - `_lifecycle` 条件等待（不处于 closing / 该 root 不在关闭中）
  - 缓存命中 → 复用 context，必要时重建 session
  - 未命中 → `DatabaseManager.connection_for()`（建库/迁移）+ 构造 `LibraryContext` + 新建 session
  - 首次打开发布 `LibraryOpened(library_root, session_token)` 领域事件
- `close_session(session)`（:278-331）：完整关闭编排：
  `session._begin_close()` → `_notify_session_closing`（预关闭监听，如 Runtime 关闭适配器）→ `_finish_close()`（排空操作）→ `_notify_session_closed`（清理 Runtime 缓存）→ `db.close_library()` → 移除缓存
- `close()`（:196-277）：关闭全部库，严格编排所有会话
- 遗留兼容：`open_library()` / `current` / `get_library_service()` 均已标 `DeprecationWarning`

## 6. LibraryRuntime `application/runtime.py` + `runtime_events.py`

### `LibraryRuntime`（:12-136）
一个库一个 Runtime，拥有：
- `epoch`（随机 hex，重启即换）、`revision`（单调递增，每次投影失效 +1）
- 状态机：`open → closing → closed`，配 `threading.Condition`
- **生命周期适配器**（`register_lifecycle_adapter` / `close_adapters`）：外部组件（如 LAN 服务器）注册后，在 runtime 关闭前必须 `stop()`。这是"库先停适配器、再排空操作"的屏障
- `close()`（:95-135）：关闭事件路由 → 若在回调线程内则延迟到回调排空后（`defer_after_drain`）→ 清理适配器 → `undo_service.cleanup()`（删除撤销备份目录）

### `RuntimeEventRouter`（runtime_events.py:97-257）—— 会话级投影失效分发
- 订阅 5 类会话事件（`EVENT_DOMAINS` :68-78），映射到投影域：
  ```
  FileSystemChanged  → files, tree, home, project_detail
  AssetTagsChanged   → metadata, tags, project_detail, home
  TagCatalogChanged  → tags, home
  AssetNotesChanged  → metadata, project_detail
  AssetUrlsChanged   → metadata, project_detail
  ```
- 只处理 `session_token` 匹配且路径在库根内的**本会话**事件（:199-214）
- 每次失效：`runtime.next_revision()` → 构造 `InvalidationEvent(epoch, revision, domains, paths)` → 同步回调订阅者
- 关闭协议复杂且严谨：`accepting → closing → drained`，保证"发布中的回调不被关闭打断，关闭后不再有回调"

### LAN 端消费（lan/api.py `runtime_startup` :57-110）
app on_startup 时订阅 `runtime.event_router`，把 `InvalidationEvent` 转成 `projection_invalidated` WebSocket 广播（含 epoch/revision/domains/paths）；on_cleanup 时 `stop_runtime_realtime` 先停广播再关订阅。WebSocket 客户端用 `epoch+revision` 快照补偿丢失的更新（websocket.py 的 admission barrier）。

## 7. 数据流总结

```
python main.py
  └→ app.main(): crash_handler → QApplication → i18n → Bootstrap(容器) → plugins → tray → StartupWindow
        └→ 用户选库 → MainWindow
             └→ workspace.add_library(path)
                  └→ LibraryService.open_session(root)
                       └→ DatabaseManager.open_library()（建库/迁移/连接）
                       └→ LibraryContext + LibrarySession(event_token)
                       └→ 发布 LibraryOpened 事件
                  └→ bootstrap.runtime_for(session)（缓存单例 LibraryRuntime）
                  └→ _apply_scoped_services：file_list/info/sidebar/tag_tree 注入服务包
        └→ 开启分享（手动或 lan_auto_start）
             └→ ShareManager.start(runtime=...)
                  └→ _LanServerImpl: 校验 runtime 服务绑定 → AuthService/ShareService 创建
                  └→ aiohttp 后台线程启动 → 注册 lifecycle adapter
                  └→ runtime.event_router.subscribe → WebSocket 广播失效事件
```
