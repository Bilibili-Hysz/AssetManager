## 阶段 B：走正门——桌面不再绕路（1-2 周）

### B1. AuthService/ShareService 归属 Runtime，桌面直调【已实现；聚焦矩阵通过】【本阶段核心】

**目标**：桌面创建分享链接不再依赖 LAN 服务器运行；HTTP 管理端点与远端分享链接仍由 LAN 保留。

| 项 | 内容 |
|---|---|
| 改动范围 | `application/bootstrap.py`、`application/runtime.py`、`dialogs/share_link_dialog.py`、`dialogs/_share_api.py`、`widgets/lan_sharing.py`、`lan/server.py`及对应架构/生命周期测试 |
| 做法 | `ApplicationBootstrap` 创建并拥有每个 Runtime 的 frozen `RuntimeSharingServices`；其中一次生成的 `token_secret` 同时注入 `AuthService` 与 `ShareService`，两者使用同一 session DB connection。Runtime 创建时在 `session.operation()` 内幂等初始化 Auth/Share 表；LAN 服务器只绑定并发布这组对象，不再创建 LAN-owned Auth/Share。桌面 `ShareLinkDialog` 通过 `ShareCreationTask` 直接调用同一 `ShareService.create_share`；HTTP 管理端点（如 `/api/shares`）与远端 `/s/{id}` 分享链路保留。 |
| 生命周期 | `token_secret` 每个 Runtime/session 只生成一次；LAN stop/start 复用同一 secret。它不持久化，session close 后失效；新的 session/Runtime（包括重新打开同一库）获得新的 secret。LAN stop 不关闭 Runtime、session 或 DB。 |
| LAN UI token | LAN 不直接使用 Runtime secret；由 `token_secret + access_key/password/auth_mode` 派生 `local_ui_auth_secret`。相同认证配置 stop/start 稳定，配置变化使旧 token 失效，session close 后整体失效。`LanServer.token_secret` 仅为兼容别名，Runtime-owned 字段为 `runtime_token_secret`。 |
| 兼容边界 | 生产路径必须使用 `services_snapshot`；`.services` 仅允许 `services_snapshot` 在类型/静态属性上不存在的 legacy runtime-shaped test double。若 snapshot 存在但为 `None`、抛错或缺少投影，不得 fallback。 |
| endpoint 语义 | 无证书/私钥时端点和生成的分享 URL 使用 `http://`；证书与私钥同时配置时使用 `https://`。协议只描述 LAN HTTP server 的传输方式，不改变桌面直调创建路径。 |
| 多库隔离 | 每个 live LibrarySession/Runtime 绑定自己的 DB connection、Auth/Share service、secret、表初始化与 LAN bundle；不同库可并行，服务/secret/分享数据不可跨库复用。 |
| 测试策略 | 已覆盖 Runtime sharing identity、桌面直调创建、LAN HTTP 列表可见、服务器关闭时桌面创建、stop/start secret 复用、session close 失效、幂等表初始化与多库隔离。旧局部计数仅作为历史快照；最终全量计数待重跑，不在此处伪造新计数。 |
| 验收 | `ShareManager` 未启动时桌面仍可创建并持久化分享；LAN 启动后 `GET /api/shares` 可见；同一 Runtime 重启 LAN 后 token 仍可验证；session close 后旧 token 不再有效。 |
| 风险 | 中——共享 DB connection 的并发写仍受既有写锁与 session operation lease 约束；最终发布环境和全量回归证据仍待归档。 |
