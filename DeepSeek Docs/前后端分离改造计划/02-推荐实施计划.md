## 阶段 A：止血——立边界（1 周，纯重构，行为等价）

### A1. 应用层 URL 剥离【核心，2-3 天】

**目标**：`application/` 内不再出现任何 `/api/` 字符串。

| 项 | 内容 |
|---|---|
| 改动范围 | `application/project_service.py`（8 处 URL 构造：:132,370,437,510,590,641-642）、`application/search_service.py:30-32`、`lan/routes/metadata.py`、`lan/routes/files.py` |
| 做法 | ① 新增值对象 `PreviewRef(source_path: Path)`（放 `domain/asset.py`）与 `DownloadRef(rel_path: str)`；服务返回引用而非 URL ② 路由层新增 `lan/routes/_urls.py` 统一 `thumbnail_url(path, size)` / `download_url(path)` 组装函数 ③ 路由把 PreviewRef 转成响应字段（替换原字符串） |
| 测试策略 | 先加契约断言：锁定 `handle_projects` / `handle_home` / `handle_tree` / `handle_search` 的响应 JSON **逐字段相等**（现有契约测试扩覆盖）；改完跑全量 |
| 验收 | `rg -n "/api/" AssetsManager/application` 输出为空；LAN 响应 JSON 与改动前完全一致（contracts 测试通过） |
| 风险 | 低——纯字符串搬家，测试锁 JSON |

### A2. 业务校验下沉到服务层【1 天】

**目标**：`lan/routes/*` 内不再承载业务规则。

| 项 | 内容 |
|---|---|
| 改动范围 | `lan/routes/shares.py:95-113`（密码 4-128、过期 1-8760h、限次 1-10000）、`lan/routes/tags.py:39-65`（标签 ≤200 字符）、`lan/routes/files.py:149-167`（summaries 48 条/唯一性/直子目录） |
| 做法 | `ShareService.create_share` / `TagService.add_tag/rename_tag` / `AssetService.summarize_directories` 内部校验并抛 `domain/errors.py:ValidationError`；路由 catch `ValidationError` → 400（新增统一异常翻译中间件或 helper） |
| 测试策略 | 每个下沉的校验在 `tests/unit/` 补服务层负例测试；LAN 测试保留（验证 400 语义不变） |
| 验收 | 路由层 `rg` 无业务校验条件；行为等价 |
| 风险 | 低 |

### A3. 服务按端装配【1-2 天】

**目标**：消除"全捆绑"——桌面不再创建纯 LAN 服务。

| 项 | 内容 |
|---|---|
| 改动范围 | `application/bootstrap.py:173-197`、`application/__init__.py`、`lan/server.py:162-174` |
| 做法 | `LibraryScopedServices` 拆两个工厂：`desktop_services(session)`（Asset 保留？→ 桌面网格用 AssetService 吗？——桌面文件列表走 FileSystemModel 自扫，不用 AssetService；最终桌面包 = Metadata/Tag/FileOperation/Undo/Plugin/AssetIndex；LAN 包 = Metadata/Tag/Asset/Project/Search/Thumbnail + LAN 专属）——**具体名单以引用扫描结果为准（见 03 的 G 矩阵）**；`LanScopedServices` 只从 LAN 包组装 |
| 测试策略 | `tests/unit/test_bootstrap.py` 补"桌面包不含 X / LAN 包不含 Y"断言 |
| 验收 | 桌面启动不再创建 Project/Search/Thumbnail 服务实例；1590 全过 |
| 风险 | 低——纯装配变化，引用矩阵已扫出依赖 |

## 阶段 B：走正门——桌面不再绕路（1-2 周）

### B1. AuthService/ShareService 进容器，桌面直调【3-4 天】【本阶段核心】

**目标**：桌面创建分享链接不再依赖 LAN 服务器运行。

| 项 | 内容 |
|---|---|
| 改动范围 | `application/bootstrap.py`（新增 `lan_services(session)` 注册点：`AuthService(db_conn, token_secret)` / `ShareService(db_conn, token_secret)`，token_secret 由桌面持有）、`dialogs/share_link_dialog.py:159`、`dialogs/_share_api.py`（分享创建分支）、`widgets/lan_sharing.py:223`（`_open_share_link_dialog` 入口） |
| 做法 | ① bootstrap 在 runtime 创建时同时构建分享服务并挂到 runtime（`runtime.share_services`）② 桌面 ShareLinkDialog 改为进程内 `ShareService.create_share` ③ LAN 服务器保留自身实例（HTTP 端点供 WebUI），两者共用同一 DB 连接与 token_secret——**保证同一库内分享数据一致** ④ `_share_api.py` 的 QR/统计请求可保留（纯展示数据） |
| 测试策略 | `tests/unit/test_lan_sharing.py` 补"桌面直调创建 → HTTP 列表可见"集成断言；服务器关闭时桌面创建仍成功 |
| 验收 | `ShareManager` 未启动时，桌面可创建分享链接并持久化；服务器启动后 `GET /api/shares` 可见 |
| 风险 | 中——涉及共享 DB 连接并发写（已有 db_write_lock 保护）；token_secret 生成时机需与服务器一致（服务器启动时复用 runtime 的 secret，而非重新生成） |

### B2. 桌面缩略图改走 ThumbnailService【2-3 天】

**目标**：展示层不再持有 Repository/Connection。

| 项 | 内容 |
|---|---|
| 改动范围 | `panels/file_list/_loader.py:185,231`（ThumbnailRepository + sqlite3.Connection）、`panels/file_list/_base.py:250`、`panels/info.py:1058` |
| 做法 | ① `ThumbnailService` 增加桌面缓存端口：`get_cached_thumb(source, thumb_dir, max_size)`（先查磁盘 webp，无则生成并落盘——把 _loader 的 bake 逻辑上移）② `_loader.py` 改为持 `ThumbnailService` 引用，删除 `set_cache_db`/Repository 字段 |
| 测试策略 | 桌面缩略图测试（tests/desktop + tests/panels）改注入 mock service；缓存语义断言不变 |
| 验收 | `rg -n "ThumbnailRepository" AssetsManager/panels` 为空；桌面与 LAN 缩略图缓存路径/键语义一致（同一 `thumbnail_cache_key`） |
| 风险 | 中——_loader 是性能敏感路径，改完必须跑性能基准（tests/performance）确认无回退 |

### B3. 桌面投影统一试点【2 天，可选先行】

**目标**：证明"桌面订阅 InvalidationEvent"可行，为阶段 C 铺路。

| 项 | 内容 |
|---|---|
| 改动范围 | `panels/tag_tree.py`（试点）、`panels/_event_bridge.py` |
| 做法 | TagTree 在 `set_scoped_services` 时订阅 `runtime.event_router`（domains: tags），收到失效后刷新自身；保留现有信号路径做对比（双路径共存一周） |
| 测试策略 | `tests/panels/` 补"发布 AssetTagsChanged → TagTree 收到失效"测试 |
| 验收 | 双路径并存无冲突；标签变更在桌面/Web 同时刷新 |
| 风险 | 低（试点 + 双路径） |

## 阶段 C：契约化——让边界可维护（2-4 周，按需执行）

### C1. 契约单一来源【1-2 周】

**目标**：消除 DTO 三份手抄（`lan/dto.py` ↔ `webui/src/api/*.ts` ↔ `tests/contracts/lan_public_contracts.json`）。

| 项 | 内容 |
|---|---|
| 做法（最小） | 脚本 `scripts/gen_ts_types.py`：从 `lan/dto.py` dataclass 生成 `webui/src/api/contracts.ts`（dataclass 字段→TS interface）；CI 校验生成物无 diff；contracts JSON 改为脚本生成快照 |
| 做法（进阶，可选） | 引入 openapi.yaml 描述 WebUI 实际用到的端点；路由响应断言走 schema 校验；TS 类型从 openapi 生成 |
| 验收 | 修改 `lan/dto.py` 后 `npm run build` 自动反映（CI 门禁）；无手写 TS 类型残留 |
| 风险 | 中——脚本本身要测；范围必须收敛到"WebUI 用到的端点" |

### C2. 桌面端口层（Protocol）【1-2 周】

**目标**：面板只依赖接口，不依赖具体服务。

| 项 | 内容 |
|---|---|
| 做法 | 新建 `application/desktop_ports.py`：`TagsViewPort`（list/add/remove/set_metadata）、`MetadataViewPort`（get/set notes, urls）、`FileOpsViewPort`（7 操作）等 Protocol；面板构造函数改为接收端口（由 window 注入）；`TagServiceAdapter` 退役 |
| 验收 | `rg -n "scoped\.(tag_service|metadata_service|file_operation_service)" AssetsManager/panels` 为空 |
| 风险 | 中——面板改动面大，按面板逐个迁移（info → tag_tree → file_list） |

### C3. 桌面投影全面统一【1 周，可选】

| 项 | 内容 |
|---|---|
| 做法 | B3 试点验证后，InfoPanel/FileList 逐步改订阅 InvalidationEvent；`signal_bus` 收窄为纯展示协调（theme/language/ui_scale） |
| 验收 | 桌面面板刷新路径统一；signal_bus 只剩展示信号 |
| 风险 | 高——放到最后，若时间不足可砍掉（保留双路径，功能不受影响） |
