# 03 · 验收标准与风险预案

## 一、总体验收标准（可量化）

改造完成后，以下断言必须全部成立（执行时逐项勾验）：

| # | 验收项 | 验证方式 |
|---|---|---|
| 1 | `rg -n "/api/" AssetsManager/application` 输出为空 | 静态扫描 |
| 2 | `rg -n "Repository\(" AssetsManager/panels AssetsManager/widgets` 输出为空（测试目录除外） | 静态扫描 |
| 3 | `rg -n "connection_for" AssetsManager/panels AssetsManager/widgets` 输出为空 | 静态扫描 |
| 4 | 分享创建在 `ShareManager` 未启动时桌面可用 | 手动冒烟 + 集成测试 |
| 5 | `rg -n "http://localhost" AssetsManager/dialogs` 仅剩纯展示请求（QR/统计），无业务创建/写入 | 静态扫描 + 人工确认 |

## 二、阶段门禁（Gate）

每阶段结束时必须全部通过才能进入下一阶段：

```
阶段 0 → [基线测试输出归档] → 阶段 A
阶段 A → [门禁 1,2,7,8,9] + 手动冒烟（开库/浏览/搜索/分享页面可开）→ 阶段 B
阶段 B → [门禁 1,3,4,5,7,8,9] + 手动冒烟（分享创建/缩略图/双端刷新）→ 阶段 C
阶段 C → [门禁 1-10 全量] + WebUI 构建通过（npm run build）
```

**门禁失败处理**：该阶段最后一个提交 revert 或修复后重跑；不允许带失败进入下一阶段（行为等价原则）。

## 三、风险预案

### R1. 行为等价被破坏（响应 JSON 变化）
- **症状**：契约测试失败 / WebUI 页面字段缺失
- **预案**：A1 的 URL 剥离必须与契约断言同步提交（先断言后改码）；若已提交，直接 `git revert` 该 commit（每个任务独立提交的意义所在）
- **预防**：A1 拆分"加断言"与"改代码"两个 commit

### R2. 桌面缩略图性能回退（B2）
- **症状**：tests/performance 缩略图项超基线 20%+
- **预案**：回退 B2，保留 ThumbnailLoader 现状，仅将 Repository 访问包装成 ThumbnailService 静态方法（性能零变化的妥协版）
- **预防**：B2 前先跑基线，改后立即对比

### R3. 分享服务双实例数据不一致（B1）
- **症状**：桌面创建的分享在 HTTP 列表不可见，或 token 校验失败
- **根因预防**：桌面与 LAN 必须共享**同一 `token_secret`**（桌面生成、启动服务器时传入，`ShareManager.start(..., token_secret=...)`）；DB 连接共用（同一 session.connection_for）
- **预案**：B1 测试先写"跨路径可见性"集成用例，再改代码

### R4. 契约生成脚本自身有 bug（C1）
- **预案**：脚本输出先人工 diff 一次；CI 同时保留 contracts JSON 快照对比（双保险）；脚本进 `tests/` 由单测覆盖

### R5. 桌面投影统一（C3）回归爆炸
- **预案**：C3 定义为**可砍项**——时间不足或回归率超标时直接不做，双路径共存不影响任何现有功能
- **预防**：B3 试点必须先行，试点稳定至少 1 周再扩大

### R6. 执行中途失去动力（个人项目最大风险）
- **预案**：A 阶段是"必须完成"的最小承诺（1 周）；B/C 按周推进，每周结束都有可交付状态；**任何阶段停止，系统都比现在好**——这是方案 B 相比 C/D 的保障

## 四、执行约定（给未来执行者）

1. **每个任务一个 commit**，消息风格沿用仓库（`feat: / fix: / refactor:`），如 `refactor: strip http URLs from application services`
2. **先加测试，后改代码**；行为等价任务禁止"改码后补测试"
3. 静态扫描验收项（门禁 1-6）写成脚本 `scripts/check_boundaries.py`，纳入 CI（可选）或本地手动跑
4. 每阶段结束更新本计划文档的"执行状态"（在任务前打 ☑️），保证计划文档始终反映真实进度
5. **边界规则五条**（来自 06 分析文档第四节）写入 `docs/architecture.md`，作为新代码评审依据：
   - 应用层返回值/参数不允许出现 URL、HTTP、传输语义
   - 展示层不允许持有 Connection / Repository
   - 进程内能调用就不走 HTTP
   - 业务校验只存在服务层
   - 每端只装配自己用的服务
6. 新功能开发期间若违反上述规则，视为缺陷（与 bug 同优先级）

**A3 当前门禁（2026-08-02）**：第五条已落为架构测试——Desktop/shared eager、Asset/Project/Search 仅由 Bootstrap 的 LAN lazy projection 构造；完整 Python `1695 passed, 1 skipped`，Task D `431 passed`，Desktop/LAN/Chromium `190 passed`，独立复核 P0–P3 清零。原“Desktop 不创建 Thumbnail”验收已按 B2 真实依赖校准为“Thumbnail eager，Asset/Project/Search lazy”。
