# 05 · 验收标准

> 全部验收项可量化执行；实施每阶段结束时逐项勾验。

## 一、静态/结构验收

| # | 验收项 | 验证方式 |
|---|---|---|
| 1 | `AssetsManager/plugin_api/` 存在且为插件唯一 sanctioned 入口 | `rg -n "import AssetsManager\." Plugins/Addons` 除 `plugin_api` 外为空（或均为诊断警告） |
| 2 | 旧 10 个注册方法在 `PluginHostContext` 中标记为 `@deprecated` 且映射到注册表 | 静态扫描 + 注释声明 |
| 3 | `host_context.py` 的 `tool_windows()` 移除（由 PanelContributor 取代） | 无消费者残留 |
| 4 | manifest 不再解析 `provides`/`config_schema`/`kind`/`display_fields`（显示为"已废弃，忽略"诊断） | 单元测试断言诊断产出 |
| 5 | `apply_registered_categories` / `apply_registered_theme_tokens` 有调用者（注册时自动执行） | `rg` 出现消费点 |
| 6 | `PluginManagerService.parse_file` 无双路径：旧实例 match/parse 与 host 注册的 FileParser 合并去重 | 单测：同一插件两种方式注册只解析一次 |

## 二、行为验收

| # | 验收项 | 验证方式 |
|---|---|---|
| 7 | **旧插件零修改兼容**：booth_link 在 v2 宿主下解析结果与改造前逐字段一致 | 回归测试：`parse_file` 输出快照对比 |
| 8 | 插件启用（UI）后**立即加载生效**，无需重启 | 手动冒烟 + 自动化（enable → state=active 断言） |
| 9 | 命令执行统一：菜单执行与右键执行进入同一 `execute(ctx, params)` 路径，`ctx.selected_paths` 均可用 | 单测模拟两条入口断言参数一致 |
| 10 | `poll=False` 时命令不可用（菜单置灰 + 右键项隐藏） | 单测 + 手动 |
| 11 | `undoable=True` 的命令操作进撤销栈并可撤销/重做 | 集成测试：执行 → undo → 文件系统恢复 |
| 12 | 参数化命令自动生成对话框，提交值传入 `execute` | 手动 + 单测（params schema → 表单 → 值） |
| 13 | 分类/主题 token 注册后**立即生效**（过滤下拉可见、themes.get() 可取） | 集成测试 |
| 14 | PanelContributor 注册 → 主窗口出现对应 dock | 桌面测试（offscreen） |
| 15 | Preferences 修改持久化，重启后保留 | 集成测试（JsonStore 文件断言） |

## 三、权限验收

| # | 验收项 | 验证方式 |
|---|---|---|
| 16 | advisory 模式：越权调用被记录到插件诊断（不阻止） | 单测：日志/诊断断言 |
| 17 | enforced 模式：越权调用抛 PermissionError 且操作失败提示 | 单测：异常断言 |

## 六、测试策略

```
tests/plugins/                    # 新增测试目录
├── test_registry.py              # 12 种贡献类型注册/回收/去重（验收 1-6, 22-24）
├── test_context.py               # PluginContext 动态查询（选中/目录/焦点）
├── test_compat_legacy.py         # 旧协议适配（验收 7 核心：booth_link 快照回归）
├── test_operators.py             # poll/params/undo（验收 9-12）
├── test_permissions.py           # advisory/enforced/代理（验收 16-19）
├── test_lifecycle.py             # 启停/重载/依赖/版本（验收 8, 20-21）
└── test_preferences.py           # 持久化与表单（验收 15）
```

**关键回归**：`test_compat_legacy.py` 的 booth_link 快照测试是兼容层安全的生命线——实施阶段 1 时必须与兼容层同日落地。

## 七、与现有文档体系的衔接

- 本规划与 [前后端分离改造计划](../前后端分离改造计划/README.md) 并行不冲突：插件 API 的服务访问层（`ctx.services()`）应建立在其"阶段 A 服务层稳定"之后，权限代理可复用其边界规则
