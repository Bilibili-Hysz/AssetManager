# 施行路线图（总规划）

> 汇总全部计划（前后端分离 / 插件 API / 功能缺口 / 性能 / 视觉）的**统一施行顺序**。
> 原则：① 先基线后动工 ② 先数据安全后功能 ③ 先稳定后美化 ④ 服务层是一切地基 ⑤ 每阶段可独立中止，停止时产品都比之前好。
> 时间按个人开发（半全职）估算。

## 依赖关系图

```
阶段0 基线提交（一切前提）
  ├──▶ 阶段1 数据安全（独立）
  ├──▶ 阶段2 性能优化（独立，桌面核心）
  ├──▶ 阶段3 前后端分离 A+B（服务层稳定）
  │        ├──▶ 阶段4 视觉改进（可与3并行，表现层）
  │        └──▶ 阶段5 插件API v2（ctx.services 依赖服务层）
  │                 └──▶ 阶段7 契约化+权限（收尾）
  └──▶ 阶段6 P1功能精选（穿插空档，无硬依赖）
```

### 阶段 2：性能优化（2-3 周）【🟡 部分完成】
第 0 步测量、第 1 步 watcher 防抖与第 2 步纹理路径复用已实现；第 3 步目录大小治理已完成“单并发 + 有界队列 + 可见目录优先”子项，第 4 步 reset 最小化尚未闭合。50,000 synthetic/offscreen 结果：cold grid.frame P50 `6.436ms`，scroll/zoom P50 `3.713ms`、P95 `10.853ms`，warm `texture_build_count=0`。
**验收未闭合**：需要真实图片 IO、发布机复测、目录大小首屏耗时和 reset/刷新语义门禁。

### 阶段 3：前后端分离 A+B（2-3 周）【服务层地基】
按 [前后端分离改造计划/02](前后端分离改造计划/02-推荐实施计划.md)：A1 URL 剥离（✅）→ A2 校验下沉（标签、分享、目录摘要✅）→ A3 按端装配（✅）→ B1 分享进容器（桌面直调）→ B2 缩略图走服务（✅ 服务边界已提交，性能/全量验收待闭合）→ B3 投影统一（Desktop TagTree + Web 活动标签重拉已形成最小闭环，最终跨端状态验收待办）。
**验收**：`rg "/api/" AssetsManager/application` 为空；TagService、ShareService 与 AssetService 已拥有 A2 业务校验，LAN 仅保留 transport/PathGuard 边界并翻译 `ValidationError`；A3 保持单一 Runtime/snapshot，Desktop/shared 服务 eager，Asset/Project/Search 仅在 LAN 组合时 single-flight materialize；ThumbnailLoader 只持有 ThumbnailService 与 immutable Runtime snapshot，不再持有 SQLite/ThumbnailRepository；session operation、generation、取消、优先级、deferred queue、stale result、orphan cleanup 与关闭 drain 已有行为门禁。A3 当前证据为完整 Python `1695 passed, 1 skipped`、Task D `431 passed`、跨端矩阵 `190 passed`。仍需完成 B1、真实图片 IO/性能与 B3 最终跨端状态验收。
**门禁**：阶段 C（契约化）可推迟，本阶段完成即达"边界规则落位"核心目标。

### 阶段 4：视觉改进 V1（2-3 周）【可与阶段 3 并行】
图标系统（SVG + 与 WebUI 同源命名）+ 按钮四变体 + 字阶系统（[未来方向/05](未来方向/05-桌面端UI视觉改进规划.md) V1）。V2/V3 按需排期。
**建议**：A3 前置条件已完成；视觉任务可继续按文件域与后续 B1 分区并行，避免同时修改 bootstrap、分享对话框和 panels 注入点。

### 阶段 5：插件 API v2（3-4 周）【依赖服务层稳定】
阶段 1（plugin_api 包 + PluginRegistry + PluginContext + 兼容层 + 命令消费点统一）→ 阶段 2（Operator/Panel/Preferences/Keymap/Category 生效）。
**验收**：booth_link 零修改行为一致（回归快照）；UI 启用插件立即生效。

### 阶段 6：P1 功能精选（穿插空档，无硬依赖）

### 阶段 7：契约化收尾（2-4 周）【可选但推荐】

## 里程碑定义

| 里程碑 | 时间点 | 产品状态 |
|---|---|---|
| **M1 可用性基线** | ~3 周 | 数据安全闭环 + 掉帧缓解——可放心日常使用 |
| **M2 边界立起** | ~6 周 | 服务层稳定 + 视觉 V1——架构可演进 + 观感提升 |
| **M3 生态起步** | ~10 周 | 插件 v2 骨架 + P1 精选——第三方可接入 |
| **M4 平台收尾** | ~14 周 | 契约化 + 权限门禁——可被任何人接手 |

**任何里程碑后都可暂停**：M1 后是"安全的工具"，M2 后是"结构清晰的产品"，M3 后是"有生态的平台"。

## 执行约定（沿用各计划文档）

1. 每个任务独立 commit（`feat:/fix:/refactor:`），消息风格沿用仓库
2. 先加测试后改代码；行为等价任务以测试锁 JSON/行为
3. 每阶段结束跑全量门禁：`pytest -q` + `tests/performance` + 契约测试
4. 静态验收项（边界规则 5 条）写入 `docs/architecture.md`
5. 店铺方向（[未来方向/01-04](未来方向/README.md)）触发条件未满足前不进入任何排期
