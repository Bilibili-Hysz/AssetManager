# Share System 桌面端分阶段改造计划（2026-07-15）

## 目标

将当前“Overview / Share Links / Users / Settings”四标签、多个独立分享弹窗和重复 HTTP 任务的 Share System，改造成以暴露状态为首要信息的单一桌面管理壳：`Endpoint`、`Links`、`Access`、`Configuration`。改造只改变桌面 presentation、交互路径和客户端编排；LAN 服务、ShareService、HTTP 路由和链接语义保持兼容，除非某项 UI 当前承诺的运行时能力需要先补齐。

设计依据：

- `docs/Suggestions/share-system-desktop-DESIGN.md`
- `docs/Suggestions/share-system-desktop-redesign-2026-07-15.md`

## 已确认约束

- `AssetsManager/widgets/lan_sharing.py` 仍是桌面 LAN server 的生命周期 owner；新 UI 不直接创建第二个 server，也不绕过现有 session、server 和设置路径。
- 现有 `SharingSettingsDialog`、`ShareLinkDialog`、`ShareLinkManager`、`QuickShareCard` 分别重复链接创建、链接管理和 HTTP QRunnable；先统一客户端调用和视图模型，再迁移 UI。
- 所有 async 回调必须在 dialog 仍存活、服务仍为原对象、所请求记录仍可识别时才提交 UI；刷新后按 immutable share ID 恢复选择，不按行号恢复。
- 保留 AppSettings、`themes.get()`、`scaled_px`、`scaled_pt`、`i18n.tr`，但不得再用翻译文本判断行为或生成持久化 key。
- 不使用 emoji 作为唯一状态、导航或动作语义。图标必须有文字邻接或可访问名称与 tooltip。
- 每一阶段必须有 focused regression tests；行为变更前应先确认现有 LAN route/service 契约。

## 阶段 F0：基线与共享桌面客户端边界

**目的：** 先消除界面层反复创建 GET/POST/DELETE QRunnable 的行为差异，为后续统一 loading/error/cancellation 提供唯一实现。

**实现：**

1. 新建一个窄的 desktop share client/helper（置于 dialogs 或 application 边界，以现有代码组织为准），集中构造本机 API base、auth headers、GET/POST/DELETE worker 与分类错误结果。
2. 为链接、邀请码、在线用户和活动加载定义稳定的视图数据入口；worker 只返回结构化成功、HTTP 失败、网络失败和取消/过期结果，不直接展示 `QMessageBox`。
3. 为认证模式和内容类型使用稳定 domain keys，例如 `none`/`password` 与 `images`/`models`/`videos`；在 combo 或 checkbox 上保存 key/property，显示层才调用 `tr()`。
4. 抽取用于 share-table 行为的 `share_id`、显示名、路径摘要、访问方式、过期和下载计数规范化函数，避免不同弹窗各自解释 response。
5. 不迁移视觉布局，不删除旧入口；旧 dialog 改为使用新 helper 后保持现有 UI 与可观察结果。

**主要文件：**

- `AssetsManager/dialogs/sharing_settings_dialog.py`
- `AssetsManager/dialogs/share_link_dialog.py`
- `AssetsManager/dialogs/share_link_manager.py`
- `AssetsManager/dialogs/quick_share_card.py`
- `AssetsManager/widgets/lan_sharing.py`
- 新增共享 desktop share client/helper 与 focused tests

**验收：**

- 链接创建、加载、删除、邀请码操作和 activity 请求共用同一错误分类与 auth-header 路径。
- 语言切换不会改变 `lan_auth_mode` 或 `lan_include_types` 的持久化值。
- 各请求在服务器停用、dialog 关闭、网络失败、HTTP 失败时不更新过期 UI，也不泄露异常文本给用户。

## 阶段 F1：统一 Share System shell 与 Endpoint 页面

**目的：** 用服务状态条替换 Overview 卡片网格，让用户一打开就能判断共享是否关闭、本地可达还是公网暴露，并执行正确范围的停止/复制操作。

**实现：**

1. 将 `SharingSettingsDialog` 改为专用 management shell，桌面最小尺寸目标为 `980 x 720`，左侧导航为 `Endpoint`、`Links`、`Access`、`Configuration`；保留窄窗口 top navigation 回退。
2. 首先实现 Endpoint 页：状态条显示状态圆点加文本、local URL、可访问性/保护摘要、连接数及一个上下文主操作。
3. 明确状态模型：`off`、`starting`、`local`、`public`、`failed`。公网 tunnel 是 `public` 的额外暴露状态，不与整个服务的 start/stop 混为一谈。
4. URL 左对齐、可选择、视觉截断但始终可通过 Copy/Open 使用；QR 改为端点存在后的按需 side sheet/secondary action，不占首屏常驻面积。
5. Recent activity 变成 Endpoint 页的支持列表，空、加载和失败状态有明确说明；移除 bullet dot/emoji 作为活动格式或状态表达。
6. 保持 `LanSharingMixin._toggle_sharing()` 的生命周期 owner 身份。Endpoint 只能调用 host action 或传入的控制器，并从实际 server 状态重绑定。

**测试：**

- stopped、starting、local、public、failed 状态的渲染与动作可用性。
- endpoint copy/open 使用 local/public 正确地址；停止公网 tunnel 不停止 local server。
- 主窗口切换、dialog 关闭、server 被外部停止时，不会有旧 timer/request 回调污染状态。
- 980px 与 800px 以下布局的 Qt geometry/snapshot-style 断言；无 emoji-only semantic status。

## 阶段 F2：规范化 Links 页面与 Create-link sheet

**目的：** 将所有创建、复制、管理和撤销链接的任务收敛到一个页面与一个可预填的创建 sheet，消除 `ShareLinkManager` 与 QuickShareCard 的重复产品路径。

**实现：**

1. 实现 Links 页面：搜索、状态筛选、可排序/可选行、选择驱动 action bar、行 context menu 和明确的 loading/empty/error 状态。
2. 用 immutable share ID 保存选择；异步 refresh/filter/delete 后按 ID 恢复选择，删除成功才移除对应记录。
3. 建立 `CreateShareLinkSheet`（或改造现有 `ShareLinkDialog` 为 sheet），输入为 selected paths 与 server/controller；包含访问方式、密码、过期、下载上限、预览许可和公网暴露提示。
4. 创建成功进入稳定的结果模式，只提供 Copy/Open/Show QR/Done，明确 `Create another link` 后才能再次发起请求，避免重复提交。
5. 右键 Quick Share、工具栏 quick share、`LanSharingMixin._quick_share()`、Share System 的 Create link 都路由到同一个 sheet；上下文入口仅提供默认值和路径预填。
6. 迁移所有调用方和测试后删除/退役独立 `ShareLinkManager` 与 `QuickShareCard`。不保留重复 UI 的兼容入口。
7. 文案将 destructive `Delete` 改为 `Revoke`，确认框说明访问影响；如果后端不支持恢复，不承诺 undo。

**测试：**

- 选中文件/目录、多选路径、服务未启动、公开 tunnel、密码、期限、下载上限和 preview 选项的 request payload。
- 成功/失败/取消/重复点击、结果模式动作、URL copy/open、当前 server 被替换后的回调忽略。
- Links 搜索、active/expired 筛选、按 ID 选择恢复、批量 revoke 部分失败和空状态。
- 所有旧分享入口均打开同一规范 sheet；删除独立 manager/card 后 import 与入口回归通过。

## 阶段 F3：Access 页面与真实生效语义

**目的：** 将邀请码、在线用户和访客默认权限收拢为访问控制，而不是 Settings 中的附属内容，并消除 UI 设置已保存但运行中 server 未使用的误导。

**实现：**

1. 实现 Access 页三段：访客策略、邀请码、当前连接者。Admin 身份如需保留，收缩为页首 identity line。
2. 为 invite create/revoke 及 online-user refresh 增加 region-local busy、成功和失败反馈；不能再静默丢弃失败。
3. 审核 guest download/preview/list 的实际 service/route 消费点。
4. 若服务端支持 reload，则将 guest 策略加入明确 hot settings 并测试运行时应用；若不能支持，则 UI 标记 `Applies after restart` 并在 Apply footer 汇总重启需求。不得把保存设置表述为已生效。
5. 统一 invite actions 使用 selection bar/context menu 与键盘可达性，不在每一行嵌套填充按钮。

**测试：**

- 邀请码生成/复制/撤销的成功与失败反馈。
- guest 策略在 runtime 生效或 restart-required 状态的端到端证明。
- 服务器停用、权限拒绝、列表为空和请求超时时的区域状态。
- 按键、accessible name、tooltip 和本地化 key 稳定性。

## 阶段 F4：Configuration 信息架构与主题一致性

**目的：** 将长滚动 accordion 配置页变为按风险和频率分组的 section navigator，并让每个变更说明其立即生效还是需要重启。

**实现：**

1. 建立 Configuration 二级导航：Network、Protection、Presentation、Library scope、Diagnostics、Internet access（可用时）。每页只呈现本主题所需控件与后果说明。
2. 实现 change tracking，比较打开时 settings snapshot 与编辑值。底部固定栏显示 `No unsaved changes`、`N changes apply now`、`N changes require restart`，并提供 Discard/Apply changes。
3. 将 restart-required 分类与 `LanSharingMixin._apply_sharing_settings()` 的实际 reload/restart 逻辑共用同一个声明，避免 UI 与运行逻辑漂移。
4. 移除各 dialog、表格 cell widget 和 popup 中的硬编码 per-widget QSS。创建基于 `themes.get()` 的 Share System semantic style helpers，并验证 theme change 时全页刷新。
5. 审核 TLS、bind、password、IP rules、rate limits 与 tunnel 的服务端支持；无支持的选项不显示为即时生效。

**测试：**

- 每个配置 key 的 load/save、live/restart 分类、Discard/Apply、无修改状态和 server stop/restart 行为。
- light/dark/custom theme 切换后 inputs、selection、action bar、status strip 与 sheet 同步更新。
- 窄窗口、长本地化字符串、路径/URL、CJK UI 与 focus order。

## 阶段 F5：清理、可访问性审计与完整回归

**目的：** 移除废弃界面路径，验证产品级交互闭环，避免以新外观掩盖旧行为分叉。

**实现：**

1. 删除弃用的独立 manager/card/重复 worker（仅当所有调用方与测试迁移完成）。
2. 清理过时翻译 key、emoji 文案和无行为对应的 UI controls；新增三语翻译并验证 key parity。
3. 将 Share System 生命周期、async stale callback、theme change、locale switch、keyboard access 和 stop/start 竞态纳入 focused desktop tests。
4. 更新 `docs/Suggestions/share-system-desktop-redesign-2026-07-15.md` 的状态和必要的开发/架构文档，记录 canonical entry points 与 setting activation semantics。

## 目标与原则

- 在功能稳定基础上，以架构与可维护性为未来 2-3 个迭代的主线；采用每批 1-2 周、可发布、可回滚的小批次方式。
- 不进行大规模重写。每个批次均遵循：先补契约测试，建立新边界，迁移调用方，禁止新增旧入口，观察一个稳定发布周期，再物理删除旧入口。
- 不得回退既有不变式：文件操作必须在 metadata、thumbnail、asset-index 投影完成后发布领域事件；WebUI 的 abort/generation 保护必须保留；LibrarySession 必须拒绝关闭后的新工作、排空既有 lease，并在数据库关闭前排空缩略图旧 generation。
- 性能优化仅在有测量证据时进行；新的队列、预取、缓存维护、索引和 telemetry 都必须绑定 session、generation 与路径，并遵守 selective library teardown。

## 第一阶段：所有权收敛

### R1：数据库写入所有权收敛

**目的**：消除 DI 中的 `DatabaseManager` 与 singleton `db_write_lock()` 可能不是同一所有者的隐患，让每个已打开 library runtime 都有可验证的连接与写入协调者。

**关键文件**：
- `AssetsManager/core/database.py`
- `AssetsManager/application/bootstrap.py`
- `AssetsManager/application/library_service.py`
- `AssetsManager/application/context.py`
- `AssetsManager/repositories/*.py`
- `tests/core/test_database_metadata.py`
- `tests/integration/test_library_service.py`
- `tests/unit/test_bootstrap.py`
- `tests/unit/test_architecture_boundaries.py`

**实施步骤**：
1. 先补并发契约：同 session 写入串行；关闭后拒绝新写；关闭会等待已获 lease 的写完成；文件操作仍是投影先于事件。
2. 让 session/runtime owner 持有唯一 `DatabaseWriteCoordinator`（名称以现有代码风格确定），并由 bootstrap 与 repository 使用同一实例。
3. 将 module-level `db_write_lock()` 降为仅供兼容层代理的入口；禁止新业务调用，增加架构 ratchet。
4. 在测试/诊断中证明 coordinator、连接与 session 生命周期一一对应。

**不做**：不改 schema、不换 ORM、不搬迁 inline SQL、不处理 `_current_root`、不改变事务边界或异常语义。

**验收**：两 library 并发读写、关闭 A 保持 B 可用、关闭与写入竞态、桌面/LAN/WebUI 文件变更可见性、架构测试均通过。若无法证明同一连接和写锁拥有相同 owner，停止迁移调用方，先修 composition root。

### R2：根目录与数据库上下文显式化

**目的**：移除 `DatabaseManager._current_root` 对数据层/后台任务的隐式影响，防止多库切换、同 root reopen 和 worker 延迟执行时的 root 串扰。

**关键文件**：
- `AssetsManager/core/database.py`
- `AssetsManager/application/context.py`
- `AssetsManager/application/library_service.py`
- `AssetsManager/application/*_service.py`
- `AssetsManager/panels/file_list/_loader.py`
- `AssetsManager/panels/file_list/_model.py`
- `tests/integration/test_library_service.py`
- `tests/unit/test_architecture_boundaries.py`

**实施步骤**：
1. 清点 `_current_root` 的读写点，分为同步 service、异步 worker、兼容 API。
2. 由 `LibrarySession` 持有不可变 library context，明确 root identity、session identity、连接/runtime 引用。
3. 优先迁移后台任务和 DB 写路径，使其只从捕获的 session/context 读取 root。
4. 将 `_current_root` 改为只读兼容镜像；禁止新增读写并记录存量调用数。

**不做**：不删除 `LibrarySession` raw 属性、不改文件操作事件协议、不引入跨 session 的可变 context。

**验收**：A/B 快速切换下扫描、缩略图、写入和事件均不串库；同 root reopen 后旧任务无法影响新 session；架构测试阻止新增隐式 root 获取。

### R3：LibrarySession 门面化

**目的**：将 `LibrarySession` 从暴露 `db_conn`、`tag_store`、`project_data` 的 infrastructure bag 收敛为生命周期与 scoped services 的受控边界。

**关键文件**：
- `AssetsManager/application/context.py`
- `AssetsManager/application/bootstrap.py`
- `AssetsManager/application/library_service.py`
- `AssetsManager/panels/file_list/_base.py`
- `AssetsManager/panels/info.py`
- `AssetsManager/panels/tag_tree.py`
- `tests/desktop/test_scoped_service_access.py`
- `tests/integration/test_library_service.py`
- `tests/unit/test_architecture_boundaries.py`

**实施步骤**：
1. 更新 ADR，明确 session 只负责 identity、lease、close barrier 与 scoped service access；connection/store/runtime 变为内部细节。
2. 为实际调用需求提供窄服务接口，避免创建新的万能 session service locator。
3. 为 raw 属性增加弃用计数/测试诊断；先迁移 worker、文件操作和高风险 panel/controller 调用方。
4. 增加 ratchet，禁止新增 `session.db_conn`、`session.tag_store`、`session.project_data`。

**不做**：不一次删除兼容属性，不重写 TagStore/ProjectData，不改变 session lease、thumbnail drain 或 selective close 行为。

**验收**：关闭中的 session 对新门面操作 fail closed；在途 service 操作正确阻塞 close；Panel 切库后不保留旧 raw DB/store；稳定发布周期后为已清零属性确定删除版本。

## 第二阶段：应用与 UI 去全局化

### R4-R6：Repository 边界与 legacy cache 清理

1. 清点 `application/` inline SQL，按表/查询能力迁至 repository 或专用 query service；每次只迁一个小 SQL 切片并先固定结果/错误契约。
2. 将 `TagStore`、`ProjectData` 的生命周期绑定到 session runtime；新代码只经 scoped service 调用，保留全局 facade 直到调用数归零。
3. 在静态调用清零、集成回归通过和稳定发布周期结束后，删除第一批 `_current_root` 写入、`db_write_lock` 适配器和已清零 raw session 属性。

**关键约束**：跨表文件操作必须仍是同一命令的强一致投影；不要为跨聚合查询硬塞进单一 repository；缓存算法优化另立性能批次。

### R7-R9：生命周期协调与 presentation 依赖收敛

1. 从 `AssetsManager/window.py` 抽取 session switch/close coordinator；只调用 panel 公共 `prepare/bind/dispose` 契约，禁止访问 panel 私有 timer/loader。
2. 逐步移除 `AssetsManager/panels/_service_access.py` 等 service-locator fallback；测试也显式注入 scoped bundle。
3. 对 DB drain、thumbnail drain、WebUI abort、panel cleanup、事件取消订阅做关闭故障注入；只在资源无泄漏和无悬挂任务后删除 fallback。

**关键文件**：`AssetsManager/window.py`、`AssetsManager/panels/_service_access.py`、`AssetsManager/panels/info.py`、`AssetsManager/panels/file_list/`、`AssetsManager/panels/sidebar.py`、`AssetsManager/panels/tag_tree.py` 与 desktop lifecycle tests。

## 第三阶段：事件与治理

### R10-R11：事件语义收敛

1. 先盘点 `domain.event_bus` 与 `core.signal_bus` 的 producer、consumer、线程模型与关闭语义。
2. 固化规则：domain events 是 application service 发布的业务事实；Qt signals 仅作 presentation command/state transport；跨层仅经过显式 bridge。
3. 按事件族迁移并做 trace 测试，验证恰好一次、投递线程、session identity、关闭后无回调。只有旧发布者和订阅者都清零，才删除 adapter。

### R12-R14：工程与性能护栏

1. 统一 Python 项目元数据与锁定依赖；CI 分成 PR-fast、PR-full、nightly-perf、release-package，并上传 JUnit、coverage、构建/benchmark artifacts。
2. 建立 migration rollback、历史 SQLite fixture 和 HTTP/WebSocket schema/consumer contract。
3. 建立低开销的性能事件与路径预算：目录首屏/缩略图/DB lock wait/文件命令/LAN route/网格帧时间；以趋势而不是单次开发机阈值判断回归。
4. 在测量基础上执行有界背压、字节配额缓存、可见区 WebUI 缩略图、目录摘要 I/O、事务批处理等优化。

## 每批发布检查

- ADR/迁移说明、兼容入口清单、弃用调用数、回滚路径与 focused contract tests 完整。

## P11: Grid Presentation State-Machine Reconstruction

### Trigger

Observed desktop behavior after P10 pacing work: fast scroll or repeated zoom can repeatedly blacken/rebuild the whole Grid and replay card entrance/fade animation. The local guards added around zoom completion and staged rebuild callbacks do not address the underlying ownership problem: multiple layers independently treat reset, thumbnail delivery, show, zoom, and scroll as animation/repaint authority.

### Evidence and root-cause hypotheses

1. `FileSystemModel.set_directory()` intentionally emits an empty `modelReset` before starting the scan, then `_on_scan_done()` emits a populated `modelReset` for the same `scan_generation` (`AssetsManager/panels/file_list/_model.py:100-137`).
2. `QWidgetFileListPanel._on_grid_model_reset()` treats both resets as committed content: it relayouts, restores selection, calls `_start_entrance_stagger()`, and schedules `_load_visible()` (`AssetsManager/panels/file_list/__init__.py:425-436`). The Grid reset handler itself clears entrance/fade state (`_grid_widget.py:200-212`). This creates duplicate entrance schedules and potentially duplicate delayed thumbnail request waves per navigation/refresh.
3. `showEvent()` independently infers entrance eligibility from an empty `_entrance_visible` set, while `_start_entrance_stagger()` clears that set every invocation (`_grid_widget.py:279-283`, `426-445`). View visibility and model presentation generation are therefore conflated.
4. Thumbnail delivery has two invalidation routes for the same rows: model `dataChanged` causes `_on_data_changed()` to discard texture and all local animation state; then batch code also calls `on_thumb_batch()` and `mark_loaded()` to dirty and start opacity state. The 16 ms animation timer calls full-widget `update()` on every tick (`_grid_widget.py:214-224`, `456-514`; `__init__.py:635-658`).
5. Zoom and scroll are separate `QVariantAnimation` state machines. Their latest-generation guards prevent stale completion, but they still directly interact with Grid cache invalidation, layout, full-widget updates, loader request debounce, and staged rebuild scheduling (`__init__.py:527-590`, `_base.py:739-767`).

### Goal

Replace the ad-hoc collection of reset/fade/texture/update triggers with an explicit, panel-owned **presentation generation** and a Grid-owned **frame scheduler**. A content generation should get at most one entrance transition; a thumbnail batch should get one commit/invalidation path; and all visual work should be coalesced into bounded, current-viewport frame requests.

### Non-goals

- Do not weaken `LibrarySession`, thumbnail runtime-generation discard, loader admission/backpressure, or panel teardown/drain contracts.
- Do not change WebP/Alpha, thumbnail worker count, cache file format, or loader cache policy.
- Do not move `QPixmap` creation off the Qt main thread.
- Do not make benchmark timing a CI/PR gate.
- Do not retain old-directory card content after a model directory generation changes.

### Target design

#### 1. Split scan lifecycle from committed presentation lifecycle

- Add an explicit model/panel signal or query that distinguishes the clearing/loading reset from the populated scan-result commit for a specific `scan_generation`.
- Keep Qt model reset semantics if other consumers need the immediate clear, but only the populated committed result can create a new Grid presentation generation.
- `QWidgetFileListPanel` owns a monotonic `presentation_generation` derived from a committed populated model generation and a visible Grid binding. It performs exactly once: layout, selection restore, visible thumbnail request scheduling, and optional entrance eligibility.
- Empty scans must commit an empty presentation without starting entrance/fade or delayed thumbnail work.
- Model reset handlers in Grid only clear model-bound caches/state. They never decide whether an entrance animation should run.

#### 2. Replace inferred entrance behavior with explicit one-shot presentation intent

- Remove entrance eligibility from `showEvent()`; a hide/show must not imply a new content transition.
- Replace public/private `_start_entrance_stagger()` use with an explicit `begin_presentation(presentation_generation, visible_rows, animate: bool)` API from the panel.
- Record a completed/consumed presentation generation in Grid. Repeated panel callbacks, delayed scan signals, view switches, or repaint events cannot replay entrance for the same presentation.
- Theme changes, zoom completion, resize, thumbnail arrival, hover, selection and scroll never start entrance. A true directory content commit may, subject to reduced-motion and the one-shot generation guard.

#### 3. Establish a single thumbnail visual-commit boundary

- Keep current ready-time validation and main-thread `QImage -> QPixmap` conversion.
- Accumulate only valid ready row IDs/pixmaps in the existing bounded 50 ms batch.
- At flush, perform one authoritative commit operation that updates model decorations/raw pixmaps, classifies the invalidation, and requests only affected visual regions.
- Remove duplicated row dirtiness between `dataChanged`, `on_thumb_batch`, and `mark_loaded`. The Grid should receive a dedicated `commit_thumbnail_rows(rows)` operation instead of inferring a thumbnail transition from generic model notifications.
- Preserve generic model `dataChanged` invalidation for metadata/subtitle/static-content changes, but classify by role:
  - thumbnail decoration/raw-pixmap: texture replacement + optional thumbnail fade;
  - subtitle/name/type: static texture rebuild, no entrance/fade reset;
  - non-render roles: no texture invalidation.
- Preserve hover, selection and unrelated fade state whenever row identity has not changed.

#### 4. Introduce one Grid frame scheduler and dirty-region ownership

- Route animation ticks, thumbnail commits, content-level full rebuilds, scroll movement, hover/selection changes, resize and layout changes through a small Grid scheduler that coalesces requests until Qt delivers the next paint.
- The scheduler tracks reason flags and current presentation/model generation; stale queued work is dropped on model reset/rebind.
- Replace unconditional timer `self.update()` with dirty-rect or minimal viewport invalidation. Use full viewport invalidation only when a transform/layout reason truly requires it.
- Preserve the 12-texture content rebuild budget, but make it a scheduler work class rather than an independent `singleShot` loop. It must yield to current viewport, thumbnail commits and new presentation generation.
- Add a clear policy for scrolling: ongoing scroll suppresses nonessential entrance/fade repaint and rebuilds only current visible dirty cards. On settle, loader priority/debounce resumes as today.

#### 5. Redefine zoom lifecycle as an atomic presentation transition

- Keep zoom interpolation for layout geometry if desired, but do not treat every intermediate layout frame as a new content presentation.
- On zoom start: cancel prior zoom generation, mark a zoom transaction active, and suppress entrance/fade replay.
- On zoom completion: one latest-generation commit updates loader size, item size and texture generation; scheduler rebuilds current viewport under budget without rearming entrance.
- Decide during implementation between two safe visual policies, based on a manual visual artifact and correctness tests:
  1. retain existing cache only for geometry interpolation, then display neutral placeholders during final-size rebuild; or
  2. use a separate old-cache/new-cache layer during zoom, swapping only after current viewport coverage is complete.
- Choose option 1 unless option 2 demonstrates materially better visual continuity without exceeding an explicit temporary memory bound or complicating cache/session teardown.

## FileList Product Interaction Delivery Plan

### Context

The FileList command-system foundation is complete:

- Grid and Details project a shared `FileListCommand` / `FileListCommandContext` model into the context menu.
- Stable command IDs drive context-menu actions and keyboard dispatch.
- Scoped file operations, undo/redo, and result-path selection restoration are covered across Grid and Details.
- Selection is path-based and protected across refresh, sort, filter, directory navigation, view changes, and file operations.

The remaining product suggestions in `docs/Suggestions/filelist-product-and-context-menu-suggestions-2026-07-19.md` are primarily interaction feedback and asset-management workflow work. Deliver them in four independently releasable batches; do not combine them with FileList rendering, session-lifecycle, or operation-service refactors.

### Shared Constraints

- Preserve the FileList ownership boundary: views provide selection/context; command and application-service layers perform filesystem mutations.
- All asynchronous work must retain the existing `LibrarySession` admission/lease behavior, reject closed sessions, and avoid UI-owned filesystem mutation logic.
- Never use a global task registry or a global current-library lookup. A task belongs to its initiating session and FileList instance.
- UI state is advisory only. Filesystem success, projection reconciliation, and domain event order remain owned by `FileOperationService` and `UndoService`.
- Preserve the existing command IDs and shortcuts. New UI surfaces invoke the same commands rather than duplicating action handlers.
- Each batch starts with focused tests and ends with:
  - `python -m ruff check .`
  - `python -m pyright`
  - `python -m compileall AssetsManager -q`
  - `python -m pytest -q`

### F1: Scoped File Operation Feedback Foundation

**Goal:** Give users a consistent, non-modal indication that a FileList operation has started, completed, partially failed, or can be undone, without changing operation semantics.

**Scope:**

1. Define a narrow immutable operation presentation record, for example `FileOperationFeedback`, containing:
   - session token and operation generation;
   - operation kind (`copy`, `move`, `trash`, `permanent_delete`, `rename`, `batch_rename`, `duplicate`, `undo`, `redo`);
   - total/completed/failed counts where deterministically known;
   - state (`running`, `succeeded`, `partial`, `failed`, `cancelled` only if cancellation is genuinely supported);
   - bounded error summary/count and optional action availability (`undo`, `details`).
2. Add a FileList-local feedback presenter near the status area. It must replace/supersede prior feedback only for the same panel/session and must disappear or reset on session rebinding/shutdown.
3. Route existing `_run_in_background()` operation completion paths through one small feedback publication helper. Start and final result presentation must be consistent for paste/move, duplicate, rename/batch rename, trash, permanent delete, undo, and redo.
4. Initially expose only truthful state:
   - Show an indeterminate running state for operations whose service API does not provide progress.
   - Show success, partial failure, or failure after result completion.
   - Offer Undo only when the scoped undo service has an applicable successful entry.
   - Do not add a Cancel control until operation services expose cooperative cancellation with defined projection and undo semantics.
5. Provide a lightweight failure-details affordance only if the service result already has bounded error data. Do not surface raw exception traces or unbounded path/error payloads.

**Primary files:**

- `AssetsManager/panels/file_list/_actions.py`
- `AssetsManager/panels/file_list/_background.py`
- `AssetsManager/panels/file_list/__init__.py`
- new narrowly scoped FileList feedback widget/helper if necessary
- `AssetsManager/application/file_operation_service.py` only for result-shape clarification, not filesystem behavior changes
- `tests/desktop/test_file_list_shim.py`
- new focused FileList feedback tests

**Acceptance:**

- Every FileList mutation shows a running state before background execution and one terminal state afterward.
- Partial success reports a partial terminal state and bounded failure count.
- Feedback from a closed/rebound session cannot update the active panel.
- Existing post-operation selection restoration still wins only after a committed scan result.
- No new operation service, domain-event, or session lifecycle regression.

**Out of scope:** byte/item progress without service support, cancellation, cross-panel task manager, persisted task history, LAN/WebUI task UI.
