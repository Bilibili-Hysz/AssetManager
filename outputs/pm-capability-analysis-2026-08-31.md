# PM 视角能力差距分析：从 Serpent 学什么（2026-08-31）

> 依据：四位分域专家报告（架构运行时/数据检索/自动化生态/交付质量，全文见会话代理输出 `C:\Users\86177\.zcode\cli\agents\sess_*\agent_*\output.txt`），对照前期文档 `outputs/serpent-vs-assetmanager-2026-08-30.md`。立场：项目经理的资源分配决策，不是功能 wishlist。
> 背景：A=AssetManager（本地优先资产库 + LAN 分享门户，商城已剥离）；B=Serpent（单机专业 DAM 工作站，Electron，7 周 1268 commits，v0.1.5）。

---

## 一、PM 总判断

**两个项目把钱花在了不同的地方，且都花得理性。** B 把钱花在"产物真实性与发布安全"（真实 ABI 测试运行时、二进制级打包校验、带哈希链的更新器），因为它是直面终端用户安装分发的桌面单品，且单人开发没有 CI 预算；A 把钱花在"过程不可漂移"（13 job CI、10 个 AST 门禁、文档三态与计数锚定、证据账本），因为它是多域系统。**A 在交付治理上已全面领先（CI/供应链审计/覆盖率门禁/a11y 门禁/静态架构治理/性能趋势留存——九项对比全部占优），B 在产品深度与生态杠杆上领先。**

因此 PM 的问题不是"追平 B"，而是：**从 B 的产品深度里挑出"单人创作者愿意为之换库"的能力，用 A 的工程体系低成本吸收。**

### T3 观察区（用户获取/条件触发）
- **Eagle/Billfish 读取器**（各 S）：读得动竞品库=免费获客；Eagle 纯 JSON 遍历性价比最高。触发条件：决定做用户获取。
- **浏览器扩展**（M）：采集成刚需，环回接收可复用 lan route_policy；触发条件：产品确认采集方向。
- **自动更新器**（L）：B 的 app-update-service.ts（824 行+单测）是完整安全规格——URL 锁定/资产白名单/SHA256 双通道/2GB 流式上限，立项时直接当规格书抄，省一次安全设计。当前 zip 手动分发不需要。
- **Browse Session 稳定分页**（M）：翻页不跳不重；webui 网格端联调量大。

### T4 明确不学（负资产清单，防止未来误立项）
1. **多进程写租约/fencing/触发器变更序列全家桶**——B 为四进程架构支付的保险费；A 单 owner 单进程下是防御性冗余。且 B 自己被 checksum 纪律反噬（v40 双分支 SQL 互判损坏）、触发器矩阵成维护税（21 表×3 手写触发器）、跨进程通知靠 250ms 轮询（A 单进程推送反而优）。
2. **QuickJS 级插件沙箱**（L）——Python 无成熟双限额嵌入方案；A 的 manifest 权限+只读服务白名单对单人可信环境已是合理边界。
3. **细粒度 MCP 权限矩阵**——B 自己推倒重来成 auto|full-access 两档，教训：直接上两档。
4. **CHECK 枚举驱动的派生物表设计**——B 每加一种 kind 重建全表（5 次）；A 的应用层白名单更抗演化。
5. **评分 0 星=未评分的语义混叠**——A 的 nullable 更干净，实现检索时保留。
6. **AI 多厂商长尾适配**——B 为中转站兼容付出持续 bug 源；A 锁定 Ollama 本地 + 单一 OpenAI 兼容口。

## 四、风险与反 lesson（B 教给我们的三件事）

1. **事故驱动的机制堆叠要定期合并简化**：B 的失效机制叠了六层（generation fence/burst gate/changeSequence staleness/interactionKey/宽限/白名单），每层对应一次生产事故补丁，互相依赖失去可测性。A 引入任何新机制时，若与旧机制解决同一问题，必须合并而非叠加。
2. **"checksum 级"不可变纪律是双刃剑**：B 的迁移 checksum 锁死导致 v40 双分支 SQL 互判损坏、v45 被迫拆三个追加迁移。A 的线性版本+冻结历史名已够，**不要升级到 checksum 模式**。
3. **单文件巨石是慢性毒**：B 的 library-service.ts 43,822 行/55 表/48 迁移/94 个测试文件引用。A 的 file_list 27 文件 mixin 已在警戒线，**新域（媒体栈/合集/FTS）坚持子包化**是本轮移植已遵守的纪律，继续保持。
