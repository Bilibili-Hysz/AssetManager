# AssetManager 长期进化战略（2026-08-31）

> 综合：7 位专家调研（用户演进/市场格局/规模分发 + 前期 Serpent 四域对比）+ 本会话全部一手实施证据。
> 三份战略输入：①用户与场景演进（北极星/三层旅程/Top6 方向/12 不做）②市场与竞品格局（生态位真空实证/趋势 Top5）③规模化与分发工程（G1-G10 差距/10 万张压力分级/最小路径）。前期四域对比：`outputs/pm-capability-analysis-2026-08-31.md`、`outputs/serpent-vs-assetmanager-2026-08-30.md`。

## 一、战略定位（两份独立调研收敛于同一句话）

**桌面即服务器、双击即部署的本地优先创作者资产库。**

- 用户专家的北极星：*做创作者愿意托付十年资产的本地库——桌面端把"越用越有组织"做到极致，局域网 Web 让任何人零安装看一眼就能拿走。*
- 市场专家的生态位：*"本地优先 + 自托管 LAN 分享 + 无订阅 + 中文友好 + MCP"* 组合在市场里是**真空**——Eagle 有 MCP 但闭源买断无服务器；Immich 验证了自托管+移动消费（113k star）但服务器-first 需 Docker、照片向无桌面 GUI。**A 是唯一"桌面 GUI 与自托管服务器同进程"的候选。**

**三支柱**（各调研独立收敛）：① 组织深度（标签+合集+评分+检索闭环，惯性最强）② 安全网（撤销/回收/备份/活动回溯——创作者敢托付的理由）③ LAN 门户（独占牌；当前后端 80 分/前端 50 分，补呈现层比加后端便宜一个量级）。

## 二、战略判断（五条，全部有证据）

1. **长期战场已从"功能"转移到"规模与时间"**：去重（零实现）、失链再挂接（零实现）、迁移产品化、容量仪表（108 处埋点消费 0 处）——全是"库存在超过一年后"的问题。当前设计假设仍停留在"库是新的、路径是稳的、单机是永久的"。
2. **规模天花板不在 SQLite，在未声明的常量**：watcher 5 万目录、备份 quick_check 512MiB 门（超限**静默跳过**完整性校验）、manifest ≤10 万文件、activity_log 无限增长。最先可感：缩略图缓存零生命周期（10 万张 ≈4GB 无上限增长）。最先静默失效：备份 100k 成员帽。**Grid 帧成本与单连接架构在 10 万级都不撞**（D3 维持判断成立）。
3. **MCP 已是入场券且窗口就在当下**：Eagle（商业）与 Serpent（开源）2026 年双双交付；"做"不再差异化，差异化在"Agent 能做多深"。且 MCP 只读暴露同时是**智能体协作规模化的杠杆**（任务包模式的自然延伸）——一份投资两个战略目标。
4. **发布形态是"被普通用户用起来"的最大 blocker**：127MB onedir 裸目录 + SmartScreen 无签名拦截 + 零引导首屏 + RuntimeData 写 exe 同级（封死 Program Files）。全部 S-M 级确定性工程。
5. **品类模式**：创作素材 DAM 用户对订阅抵触强烈（买断/免费是事实标准）；移动端"生产"被品类集体放弃但"消费"空间敞开——A 的 WebUI+移动适配恰好独占承接。

## 三、进化路线图（三地平线）

### H1 现阶段（0-3 个月）：把已有资产"点灯"
| 批次 | 内容 | 来源 |
|---|---|---|
| H1-a 检索质量 | 中文子串 trigram 双轨（修"风景搜不到美丽的风景"）+ 评分/收藏入检排序 + 智能合集浏览态快照 | 数据专家 Top1-3 |
| H1-b 安全网收口 | 派生物生命周期三列 + 库内回收站视图（撤销/备份已就绪，只盖视图）+ 活动面板（数据在睡觉） | 用户专家 Top6.1 + 数据专家 Top4 |
| H1-c 访客链路点灯 | ShareReceive 配额渲染 + `min-h-[100dvh]` + files.py 分页 + ETag/Cache-Control | 用户专家 Top6.6（纯前端活，成本最低） |
| H1-d 分发起步 | **G1 版本常量（S，明天就能做）** → Inno Setup per-user 安装器（绕开 G3）→ 首启动三选一引导（新建/导入/打开示例）→ crash 回传 opt-in | 规模专家 G1/G2/G5/G7 |

### H2 半年内（3-9 个月）：规模化与生态地基
- **T10 读连接池** + lane 化调度（触发条件：容量仪表上线后 D3 重启条件可被观测验证时）
- **T8 → 命令注册表 → MCP 只读→读写** 递进链（challenge 随 MCP 落地；A 的差异化卖点：MCP 批量写入保留"人类可见摘要"，修正 B 的静默缺陷）
- **AI 打标栈**（Ollama OpenAI 兼容口 + 写边界标签白名单 + 导入 AI 豁免表；带 model/revision 溯源列——B 的 ai_asset_tags 溯源是 A 的 v36 缺口）
- 缩略图磁盘生命周期（容量帽+驱逐，原语已存在）+ activity_log 保留期（90 天）+ 备份成员帽分片
- **失链再挂接**（复用缩略图 v2 键身份指纹 + 导入收养机制，无新技术）与**去重**（感知哈希分组）
- WebDAV 同步（对接用户已有 NAS，Serpent 的 sync 文档即现成需求规格）

### H3 一年以上（9 个月+）：生态与规模
- 512MiB quick_check 门改造（采样/分卷）、watcher 增量化、FTS 分批重建、超大库拆分引导
- PWA 移动消费安装化（假设：LAN 分享被真实使用之后）
- 自动更新器（全量 zip + B 的更新器安全规格；前置 H1-d 的 G1）
- Eagle/Billfish 只读导入器（用户获取漏斗；独立脚本形态，不进主程序）
- 语义搜索（先 MCP 接外部能力，自建向量索引不做）

### 不做清单（合并三份调研，14 条）
云同步自建 / 商城回归核心包 / Web 端生产功能 / 向量检索自建 / 资产版本管理 / 原生移动 App / 协作者评论 / 插件市场运营 / 连接池重构未触发前 / 竞品库直开进主程序 / 商城孤儿表清理 / 回收站快照化变体 / QuickJS 沙箱 / AI 多厂商长尾适配。每条均有 ADR、路线图或专家证据背书。

## 五、近期行动序列（下一批执行建议）

1. **H1-d 分发起步**：G1 版本常量（S，一天内）→ Inno 安装器 → 引导首屏。这是"从工具到产品"的第一步，也是 H1 里唯一还没有任何代码的方向。
2. **H1-a 检索质量**：trigram 双轨 + 评分入检（直接消化 Serpent 数据专家的 Top1-2，成本 M+S）。
3. **H1-b/c 并行**：生命周期三列、回收站视图、活动面板、访客配额渲染——全是"数据已就绪、只差最后一屏"的收口活。

每批照既有模式执行：调研 → 执行子代理（串行）→ 全量门禁 → 提交推送（代理探测方法见任务包 §2.6）。

## 六、一页结论

**进化方向已定：不转向，收敛。** 产品北极星是"托付十年资产的本地库"（用户专家）与"桌面即服务器"（市场专家）的合流——两者说的是同一件事的两面：库主敢托付，访客零门槛。短期把已有资产点灯（检索质量/安全网/访客链路/安装器），中期建规模化与生态地基（T10/T8→MCP/AI 打标），长期按触发信号走规模分级表。**最大的战略风险不是选错方向，而是"生产了没人消费"的模式复发**——三份调研共同指向的解药是把"最后一屏"（访客配额、活动面板、回收站视图、库体检）当作与后端能力同等级的交付物。
