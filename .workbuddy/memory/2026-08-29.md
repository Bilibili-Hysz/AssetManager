## 恢复尝试结论（重要经验）

被 revert 的**工作区**改动**无法用 git 恢复**：
- 从未 `git add` → 不进 object database → `git fsck --lost-found` 捞不到
- `git reflog` 里 **没有** checkout/reset 痕迹（`git checkout -- <file>` 不写 reflog）
- 实测 `git fsck` 找到的 dangling 对象全是历史 stash 与旧 blob，与本次无关

**唯一可行的恢复途径**：编辑器的 undo 缓冲 / IDE Local History。

**给未来的铁律**：任何 agent 做变异测试，还原必须是
**字节级内存备份/还原**，绝不允许出现 `git checkout -- .` 或 `git stash`（全树操作）。

## ⚠️ 前日报告勘误（我自己犯的错）

2026-08-28 报告里写的「**30 个 commit 从未推送**」是**口径错误**。

- 我当时用 `git rev-list --left-right --count origin/master...HEAD` = 0/30
- 但当前分支是 `feat/quality-audit-2026-08-17`，跟踪的是 `origin/同名分支`
- **拿特性分支比 origin/master 本来就必然领先**，不代表没推送

**正确口径**：
```
git rev-list --count origin/feat/quality-audit-2026-08-17..HEAD   → 0  (未推送)
git rev-list --count HEAD..origin/feat/quality-audit-2026-08-17   → 0  (未拉取)
git status -sb   →无 [ahead N] 标记
```
结论：**用户代码一直是有远程备份的**，我当时虚惊一场、也误导了用户。

**教训**：判断"是否已推送"必须看分支自己的 upstream，不能拿它跟 master 比。
