# Request
生成 AssetManager（Python 桌面资产管理器 + 局域网分享服务器）的整体分层架构图，重点展示“桌面端 PySide6 与 LAN Web 端双展示层共享同一套应用服务”的分层骨架，以及各层职责、模块边界与自上而下的依赖方向。

核心设计（已解引用自项目 README、docs/architecture.md、docs/architecture-diagram.md）：

一句话重点：用分层容器呈现「入口 → 展示层（桌面 UI + 控制器 + LAN 路由/React SPA）→ 应用与运行时层 → 领域层 → 仓库层 → 核心基础设施 → 外部依赖」，并标注 LAN 层为可选、与 core 共享、经 application 访问数据；强调依赖向下原则 domain ← repositories ← application ← lan/panels。

各层与关键模块（角色 / 职责 / 上下游）：

1. 入口层 ENTRY：main.py / run.py 启动 → app.py → window.py（启动窗口选库 → 主窗口）。仅负责进程引导，不含业务逻辑。

2. 展示层 PRESENTATION（双展示面，零业务规则）：
   - 桌面 UI：panels/（sidebar、file_list、info、tag_tree、image_viewer）、widgets/（14 个可复用 Qt 组件）、dialogs/（21 个对话框）、dock_factory（统一 dock 构建）、window.py、window_lifecycle_coordinator.py、系统托盘、stylekit/主题预览。职责：纯 UI 渲染，所有数据经控制器或作用域服务。
   - Controllers（4 个，零 Qt import，可纯 Python 测试）：InfoController（元数据/标签/备注）、FileListController（搜索历史/状态）、TagTreeController（标签 CRUD）、SidebarController（搜索计数）。上游：panels 委托；下游：调用 application 服务。
   - LAN 展示：lan/routes/*（24 模块、140 路由）+ React SPA（webui/dist 托管，含 RealtimeContext）。上游：浏览器 HTTP/WebSocket；下游：经中间件 → application 服务。

3. 应用与运行时层 APPLICATION + RUNTIME（51 个服务模块，DI 装配）：
   - ApplicationBootstrap / ServiceContainer 组装每库 LibraryRuntime、LibrarySession、LibraryContext（冻结快照：root/data_dir/thumb_dir/db_conn/tag_store/project_data）。
   - 桌面/共享 eager 服务：LibraryService（开库+QLockFile 跨进程准入）、MetadataService、TagService、ThumbnailService、FileOperationService、UndoService、PluginService、AssetIndexService、AssetIndexReconciliationService、DatabaseIntegrity/Maintenance/Export、LibrarySettingsAdapter（Qt-free 维护边界）。
   - LAN 惰性投影（single-flight 惰性构建）：AssetService、ProjectService、SearchService、GalleryService、FavoriteService。
   - 冻结 RuntimeSharingServices 包：AuthService + ShareService + 每 runtime 一次性 token_secret（不落库）；RuntimeEventRouter 负责投影失效路由；ReconciliationQueue 跨进程后台重建队列。

4. 领域层 DOMAIN（零基础设施依赖）：值对象、16 个领域事件（domain.event_bus 不可变事实）、错误层级、domain.auth（纯密码哈希/令牌生成，被 AuthService/ShareService 复用）。依赖规则：不依赖 presentation / infrastructure。

5. 仓库层 REPOSITORIES（17 个 SQL 仓库，统一 for_session + SAVEPOINT + CAS）：tag、metadata、thumbnail、favorite、share、auth、asset_index、plugin_metadata、shop、order、quota、free_download_quota、seller_profile、storefront_analytics、shop_buyer、gallery_home、revoked_token。职责：SQLite 持久化适配，不依赖 application/LAN/presentation。

6. 核心基础设施 CORE INFRASTRUCTURE（被上层共享）：database.py（DatabaseManager 连接级读写门 + 身份标记）、db_migrations（v1–v35 契约回溯）、settings、tag_store、project_data、signal_bus（7 个 Qt 信号，仅 UI 协调）、path_resolver（PathGuard 防路径穿越）、themes（24 主题）、icons（56 图标 DPR 感知）、cache、json_store（原子持久化）、plugins/（descriptor/loader/manager/host_context）。

7. LAN 层（可选，与 core 共享，经 application 访问数据）：LanServer(runtime) → lan/api.py（setup_routes 注册 140 路由 + 实时桥）→ lan/routes/*；lan/auth、lan/security（middleware 顺序 security→metrics→auth）、lan/path_guard、lan/ws（WebSocketManager 实时失效推送，>1MB 帧截断）、lan/tunnel（Cloudflare 一键公网，强制强认证）、lan/manager（生命周期）。权限：6 种 principal + 8 位能力；fail-closed（无法确认安全即拒绝）。HTTP 无证书用 http，有证书/密钥用 https。

8. 外部依赖 EXTERNAL：PySide6（Qt GUI）、sqlite3（WAL + 文件锁 + CAS）、Pillow（缩略图/内容门）、aiohttp（LAN 服务）、segno（QR）、send2trash、requests、cloudflared（隧道）、React/Vite（webui 构建产物）。

关键关系（可复述为明确语句）：
- 依赖向下：domain ← repositories ← application ← presentation/lan（下层不反向依赖上层）。
- 双展示共享：桌面 panels 与 LAN routes 都消费同一个 LibraryRuntime 冻结快照与同一套 application 服务，避免业务逻辑重复。
- 实时失效链路：LibraryRuntime → RuntimeEventRouter → 经 local_ui_auth_secret 鉴权的 WebSocket → React RealtimeContext（仅失效提示，HTTP /api/revision 权威游标恢复，SQLite/文件系统为权威源）。
- LAN 不自行组装服务：routes 仅做权限/JSON/PathGuard/传输归一化，业务校验在 application 服务（TagService/ShareService/AssetService 持有 A2 校验）。
- 开库链路：main → LibraryService.open_session → QLockFile 准入 → DatabaseManager 连接 → TagStore/ProjectData → LibraryContext/Session → ApplicationBootstrap.runtime_for → 主窗口 + 各面板。

展示要求：科技蓝主色（tech_blue），容器/分层风格强调模块边界；不对齐像素级坐标。重点呈现分层骨架与依赖方向，LAN 层作为可选侧翼与主链路分离。
